# Конфигурация IORuntime

`IORuntime` — это сердце Cats Effect, содержащее все необходимые пулы потоков, 
планировщики и конфигурации для выполнения `IO` программ. 
Возможность его внешней настройки позволяет адаптировать поведение Cats Effect 
под специфические требования вашего приложения и среды выполнения, будь то JVM, Node.js или браузер. 
Вы можете настроить `IORuntime` как через **аргументы JVM** (на платформе JVM), 
так и через **переменные окружения** (для платформ JavaScript, например, Node.js или браузера). 
В браузере также можно определить глобальные переменные.

## JVM

На платформе JVM параметры конфигурации передаются в приложение как **системные свойства** Java, используя аргумент командной строки `-D`:

```bash
java -Dcats.effect.propName=propValue -jar my-app.jar
```

## JavaScript (Node.js и браузер)

В среде JavaScript (Node.js) для конфигурации используются **переменные окружения** (environment variables):

```bash
export CATS_EFFECT_PROPNAME=propValue
node my-app.js
```

В **браузере** (и, как правило, в любой другой среде выполнения JavaScript) прямого доступа к переменным окружения нет. 
Вместо этого вы можете определить глобальную переменную в вашем бандле, используя инструменты сборки, такие как Webpack. 
Например, с помощью `EnvironmentPlugin` или определив переменную в объекте `process.env` глобально (если ваша среда его поддерживает):

```javascript
// Node.js или среда с поддержкой process.env
process.env.CATS_EFFECT_PROPNAME = propValue;

// псевдоним для совместимости с Create React App
process.env.REACT_APP_CATS_EFFECT_PROPNAME = propValue;
```

В Webpack это можно настроить через [EnvironmentPlugin](https://webpack.js.org/plugins/environment-plugin/), 
который позволяет передать переменные окружения в сборку.

## Таблица параметров конфигурации

Ниже приведена таблица параметров конфигурации `IORuntime`, с их названиями для JVM (системное свойство) 
и JavaScript (переменная окружения), ожидаемым типом значения по умолчанию и подробным описанием.

**Параметр:** `cats.effect.detectBlockedThreads`

- **JS env:** N/A
- **Тип по умолчанию:** `Boolean` (`false`)
- **Описание:** **Включает детектор заблокированных потоков.** Если `true`, планировщик будет периодически проверять состояние случайных вычислительных потоков и выводить предупреждение, если они оказываются в состоянии `BLOCKED`. Крайне полезно для отладки, но создает дополнительную нагрузку, поэтому в production обычно отключено.

**Параметр:** `cats.effect.logNonDaemonThreadsOnExit`

- **JS env:** N/A
- **Тип по умолчанию:** `Boolean` (`true`)
- **Описание:** При завершении работы JVM (в `IOApp`) проверяет, остались ли в живых не-демонические потоки (кроме основного). Если такие потоки есть, выводит их список в лог, чтобы помочь обнаружить утечки потоков.

**Параметр:** `cats.effect.logNonDaemonThreads.sleepIntervalMillis`

- **JS env:** N/A
- **Тип по умолчанию:** `Long` (`10000L`)
- **Описание:** Интервал (в миллисекундах) между проверками наличия не-демонических потоков при завершении работы.

**Параметр:** `cats.effect.warnOnNonMainThreadDetected`

- **JS env:** N/A
- **Тип по умолчанию:** `Boolean` (`true`)
- **Описание:** Если `true`, `IOApp` выведет предупреждение, если его метод `main` был запущен не в основном потоке JVM (что может указывать на проблемы с планированием).

**Параметр:** `cats.effect.cancelation.check.threshold`

- **JS env:** `CATS_EFFECT_CANCELATION_CHECK_THRESHOLD`
- **Тип по умолчанию:** `Int` (`512`)
- **Описание:** **Частота проверки отмены.** Через каждые `N` итераций цикла выполнения волокно проверяет, не был ли оно отменено. Меньшее значение делает отмену более отзывчивой, но увеличивает накладные расходы.

**Параметр:** `cats.effect.auto.yield.threshold.multiplier`

- **JS env:** `CATS_EFFECT_AUTO_YIELD_THRESHOLD_MULTIPLIER`
- **Тип по умолчанию:** `Int` (`2`)
- **Описание:** **Коэффициент автоматической уступки (auto-yield).** Автоматическая уступка происходит каждые `cancelationCheck.threshold * multiplier` итераций. Это помогает предотвратить монополизацию CPU волокном с длинным синхронным циклом.

**Параметр:** `cats.effect.tracing.exceptions.enhanced`

- **JS env:** `CATS_EFFECT_TRACING_EXCEPTIONS_ENHANCED`
- **Тип по умолчанию:** `Boolean` (`true`)
- **Описание:** **Улучшенные трассировки ошибок.** При включении Cats Effect обогащает трассировки стека исключений асинхронными фреймами (кадрами волокон), что значительно упрощает отладку, но добавляёт небольшие накладные расходы.

**Параметр:** `cats.effect.tracing.buffer.size`

- **JS env:** `CATS_EFFECT_TRACING_BUFFER_SIZE`
- **Тип по умолчанию:** `Int` (`16`)
- **Описание:** **Размер буфера трассировки.** Количество сохраняемых фреймов стека для асинхронной трассировки. Будет округлено до следующей степени двойки. Влияет на детализацию стектрейсов.

**Параметр:** `cats.effect.shutdown.hook.timeout`

- **JS env:** `CATS_EFFECT_SHUTDOWN_HOOK_TIMEOUT`
- **Тип по умолчанию:** `Duration` (`Inf`)
- **Описание:** **Таймаут хука завершения.** Если приложение получает сигнал (например, `Ctrl+C`), Cats Effect запускает процесс отмены всех волокон. Этот параметр определяет, как долго среда будет ждать их завершения, прежде чем принудительно остановить JVM. Установите конкретное значение, чтобы избежать бесконечного ожидания.

**Параметр:** `cats.effect.cpu.starvation.check.interval`

- **JS env:** `CATS_EFFECT_CPU_STARVATION_CHECK_INTERVAL`
- **Тип по умолчанию:** `FiniteDuration` (`1.second`)
- **Описание:** **Интервал проверки голодания CPU.** Через этот интервал встроенный детектор просыпается и проверяет, не превышает ли задержка планировщика допустимый порог.

**Параметр:** `cats.effect.cpu.starvation.check.initialDelay`

- **JS env:** `CATS_EFFECT_CPU_STARVATION_CHECK_INITIAL_DELAY`
- **Тип по умолчанию:** `Duration` (`10.seconds`)
- **Описание:** **Начальная задержка проверки голодания.** Чтобы избежать ложных срабатываний во время "прогрева" JVM (JIT-компиляции), проверка запускается не сразу. Установите `Duration.Inf`, чтобы полностью отключить проверку на голодание.

**Параметр:** `cats.effect.cpu.starvation.check.threshold`

- **JS env:** `CATS_EFFECT_CPU_STARVATION_CHECK_THRESHOLD`
- **Тип по умолчанию:** `Double` (`0.1`)
- **Описание:** **Пороговое значение голодания.** Детектор выводит предупреждение, если `(фактическое_время - ожидаемое_время) / ожидаемое_время > threshold`. Значение `0.1` значит, что предупреждение появится, если фактическое время сна превысило ожидаемое более чем на 10%.

**Параметр:** `cats.effect.trackFiberContext`

- **JS env:** N/A
- **Тип по умолчанию:** `Boolean` (`false`)
- **Описание:** **Отслеживание контекста волокна.** Включает механизм, необходимый для корректной работы `IOLocal` в многопоточных средах, аналогично `ThreadLocal`. Включайте только при необходимости, так как это создаёт накладные расходы.

## Рекомендации по настройке

1.  **Разработка и отладка:**
    - Установите `cats.effect.detectBlockedThreads=true` для поиска случайных блокирующих вызовов.
    - Убедитесь, что `cats.effect.tracing.exceptions.enhanced=true` (включено по умолчанию) для читаемых стектрейсов.

2.  **Production (высокая производительность):**
    - Оставьте `cats.effect.detectBlockedThreads=false` (по умолчанию).
    - Если вы не используете `IOLocal`, оставьте `cats.effect.trackFiberContext=false`.
    - Настройте `shutdown.hook.timeout` в соответствии с вашим SLA (например, `30.seconds`), чтобы приложения не "висели" при остановке.

3.  **Борьба с голоданием (CPU Starvation):**
    - Если вы получаете ложные предупреждения о голодании из-за особенностей среды (например, в CI или на медленных машинах), увеличьте `cpu.starvation.check.interval` или установите `cpu.starvation.check.initialDelay = Duration.Inf`.
    - Если вы намеренно мигрируете на более "широкие" (с большим числом CPU) экземпляры, возможно, захотите уменьшить порог (`threshold`) для более раннего обнаружения проблем.

4.  **Трейдинг / финтех (сверхнизкие задержки):**
    - Увеличьте `cancelation.check.threshold` (например, до `4096`), чтобы снизить накладные расходы на проверку отмены.
    - Соответственно увеличьте `auto.yield.threshold.multiplier`, чтобы отсрочить автоматическую уступку.
    - Полностью отключите улучшенные трассировки ошибок, установив `tracing.exceptions.enhanced=false`.
    - Отключите проверку на голодание (`initialDelay = Inf`), так как она сама вносит шум в замеры.
