# Parallel

При изучении различных монад вы могли заметить, что некоторые типы данных имеют одинаковую структуру, 
но вместо монады предоставляют экземпляр [`Applicative`](applicative.md). Классический пример — `Either` и `Validated`.

Почему это происходит? Дело в том, что определение экземпляра `Monad` для типов данных, подобных `Validated`, 
было бы несовместимо с их поведением накопления ошибок. Чтобы понять это, нужно вспомнить фундаментальное различие:

- [**Монады**](monad.md) (`Monad`) описывают **зависимые вычисления** — результат следующего шага зависит от результата предыдущего (используется `flatMap`).
- [**Аппликативы**](applicative.md) (`Applicative`) описывают **независимые вычисления** — вычисления можно выполнять параллельно, 
  и они не зависят друг от друга (используется `mapN`).

В случае с `Validated` мы хотим накапливать все ошибки, а не останавливаться на первой, 
как это делает `Either` в монадическом контексте. 
Поэтому `Validated` имеет экземпляр `Applicative`, но не `Monad`.

Однако на практике часто возникает ситуация, когда нужно использовать оба подхода вместе. 
Например, мы хотим выполнить несколько независимых валидаций (через `Applicative`), 
а затем продолжить вычисления в монадическом стиле (через `Monad`). 
Ручное преобразование между типами вроде `Either` и `Validated` возможно, но становится громоздким и повторяющимся.

## Пример: валидация данных пользователя

Рассмотрим конкретную задачу. У нас есть простые case-классы для представления данных пользователя:

```dotty
import cats.syntax.all.*
import cats.data.*

case class Name(value: String)
case class Age(value: Int)
case class Person(name: Name, age: Age)
```

И у нас есть функции для парсинга и валидации строковых значений:

```dotty
def parse(s: String): Either[NonEmptyList[String], Int] =
  if s.matches("-?[0-9]+") then Right(s.toInt)
  else Left(NonEmptyList.one(s"$s is not a valid integer."))

def validateAge(a: Int): Either[NonEmptyList[String], Age] =
  if a > 18 then Right(Age(a))
  else Left(NonEmptyList.one(s"$a is not old enough"))

def validateName(n: String): Either[NonEmptyList[String], Name] =
  if n.length >= 8 then Right(Name(n))
  else Left(NonEmptyList.one(s"$n Does not have enough characters"))
```

Теперь мы хотим спарсить две строки в значение `Person`. 
Валидации имени и возраста независимы (мы хотим собрать все ошибки), поэтому логично использовать `Applicative`. 
Однако парсинг зависит от результата предыдущего шага, поэтому нужна `Monad`.

**Проблема**: Без `Parallel` нам приходится вручную преобразовывать типы:

```dotty
def parsePerson(ageString: String, nameString: String) =
  for
    age    <- parse(ageString)
    person <-
      (validateName(nameString).toValidated, validateAge(age).toValidated)
        .mapN(Person)
        .toEither
  yield person
```

Мы вынуждены:

1. Преобразовывать `Either` в `Validated` с помощью `.toValidated`
2. Использовать `mapN` для параллельной комбинации
3. Преобразовывать обратно в `Either` с помощью `.toEither`

Этот подход работает, но становится всё более громоздким по мере роста числа комбинируемых `Either`.

## Решение: класс типов Parallel

Чтобы облегчить эту боль, [Cats](https://typelevel.org/cats/) вводит класс типов `Parallel`. 
Он абстрагирует монады, которые также поддерживают параллельную композицию через соответствующий аппликатив.

```dotty
trait Parallel[M[_]]:
  type F[_]

  def sequential: F ~> M

  def parallel: M ~> F
```

Где:

- `M[_]` — тип, имеющий экземпляр `Monad` (например, `Either`)
- `F[_]` — тип, имеющий экземпляр `Applicative` (например, `Validated`)
- `sequential` — преобразует аппликатив `F` обратно в монаду `M`
- `parallel` — преобразует монаду `M` в аппликатив `F`

![Типкласс Parallel преобразует между монадой M[_] и аппликативом F[_].](../images/parallel.png)

Напомним, что `~>` — это псевдоним для `FunctionK`, представляющий естественное преобразование между типами-контейнерами.

## Использование Parallel на практике

С `Parallel` наш код становится гораздо чище:

```dotty
def parsePerson(ageString: String, nameString: String) =
  for
    age    <- parse(ageString)
    person <- (validateName(nameString), validateAge(age)).parMapN(Person)
  yield person
```

Вместо ручных преобразований мы просто используем `.parMapN` вместо `.mapN`. Cats автоматически:

1. Преобразует `Either` в соответствующий аппликатив (в данном случае `Validated`)
2. Применяет `mapN` для параллельной композиции
3. Преобразует результат обратно в `Either`

### Traverse с Parallel

`Parallel` также позволяет использовать `parTraverse` и `parSequence` для обхода коллекций:

```dotty
List(
  Either.right(42),
  Either.left(NonEmptyList.one("Error 1")),
  Either.left(NonEmptyList.one("Error 2"))
).parSequence
// Left(NonEmptyList(Error 1, Error 2))
```

Этот код параллельно обрабатывает все элементы списка, накапливая ошибки в `NonEmptyList`, 
вместо того чтобы остановиться на первой ошибке (как повело бы себя обычное `sequence` с монадой).

### Zipping коллекций

`Parallel` также полезен для операции `zip` над коллекциями. 
Стандартный экземпляр `Applicative` для `List`, `Vector` и т.д. ведёт себя как декартово произведение коллекций:

```dotty
(List(1, 2, 3), List(4, 5, 6)).mapN(_ + _)
// Результат: List(5, 6, 7, 6, 7, 8, 7, 8, 9) - все комбинации
```

Однако часто мы хотим просто "сцепить" коллекции поэлементно (как `zip`). 
`Parallel` позволяет использовать `parMapN` для этого:

```dotty
(List(1, 2, 3), List(4, 5, 6)).parMapN(_ + _)
// Результат: List(5, 7, 9) - поэлементное сложение
```

В данном случае `Parallel` для списков использует альтернативный аппликативный экземпляр, 
который реализует `zip` вместо декартова произведения.

## NonEmptyParallel: ослабленная версия Parallel

Некоторые типы не могут образовать ни `Monad`, ни `Applicative`, 
потому что невозможно реализовать функцию `pure` (помещающую значение в контекст). 
Однако они могут иметь экземпляры [`Bind`](bind.md) (без `unit`) или [`Apply`](apply.md) (без `unit`).

Для таких типов существует класс `NonEmptyParallel`. 
Классический пример — `ZipList`. `ZipList` — это список, который позволяет поэлементно комбинировать значения, 
но не может быть `Applicative`, потому что невозможно определить `pure` для бесконечных списков.

Особенности `NonEmptyParallel`:

- Нельзя использовать `parTraverse` и `parSequence` (они требуют `pure` для возврата результата)
- Можно использовать `parMapN` (аналогично `Parallel`)
- Доступны `parNonEmptyTraverse` и `parNonEmptySequence` — аналоги функций из [`NonEmptyTraverse`](non-empty-traverse.md), 
  которые работают с непустыми структурами

## Выводы

Класс типов `Parallel` решает важную проблему: позволяет использовать как монадическую композицию (для зависимых вычислений), 
так и аппликативную (для независимых параллельных вычислений) без ручного преобразования типов. Это делает код:

- **Чище** — исчезает шаблонный код преобразования типов
- **Безопаснее** — меньше шансов ошибиться в ручных преобразованиях
- **Гибче** — легко менять стратегию композиции (последовательная vs параллельная)
- **Универсальнее** — работает с различными типами данных через единый интерфейс

`Parallel` особенно полезен для:

- Валидации форм с накоплением всех ошибок
- Параллельной обработки коллекций
- Комбинирования независимых вычислений в монадическом контексте
- Поэлементной работы с коллекциями (zip вместо декартова произведения)
