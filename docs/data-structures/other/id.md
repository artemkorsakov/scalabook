# Id: Монада идентичности

## Эффект отсутствия эффектов

В функциональном программировании [монады](../../typeclass/monad/monad.md) часто используются для управления эффектами: 
`Option` — для отсутствующих значений, `Either` — для ошибок, `IO` — для ввода-вывода. 
Но что, если эффекта нет? Что, если значение уже "чистое" и не требует никакой обёртки?

Монада идентичности `Id` (англ. _identity monad_) — это монада, которая **не добавляет никакого эффекта**. 
Она просто оборачивает значение в само себя, являясь тривиальной обёрткой, которая ничего не меняет.

## Определение типа Id

`Id` определяется как **синоним типа** (type alias):

```dotty
type Id[A] = A
```

Это означает, что `Id[A]` — это просто `A`. Значения типа `A` могут свободно использоваться как значения типа `Id[A]`, и наоборот.

```dotty
val x: Id[Int] = 1 // x имеет тип Int
val y: Int     = x // никакого преобразования не требуется
```

В отличие от других монад, `Id` не требует конструкторов (`Some`, `Right`, `IO(...)`), 
так как любое значение уже является своим собственным "обёрнутым" вариантом.

### Сравнение с другими монадами

| Монада   | Тип            | Конструктор             | Эффект              |
|----------|----------------|-------------------------|---------------------|
| `Id`     | `Id[A] = A`    | Любое значение          | Нет эффекта         |
| `Option` | `Option[A]`    | `Some(a)` / `None`      | Отсутствие значения |
| `Either` | `Either[E, A]` | `Right(a)` / `Left(e)`  | Ошибки              |
| `List`   | `List[A]`      | `List(a)` / `Nil`       | Множественность     |
| `IO`     | `IO[A]`        | `IO(a)` / `IO.delay(a)` | Ввод-вывод          |

## Id как монада

Поскольку `Id` — это просто синоним типа, мы можем рассматривать его как [`Monad`](../../typeclass/monad/monad.md). 
Посмотрим на реализации основных методов:

```dotty
given Monad[Id] with
  def unit[A](a: => A): Id[A] = a

  extension [A](fa: Id[A])
    def flatMap[B](f: A => Id[B]): Id[B] = f(fa)
```

Метод `unit` просто возвращает переданное значение — это **функция идентичности**.

`flatMap` - это просто **применение функции** `f` к значению `fa`.

Важно отметить, что для `Id` **`map` и `flatMap` имеют одинаковую реализацию**, так как дополнительный слой монады отсутствует.

### Сравнение реализаций map и flatMap

```dotty
// Для монады Option
Option(1).map(_ + 1)                // Some(2)
Option(1).flatMap(x => Some(x + 1)) // Some(2)

// Для Id (Identity)
1.map(_ + 1)     // 2 (просто применение функции)
1.flatMap(_ + 1) // 2 (то же самое!)
```

## Id как комонада

`Id` также является [`Comonad`](../../typeclass/monad/co-monads.md) — структурой, дуальной монаде. 

```dotty
given CoMonad[Id] with
  def coUnit[A](fa: Id[A]): A =
    fa

  extension [A](fa: Id[A])
    def cobind[B](f: Id[A] => B): Id[B] =
      f(fa)
```

Поскольку `Id[A] = A` и `Id[B] = B`, это снова просто.

### Сравнение сигнатур

```dotty
// Все три метода имеют одинаковую сигнатуру для Id!
map       [A, B](fa: Id[A])(f: A => B): Id[B]
flatMap   [A, B](fa: Id[A])(f: A => Id[B]): Id[B]
coflatMap [A, B](fa: Id[A])(f: Id[A] => B): Id[B]

// Упрощённо (подставляя Id[A] = A, Id[B] = B):
map       [A, B](fa: A)(f: A => B): B
flatMap   [A, B](fa: A)(f: A => B): B
coflatMap [A, B](fa: A)(f: A => B): B
```

Все три метода ведут себя одинаково — просто применяют функцию к значению.

## Практическое применение Id

### 1. Абстракция над эффектами

`Id` полезен для написания полиморфного кода, который может работать с разными монадами:

```dotty
def genericComputation[F[_]: Monad](value: Int): F[Int] =
  Monad[F].pure(value).map(_ + 1)

// С Id - без эффекта
genericComputation[Id](5) // 6

// С Option - с возможным отсутствием
genericComputation[Option](5) // Some(6)

// С List - с множественностью
genericComputation[List](5) // List(6)
```

### 2. Тестирование и прототипирование

`Id` позволяет тестировать код, написанный для монад, без реальных эффектов:

```dotty
case class User(id: Long)

trait UserService[F[_]]:
  def getUser(id: Long): F[User]
  def saveUser(user: User): F[Unit]

// Тестовая реализация с Id
class TestUserService extends UserService[Id]:
  private var users = Map.empty[Long, User]

  def getUser(id: Long): Id[User]    = users(id)
  def saveUser(user: User): Id[Unit] = users += (user.id -> user)
```

## Заключение

**Id — это монада "без эффекта"**, которая:

1. **Не добавляет никакого поведения** — значения не оборачиваются в конструкторы
2. **Является синонимом типа** — `type Id[A] = A`
3. **Упрощает абстракции** — позволяет писать полиморфный код для любых монад
4. **Полезна для тестирования** — заменяет реальные эффекты чистыми значениями
5. **Тривиально выполняет законы** — все законы сводятся к тождествам
6. **Является и монадой, и комонадой** — `map`, `flatMap` и `coflatMap` совпадают

Применение `Id` оправдано в ситуациях, когда:

- Нужно тестировать код с абстрактными эффектами
- Требуется композиция без эффектов в качестве базового слоя
- Вы пишете полиморфный код и хотите минимальный контекст
- Вам нужна моноидная структура для чистых вычислений

`Id` — это "нулевой" эффект, показывающий, что монады — это просто абстракция, 
которая может быть применена к чему угодно, даже к обычным значениям без эффектов.

## Реализация в библиотеках

### Реализация в Cats

```dotty
import cats.syntax.functor.*
import cats.{Id, Monad}

import cats.Monad

def genericComputation[F[_]: Monad](value: Int): F[Int] =
  Monad[F].pure(value).map(_ + 1)

// С Id - без эффекта
genericComputation[Id](5) // 6
```
