# Scala Native

[Scala Native](https://github.com/scala-native/scala-native) — это технология, 
позволяющая компилировать код Scala непосредственно в **нативный машинный код** (Native code), 
минуя виртуальную машину Java (JVM). В отличие от традиционной JVM-модели (байт-код → интерпретация / JIT-компиляция), 
Scala Native использует компилятор на основе [LLVM](https://llvm.org/) для создания автономных исполняемых файлов.

**Ключевые преимущества Scala Native:**

| Характеристика                   | JVM-компиляция                               | Scala Native                                   |
|:---------------------------------|:---------------------------------------------|:-----------------------------------------------|
| **Время запуска**                | От сотен миллисекунд до секунд               | **Микросекунды — миллисекунды**                |
| **Потребление памяти**           | Высокое (включая JVM)                        | **Значительно ниже**                           |
| **Размер итогового файла**       | JAR (от единиц до сотен МБ) + JVM            | Один исполняемый файл (единицы или десятки МБ) |
| **Пиковая производительность**   | Высокая (после прогрева JIT)                 | Ниже, чем у прогретой JVM                      |
| **Поддержка многопоточности**    | Полноценная (множество потоков)              | **Однопоточное выполнение** (на данный момент) |
| **Прямой вызов нативного кода**  | Через JNI (с большими накладными расходами)  | Да, напрямую (без накладных расходов)          |

**Когда использовать Scala Native:**

- **CLI-утилиты** — критически важен быстрый запуск.
- **Скрипты** — вам нужен мгновенный старт, сравнимый с Bash или Python.
- **Serverless / FaaS (AWS Lambda, Cloud Functions)** — критично время холодного старта.
- **Встраиваемые системы** с жёсткими ограничениями по памяти.
- **Высокопроизводительные вычисления** с вызовом нативного кода (BLAS, LAPACK, CUDA).

**Когда лучше использовать JVM/Cats Effect:**

- Долгоживущие серверы с высокими требованиями к пиковой пропускной способности (JVM после прогрева быстрее).
- Приложения, активно использующие конкурентность (Scala Native пока однопоточный).
- Когда важна максимальная переносимость («скомпилировал один JAR — бежит везде»).

## Поддержка Cats Effect

Начиная с версии **Cats Effect 3.3.14**, библиотека **полностью поддерживает Scala Native**. 
Это результат значительной работы по портированию `IO`, пулов потоков (work-stealing), 
`Resource`, `Ref`, `Deferred`, `Queue`, `Semaphore` и других примитивов на платформу Native.

> **Важно понимать:** На данный момент среда выполнения Scala Native является **однопоточной** 
> (но может переключаться между волокнами). Библиотеки, требующие многопоточности (например, кэширующие пулы потоков), 
> будут работать в однопоточном режиме. 
> Это не является существенным ограничением для CLI, парсеров, воркеров, скриптов и многих других приложений.

## Полный пример Hello World

### 1. Настройка плагина (`project/plugins.sbt`)

```dotty
// Проверьте актуальную версию
addSbtPlugin("org.scala-native" % "sbt-scala-native" % "0.4.17")
```

### 2. Конфигурация проекта (`build.sbt`)

```dotty
ThisBuild / organization := "com.example"
ThisBuild / scalaVersion := "3.8.3"

lazy val root = project.in(file("."))
  .enablePlugins(ScalaNativePlugin)
  .settings(
    name := "cats-effect-native-demo",
    libraryDependencies += "org.typelevel" %%% "cats-effect" % "3.7.0",
    Compile / mainClass := Some("com.example.Main")
  )
```

### 3. Код приложения (`src/main/scala/com/example/Main.scala`)

```dotty
package com.example

import cats.effect.{IO, IOApp}

object Main extends IOApp.Simple:
  def run: IO[Unit] = IO.println("Hello Cats Effect! I am a native binary.")
```

### 4. Компиляция

```bash
sbt nativeLink
```

Нативный исполняемый файл будет создан по адресу:

```
target/scala-3.8.3/cats-effect-native-demo-out
```

### 5. Запуск и бенчмарк

```bash
# Простой запуск
$ ./target/scala-3.8.3/cats-effect-native-demo-out
Hello Cats Effect! I am a native binary.

# Измерение времени запуска с помощью hyperfine
$ hyperfine ./target/scala-3.8.3/cats-effect-native-demo-out
Benchmark 1: ./target/scala-3.8.3/cats-effect-native-demo-out
  Time (mean ± σ):       7.5 ms ±   1.2 ms    [User: 3.6 ms, System: 2.3 ms]
  Range (min … max):     6.0 ms …  17.9 ms    141 runs
```

**Результат:** Запуск 7.5 мс — сопоставим с Go или C++ CLI-утилитами и значительно быстрее (в 10–100 раз) запуска на JVM.

## Ограничения Scala Native, важные для Cats Effect

### 1. Отсутствие многопоточности (сейчас)

```dotty
// На JVM это создало бы несколько потоков.
// На Native всё выполняется в одном потоке, но волокна Cats Effect
// всё равно могут переключаться между собой кооперативно.
val fib1 = longComputation.start
val fib2 = anotherLongComputation.start
```

**Последствия:**

- **Недоступен `IO#unsafeRunSync`** — метод, блокирующий поток до завершения. Он не имеет смысла в однопоточной среде.
- **`IO.blocking(...)` ведёт себя как `IO.delay(...)`** — выделенного блокирующего пула нет. 
  Если вы используете `blocking` в Native, он просто блокирует единственный поток выполнения.
- **Параллельные коллекции (`parTraverse`)** работают, но переключение между волокнами происходит в одном потоке.

### 2. Отсутствие `evalOn` (смена пула потоков)

Метод `IO.executionContext` и `IO.evalOn` не имеют смысла в однопоточной среде. 
При вызове они просто игнорируют переданный `ExecutionContext` (контекст выполнения) и продолжают выполнение в основном потоке.

### 3. Нет дампов волокон через сигналы POSIX

Scala Native не поддерживает `sun.misc.Signal`. Дампы волокон (`SIGUSR1` / `SIGINFO`) в Native приложениях недоступны.

### 4. Время выполнения и поведение

Всё, что не требует системных вызовов (чистые вычисления, `flatMap`, `map`), работает очень быстро. 
При этом вы можете спокойно вызывать нативные библиотеки C (например, для работы с GPU, векторизации, системным API).

## Альтернативные способы компиляции: `scala-cli`

Если вы не используете sbt, вы можете скомпилировать нативный образ с помощью `scala-cli`:

```bash
scala-cli package --native Main.scala -o hello-native
./hello-native
```

Это может быть проще для небольших скриптов и утилит.

## Пример реального приложения: HTTP-сервер `http4s` на Native

[Проект `scala-native-ember-example`](https://github.com/ChristopherDavenport/scala-native-ember-example) 
демонстрирует полноценный HTTP-сервер на базе Http4s и Ember, скомпилированный в нативный бинарник. 
Это доказывает, что даже несмотря на однопоточность, можно создавать эффективные сетевые приложения на Scala Native.

### Архитектура такого сервера:

- **Один поток** обрабатывает все входящие соединения.
- Волокна Cats Effect переключаются между сокетами и запросами кооперативно.
- Для работы с сокетами используется **неблокирующий ввод-вывод** (epoll / kqueue).
- Всё это внутри одного потока ОС может выдерживать тысячи соединений.

## Заключение и рекомендации

| Если ваш сценарий...                               | Рекомендуемый подход                                   |
|:---------------------------------------------------|:-------------------------------------------------------|
| CLI-утилита, скрипт, воркер                        | ✅ **Scala Native** (мгновенный запуск, малый размер)   |
| Сервер с интенсивным вводом-выводом (http4s, FS2)  | ⚠️ Возможно на Native, но с ограничениями              |
| Высококонкурентное приложение на многоядерном CPU  | 🟡 **JVM** (Native пока однопоточный)                  |
| Serverless / Lambda                                | ✅ **Scala Native** (холодный старт в 5-10 мс)          |
| Приложение, активно использующее `IO.blocking`     | ❌ **JVM** (в Native `blocking` бесполезен)             |

**Будущее:** Отсутствие многопоточности в Scala Native — временное ограничение. 
Команда Scala Native активно работает над поддержкой многопоточности. 
Как только эта функциональность станет стабильной, Cats Effect на Native получит полноценную параллельность на уровне JVM 
(но со всеми плюсами нативного бинарника).
