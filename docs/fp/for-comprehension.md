# For-comprehension

Представьте, что вам нужно работать со значениями, которые обернуты в контейнеры (например, `List`, `Option`, `Future`). 
Эти контейнеры говорят: "У меня есть значение, но чтобы с ним работать, нужно сначала "достать" его из контейнера".

**For-comprehension** — это специальный синтаксис в Scala, который делает работу с такими контейнерами удобной и читаемой. 
Это "синтаксический сахар" — более приятный способ записи цепочек вызовов `map`, `flatMap` и `filter`.

## Простейший пример: Один генератор

Допустим, у нас есть список чисел, и мы хотим каждое умножить на 2:

```dotty
for x <- List(1, 2, 3) // "достаем" каждый элемент из списка
yield x * 2 // преобразуем каждый элемент
// Результат: List(2, 4, 6)
```

Это эквивалентно вызову:

```dotty
List(1, 2, 3).map(x => x * 2)
```

Здесь `x <- List(1, 2, 3)` работает как `map` — применяет функцию к каждому элементу.

## Несколько генераторов: Комбинации

Теперь представим, что мы хотим получить все возможные пары из двух списков:

```dotty
for
  number <- List(1, 2)     // берем число из первого списка
  letter <- List('a', 'b') // для КАЖДОГО числа берем все буквы
yield (number, letter) // формируем пару
// Результат: List((1,'a'), (1,'b'), (2,'a'), (2,'b'))
```

Эквивалентный код без for-comprehension:

```dotty
List(1, 2).flatMap: number =>
  List('a', 'b').map: letter =>
    (number, letter)
```

Ключевой момент: второй генератор `letter <- List('a', 'b')` выполняется для **каждого** элемента из первого генератора. 
Это работает как вложенный цикл.

## Фильтрация: Добавляем условия

Мы можем фильтровать значения прямо внутри for-comprehension:

```dotty
for
  x <- 1 to 10 // берем числа от 1 до 10
  if x % 2 == 0 // оставляем только четные
yield x * x // возводим в квадрат
// Результат: Vector(4, 16, 36, 64, 100)
```

Условие `if` отфильтровывает элементы, которые не удовлетворяют условию.

## Практическая польза: Работа с Option

`Option` — это контейнер, который может содержать значение (`Some(value)`) или быть пустым (`None`). 
For-comprehension идеально подходит для последовательной работы с несколькими `Option`:

```dotty
def getUser(id: Int): Option[String] =
  if id == 123 then Some("Анна") else None // может вернуть Some или None

def getAge(name: String): Option[Int] =
  if name == "Анна" then Some(30) else None

for
  name <- getUser(123) // если getUser вернет None,
  age  <- getAge(name) // то getAge даже не вызовется
yield s"$name is $age years old"
// Результат: Some("Анна is 30 years old")
```

**Вот что делает этот код таким мощным:**

- Если `getUser(123)` вернет `None`, вычисления прекратятся, и весь результат будет `None`
- Если `getAge(name)` вернет `None`, результат также будет `None`
- Только если **все** операции вернут `Some`, выполнится блок `yield`

Это избавляет от многоуровневых проверок типа:

```dotty
// Без for-comprehension (менее читаемо)
getUser(123).flatMap(name =>
  getAge(name).map(age => s"$name is $age years old")
)
```

## Как это работает внутри?

Scala преобразует for-comprehension в цепочку вызовов:

1. `x <- collection` → `.flatMap(x => ...)`
2. Последний `yield` → `.map(...)`
3. `if condition` → `.withFilter(x => condition)`

Например:

```dotty
for
  a <- listA
  b <- listB
  if condition(a, b)
  c <- listC
yield f(a, b, c)
```

Преобразуется в:

```dotty
listA.flatMap(a =>
  listB.withFilter(b => condition(a, b))
    .flatMap(b =>
      listC.map(c => f(a, b, c))
    )
)
```

## Какие типы можно использовать?

Любой тип, который имеет методы:

- `flatMap` — для извлечения значений (`<-`)
- `map` — для преобразования (`yield`)
- `withFilter` — для фильтрации (`if`)

Это включает: `List`, `Option`, `Try`, `Future`, `Either` и многие другие.

## Когда использовать?

**Используйте for-comprehension, когда:**

- Работаете с несколькими вложенными контейнерами
- Нужно комбинировать значения из разных источников
- Хотите улучшить читаемость цепочек `map`/`flatMap`

**Не используйте, когда:**

- Делаете одну простую операцию (достаточно одного `map`)
- Работаете с типами, не поддерживающими `flatMap`/`map`

## Итог

For-comprehension — это:

- ✅ Читаемый способ работы с вложенными вычислениями
- ✅ Избавление от "адского" вложения `map`/`flatMap`
- ✅ Единый синтаксис для разных типов контейнеров
- ✅ Элегантная обработка отсутствующих значений (`Option`, `Try`)

Начинайте использовать for-comprehension, когда чувствуете, что цепочки `map`/`flatMap` становятся слишком сложными для восприятия.

## Упражнения

### Упражнение 4.1.1: Вложенные структуры

> [Репозиторий с упражнениями и инструкцией по выполнению][sample]

Дан список списков (матрица 3x2):

```dotty
val matrix = List(List(1, 2), List(3, 4), List(5, 6))  
```

Напишите for-comprehension, который преобразует эту матрицу в одномерный список, извлекая все элементы по порядку.

**Ожидаемый результат**:

```dotty
List(1, 2, 3, 4, 5, 6)
```  

@:note(🔍 Показать решение)

Этот for-comprehension преобразует вложенный список `matrix` в плоский, используя два генератора: 
первый (`row <- matrix`) последовательно извлекает каждый подсписок, 
а второй (`num <- row`) проходит по элементам текущего подсписка, 
после чего `yield num` собирает все элементы в одномерный список. 

```dotty
for
  // Итерация по внешнему списку 
  // (получаем List(1,2), затем List(3,4) и т.д.)
  row <- matrix  
  // Итерация по каждому внутреннему списку   
  num <- row   
// Возвращаем каждый элемент по отдельности       
yield num           
```

### Упражнение 4.1.2: Собственный тип для for-comprehension

Дан класс:

```dotty
case class Box[A](value: A)  
```

Сделайте так, чтобы с `Box` можно было использовать for-comprehension. 
Для этого необходимо реализовать методы `map` и `flatMap`, 
которые являются частью контракта for-comprehension в Scala.

**Пример**:

```dotty
val result =
  for
    a <- Box(2)
    b <- Box(3)
  yield a + b
// Ожидаемый результат: Box(5)
```  

@:note(🔍 Показать решение)

Для работы for-comprehension с типом `Box[A]` необходимо реализовать:

1. `map` - преобразует значение внутри `Box` с помощью функции `A => B`
2. `flatMap` - позволяет последовательно комбинировать операции, сохраняя контекст `Box`

```dotty
case class Box[A](value: A):
  def map[B](f: A => B): Box[B] = 
    Box(f(value))
  def flatMap[B](f: A => Box[B]): Box[B] = 
    f(value)
```

Объяснение:

- `map` создает новый `Box`, применяя функцию `f` к значению
- `flatMap` применяет функцию, которая уже возвращает `Box`, и "распаковывает" результат
- Этих двух методов достаточно для базового for-comprehension (без фильтрации)

### Упражнение 4.1.3: Совместимость типов в for-comprehension

Рассмотрим два варианта кода:

**Вариант 1**:

```dotty
val a = Option(1)
val b = List(1, 2, 3)

val c =
  for
    x <- a  // Генератор Option
    y <- b  // Генератор List
  yield x + y
```

**Вариант 2** (поменяли порядок генераторов):

```dotty
val c =
  for
    y <- b  // Генератор List
    x <- a  // Генератор Option
  yield x + y
```

**Вопросы**:

1. Какой тип и значение будет у `c` в первом варианте?
2. Какой тип и значение будет у `c` во втором варианте?

@:note(🔍 Показать решение)

**Ответ 1**: Первый вариант **не скомпилируется**.

**Причина**:

- Эквивалентный код: `a.flatMap(x => b.map(y => x + y))`
- `Option.flatMap` ожидает функцию `A => Option[B]`, но `b.map` возвращает `List[Int]`
- Нет неявного преобразования `List` → `Option`

**Ответ 2**: Второй вариант даст `List(2, 3, 4)`.

**Причина**:

- Эквивалентный код: `b.flatMap(y => a.map(x => x + y))`
- `List.flatMap` ожидает `A => IterableOnce[B]`
- `Option` неявно преобразуется в `IterableOnce`
- Результат: для каждого `y` из списка берётся `x` из `Option(1)`

**Дополнительные вопросы**:

Как сделать первый вариант рабочим (когда вначале идет `Option`)?

**Ответ 3**: явно преобразовать `Option` в коллекцию

```dotty
val c =
  for
    x <- a.toList
    y <- b
  yield x + y
```
