# Настройки и ложные срабатывания

## Детализация таймера (Timer Resolution) — ложные срабатывания

> **Это единственная первопричина, которая НЕ является законным голоданием, а приводит к ЛОЖНООТРИЦАТЕЛЬНЫМ срабатываниям детектора.**

Детектор голодания работает, сравнивая ожидаемое время `IO.sleep` с реальным. 
Если реальное время часто превышает ожидаемое, детектор думает, что планировщик задач работает плохо.

Но есть две причины, по которым сам таймер может быть неточен:

1. **Ограничение таймеров браузером (на Scala.js):** Браузеры, особенно Firefox, 
   могут ограничивать минимальную детализацию `setTimeout` 4 или даже 10 мс. 
   Это не влияет на порог в 100 мс, но делает тест менее точным.
2. **Конфликт таймеров (Timer Contention):** Это возникает, когда в вашем приложении создаётся **огромное количество** 
   очень коротких таймеров (например, миллионы `IO.sleep(1.milli)`). 

**В этих сценариях:** детектор срабатывает, но проблема не в голодании CPU, а в неточности таймеров. 
**Правильное решение — отключить детектор или увеличить его порог чувствительности**, а не пытаться «оптимизировать» планирование.

## Настройка детектора голодания (Configuration)

### Отключение (Disable)

**В большинстве случаев это НЕ рекомендуется!** Отключайте проверку только если:

1. У вас **нет никаких SLA (требований к задержке)**.
2. Или вы точно установили, что проблема в неточности таймеров (см. раздел выше).

```dotty
import scala.concurrent.duration.*

object MyMain extends IOApp:
  // Устанавливаем бесконечную задержку перед первым запуском проверки
  override def runtimeConfig =
    super.runtimeConfig.copy(cpuStarvationCheckInitialDelay = Duration.Inf)

  def run(args: List[String]) = ???
```

### Настройка чувствительности

По умолчанию детектор выдает предупреждение при задержке > **100 мс**. Это значение вычисляется как:
`cpuStarvationCheckInterval` (по умолчанию: `1.second`) × `cpuStarvationCheckThreshold` (по умолчанию: `0.1`).

- **Увеличение чувствительности (меньше ложных срабатываний):** Увеличьте интервал проверки.
- **Уменьшение чувствительности (раннее обнаружение проблем):** Уменьшите интервал.

```dotty
object MyOtherMain extends IOApp:
  // Увеличиваем порог до 500 мс
  override def runtimeConfig =
    super.runtimeConfig.copy(cpuStarvationCheckInterval = 5.seconds)

  def run(args: List[String]) = ???

```

**Главный совет:** Настройте чувствительность в соответствии с вашими **SLA**. 
Если ваш API должен отвечать за 200 мс, то порог в 100 мс вполне разумен. 
Если ваш бэкенд обрабатывает ночные batch-задачи, где задержка в секунды допустима, 
можно увеличить порог или вовсе отключить проверку.
