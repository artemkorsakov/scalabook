# Отмена волокон

В традиционных JVM-потоках отмена — это **головная боль**. Поток можно только прервать (`Thread.interrupt()`), но это:

- Работает только в ограниченном числе мест (например, `Thread.sleep()`, `Object.wait()`).
- Не очищает ресурсы автоматически.
- Легко теряется или игнорируется.
- Требует ручной проверки флага `Thread.isInterrupted()` в цикле.

**Волокна Cats Effect** решают эту проблему кардинально: отмена — это **операция первого класса**, встроенная в саму модель вычислений. Она:

1. **Согласованная** — волокно может контролировать, когда её обрабатывать.
2. **Безопасная** — гарантирует выполнение финализаторов (`guarantee`, `bracket`).
3. **Автоматическая** — высокоуровневые операторы (например, `parTraverse`) сами отменяют ненужные волокна.

### Простой пример отмены

```dotty
import cats.effect.{IO, IOApp}
import scala.concurrent.duration.*

object CancelDemo extends IOApp.Simple:
  def run: IO[Unit] =
    for
      // Запускаем волокно, которое печатает текст
      fiber <- IO.println("Catch me if you can!").foreverM.start

      // Ждём 3 секунды
      _ <- IO.sleep(3.seconds)

      // Отменяем волокно
      _ <- IO.println("Отменяем!")
      _ <- fiber.cancel

      // Ждём ещё секунду — печати не будет
      _ <- IO.sleep(1.second)
      _ <- IO.println("Готово")
    yield ()
```

**Вывод:**

```
Catch me if you can!
...
Catch me if you can!
...
Catch me if you can!
Отменяем!
Готово
```

**Что здесь произошло:**

1. Главное волокно создаёт дочернее волокно `fiber`, которое бесконечно печатает сообщение.
2. Оба волокна выполняются конкурентно.
3. Через 3 секунды главное волокно вызывает `fiber.cancel` — отправляет **сигнал отмены**.
4. Дочернее волокно получает сигнал, прекращает выполнение на ближайшей **точке отмены** (в данном случае — после завершения очередного `println`).
5. Попыток печати после отмены не происходит — волокно остановлено.

> **Важно:** Если бы волокно было занято CPU-интенсивными вычислениями без точек отмены, оно бы не остановилось мгновенно.

### Как работает отмена под капотом?

```dotty
// Отмена — это согласованный процесс
fiber.cancel  // Отправляет сигнал отмены

// Волокно должно "согласиться" отмениться
// Cats Effect автоматически проверяет отмену:
// - В точках flatMap
// - В операциях sleep
// - В async операциях
```

#### Механизм отмены (упрощённо)

1. **Сигнал** — `fiber.cancel` устанавливает внутренний флаг "cancel requested".
2. **Проверка** — при входе в каждую операцию, которая является **точкой отмены** (cancelation point), волокно проверяет этот флаг.
3. **Реакция** — если флаг установлен, волокно выбрасывает специальное исключение `CanceledException` и начинает процесс финализации.
4. **Очистка** — выполняются все `guarantee`, `bracket` и другие обработчики ресурсов.
5. **Завершение** — волокно переходит в состояние `Canceled`, его `join` возвращает `Outcome.Canceled`.

#### Где находятся точки отмены?

Cats Effect автоматически вставляет проверки отмены в:

- **Каждый `flatMap`** — после завершения одного эффекта и перед переходом к следующему.
- **`IO.sleep`** — можно проснуться досрочно из-за отмены.
- **`IO.async`** и `IO.async_` — при ожидании callback'а.
- **`IO.cede`** — явная передача управления (также точка отмены).
- **`IO.defer`**, `IO.raiseError`, `IO.pure` — в некоторых случаях.

> Это означает, что **большинство кода уже отменяемо** без дополнительных усилий.

## CPU-интенсивные операции и проблема "неотменяемости"

Если волокно занято **чистыми вычислениями** без точек отмены (например, долгий цикл, сложные математические расчёты), 
сигнал отмены не будет обработан до завершения вычислений. Это может привести к задержкам или даже "зависанию".

```dotty
// Плохо: этот код проигнорирует отмену на 10 секунд
MonadCancel[F].uncancelable: _ =>
  // Цикл без точек отмены!
  (0 until 1_000_000_000).foreach: i =>
    math.sqrt(i) // тяжёлые вычисления
```

**Решение:** добавлять **явные точки отмены** через `poll` и `IO.cede`.

```dotty
// Хорошо: периодически проверяем отмену
MonadCancel[F].uncancelable: poll =>
  def loop(i: Int): F[Unit] =
    if i >= 1_000_000_000 then MonadCancel[F].unit
    else
      // Позволяем отмене произойти на каждой итерации
      poll(IO.cede) >> // ← точка отмены
        IO {
          math.sqrt(i)
          i + 1
        }.flatMap(loop)

  loop(0)
```

**Объяснение:**

- `poll(IO.cede)` — временно разрешает отмену внутри `uncancelable`.
- `IO.cede` — принудительно передаёт управление планировщику и **проверяет отмену**.
- Если сигнал отмены есть, выполнение перейдёт в финализаторы, минуя остаток вычислений.

## Реальный пример: параллельные HTTP-запросы с автоотменой

```dotty
import cats.effect.IO
import cats.syntax.all.*

val urls = List(
  "https://api1.example.com",
  "https://api2.example.com",
  "https://api3.example.com",
  "https://api4.example.com"
)

// Параллельно загружаем все URL
val result: IO[List[String]] = urls.parTraverse: url =>
  httpClient.get(url).flatMap: response =>
    if response.isSuccess then IO.pure(response.body)
    else IO.raiseError(new Exception(s"Ошибка: $url"))
```

**Что происходит при ошибке:**

1. Четыре волокна стартуют одновременно, каждое загружает свой URL.
2. Допустим, `api2` вернул ошибку. Его волокно вызывает `IO.raiseError`.
3. `parTraverse` **немедленно отменяет все остальные волокна** (`api1`, `api3`, `api4`).
4. Отменённые волокна прекращают загрузку (возможно, уже частичную) и освобождают соединения.
5. Внешний `IO` завершается с ошибкой, не дожидаясь завершения ненужных запросов.

**Экономия:** вместо ожидания всех 4 запросов (включая медленные или висящие) мы прерываемся при первой же ошибке. 
В реальных системах это экономит секунды и ресурсы.

## Сравнение: отмена волокон vs прерывание потоков

| Характеристика                 | `Thread.interrupt()`                           | `Fiber.cancel`                              |
|--------------------------------|------------------------------------------------|---------------------------------------------|
| **Модель**                     | Императивная, с исключениями                   | Функциональная, встроенная в `F[_]`         |
| **Гарантия очистки ресурсов**  | Нет (нужен `try/finally`)                      | Да (`guarantee`, `bracket`)                 |
| **Точки отмены**               | Только блокирующие операции (`sleep`, `wait`)  | Любой `flatMap`, `cede`, `async`            |
| **Вложенность**                | Прерывание "бьёт" через все стеки              | Кооперативное, уважает `uncancelable`       |
| **CPU-интенсивные задачи**     | Не останавливаются (нужна ручная проверка)     | Не останавливаются (тоже нужен `cede`)      |
| **Безопасность**               | Можно прервать в неподходящий момент           | `uncancelable` защищает критические секции  |

**Вывод:** волокна дают **контролируемую, предсказуемую и безопасную отмену**, которой не хватает классическим потокам.

## Высокоуровневые паттерны с автоотменой

Cats Effect и Cats предоставляют множество операторов, которые **автоматически управляют отменой**:

| Оператор       | Что делает                                                              | Поведение при ошибке          |
|----------------|-------------------------------------------------------------------------|-------------------------------|
| `parTraverse`  | Параллельно обработать каждый элемент                                   | Отмена всех, если любой упал  |
| `parSequence`  | Параллельно выполнить список эффектов                                   | Отмена всех, если любой упал  |
| `race`         | Гонка между двумя эффектами                                             | Отмена проигравшего           |
| `racePair`     | Гонка с доступом к волокну проигравшего                                 | Контролируемая отмена         |
| `timeout`      | Ограничение времени выполнения                                          | Отмена по таймауту            |
| `background`   | Запуск в фоне с автоматической отменой при выходе из области видимости  | Отмена при финализации        |

## Практические советы по работе с отменой

1. **Всегда используйте `guarantee` или `bracket` для ресурсов** — никогда не полагайтесь на то, что "код просто завершится".
2. **В долгих CPU-циклах добавляйте `IO.cede`** — иначе волокно может "залипнуть" и не отреагировать на отмену.
3. **Используйте `uncancelable` только там, где действительно нужно** — избыточное использование мешает отмене.
4. **При ручном управлении волокнами** — сохраняйте `Fiber` и вызывайте `cancel` в финализаторах.
5. **Для фоновых процессов** — используйте `background` вместо ручного `start`/`cancel`.

```dotty
// Плохо: утечка волокна
def startBackground[F[_]: Spawn](task: F[Unit]): F[Unit] =
  task.start.void

// Хорошо: волокно отменится при выходе из use
def startBackgroundSafe[F[_]: Spawn: MonadCancel](task: F[Unit]): Resource[F, Unit] =
  Resource.make(task.start)(_.cancel).void
```
