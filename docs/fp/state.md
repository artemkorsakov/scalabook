# Функциональное состояние

## Описание и концепция

Функциональный подход к управлению состоянием основан на фундаментальном шаблоне, 
позволяющем моделировать любой API с отслеживанием состояния, сохраняя при этом чистоту функций. 
Базовый шаблон реализуется следующим образом:

```dotty
opaque type State[S, +A] = S => (A, S)

object State:
  extension [S, A](underlying: State[S, A])
    // Выполняет вычисление состояния, возвращая результат и новое состояние
    def run(s: S): (A, S) = underlying(s)

  // Конструктор для создания State из функции
  def apply[S, A](f: S => (A, S)): State[S, A] = f
```

### Анализ реализации

Тип `State[S, A]` представляет собой:

1. **Вычисление с состоянием** - операцию, которая зависит от и может изменять некоторое состояние типа `S`
2. **Чистую функцию** - преобразование входного состояния в пару (результат, новое состояние)
3. **Абстракцию** - скрытую за `opaque type` для обеспечения безопасности типов

Ключевые компоненты:

- `run` - единственный способ "извлечь" значение из `State`, выполнив вычисление
- `apply` - фабричный метод для создания `State`-вычислений

Использование `opaque type` вместо простого type alias дает важные преимущества:

1. **Инкапсуляция** - за пределами модуля `State` невозможно узнать, что `State` — это просто функция
2. **Безопасность** - предотвращает случайное смешивание с обычными функциями
3. **Гибкость** - позволяет изменять внутреннюю реализацию без изменения API

```dotty
// Пример использования:
val counter: State[Int, String] = State { s => 
  ("Result", s + 1) 
}
counter.run(0)  // ("Result", 1)
```

### Преимущества подхода

1. **Чистота** - все изменения состояния явные и контролируемые
2. **Тестируемость** - состояния можно легко имитировать
3. **Композируемость** - сложное поведение собирается из простых компонентов
4. **Потокобезопасность** - естественная иммутабельность

### Резюме

- **Функциональное состояние** - это вычисление, преобразующее входное состояние в результат и новое состояние
- **State** предоставляет:
    - Чистый способ работы с изменяемым состоянием
    - Возможность композиции state-трансформаций
    - Явное отслеживание потока состояния

### Упражнение 6.1.1: Генерация последовательности Фибоначчи с помощью State

> [Репозиторий с упражнениями и инструкцией по выполнению][sample]

Требуется реализовать генератор чисел Фибоначчи, используя `State`. 
Генератор должен принимать текущее состояние и возвращать следующее число Фибоначчи с обновленным состоянием.

```dotty   
// Генерация последовательности Фибоначчи  
val fibState: State[???, ???] =
  State(???)
```  

**Примеры:**

```dotty  
fibState.run((5, 8)) // (5, (8, 13)) 
// Возвращается текущее число (5), новое состояние — (8, 13)
```  

@:note(🔍 Показать решение)

Генератор чисел Фибоначчи можно реализовать с помощью `State[(Long, Long), Long]`, 
где состояние — это текущая пара чисел `(a, b)`, 
а выходное значение — очередное число последовательности (`a`). 
При каждом вызове состояние обновляется: `a` заменяется на `b`, а `b` — на `a + b`.

```dotty  
val fibState: State[(Long, Long), Long] =
  State((a, b) => (a, (b, a + b)))
```  

Как это работает:

1. Входное состояние: `(a, b)` (например, `(5, 8)`).
2. Возвращаемое значение: `a` (в примере — `5`).
3. Новое состояние: `(b, a + b)` (в примере — `(8, 13)`).

Таким образом, каждый вызов `fibState.run` генерирует очередное число Фибоначчи и продвигает состояние вперед.

@:@

## Пример функционального состояния

Рассмотрим упрощенный пример машины по раздаче конфет.

```dotty
case class SimpleMachine(candies: Int, coins: Int)
```

Если в машине остались конфеты и ей заплатить монету, то она выдаст конфету.
Количество конфет уменьшиться на 1, а количество монет увеличится на 1.
В остальных случаях состояние машины не изменится.

Опишем это функцией вычисления следующего состояния машины:

```dotty
case class SimpleMachine(candies: Int, coins: Int):
  self =>

  lazy val next: SimpleMachine =
    if candies <= 0 then self
    else SimpleMachine(candies - 1, coins + 1)
```

Определим `State`, вычисляющий значение - количество заработанных монет:

```dotty
val state: State[SimpleMachine, Int] = State(sm => (sm.coins + 1, sm.next))
```

Здесь используется метод `apply`, создающий значение `State` из функции.

Запустить вычисление значения и следующего состояния можно, вызвав `run`:

```dotty
val initial = SimpleMachine(100, 0)
state.run(initial)
// (1, SimpleMachine(99, 1))
```

## Функции общего назначения

Функции общего назначения, описывающие шаблоны программ с отслеживанием состояния. 
Эти функции образуют базовый набор операций для работы со `State`, позволяя комбинировать 
и преобразовывать вычисления с состоянием.

### Основные комбинаторы

#### map

Функция `map` позволяет трансформировать значение внутри контекста `State`, не затрагивая само состояние. 
При наличии базового шаблона `State[S, A]` и функции преобразования `A => B` создается новый `State`, 
который при выполнении:

1. Принимает начальное состояние типа `S`
2. Запускает исходный `State`, получая пару `(A, S1)`
3. Применяет функцию `f` к значению `A`, получая `B`
4. Возвращает пару `(B, S1)`

```dotty
object State:
  extension [S, A](underlying: State[S, A])
    def map[B](f: A => B): State[S, B] =
      s =>
        val (a, s1) = run(s)
        (f(a), s1)
```

Пример использования показывает преобразование числового значения в строку:

```dotty
val stateB = state.map(coins => s"Заработано $coins монет")
stateB.run(initial)
// Результат: (Заработано 1 монет, SimpleMachine(99, 1))
```

#### map2

Комбинатор `map2` позволяет параллельно выполнить два `State`-вычисления и объединить их результаты с помощью функции. 

Особенности:

- Вычисления выполняются последовательно, состояние передается от первого ко второму
- Позволяет комбинировать результаты без явного извлечения значений

```dotty
object State:
  extension [S, A](underlying: State[S, A])
    def map2[B, C](sb: State[S, B])(f: (A, B) => C): State[S, C] =
      s0 =>
        val (a, s1) = run(s0)
        val (b, s2) = sb.run(s1)
        (f(a, b), s2)
```

Пример демонстрирует конкатенацию строк из двух `State`-вычислений:

```dotty
val stateA = State[SimpleMachine, String](sm => ("Первое изменение", sm.next))
val stateB = State[SimpleMachine, String](sm => (", Второе изменение", sm.next))
val stateC = stateA.map2(stateB)(_ + _)

stateC.run(initial)
// Результат: (Первое изменение, Второе изменение, SimpleMachine(98, 2))
```

#### flatMap

Функция `flatMap` (также известная как `bind`) позволяет создавать последовательные вычисления, 
где каждое следующее зависит от результата предыдущего. 
Это ключевая операция для `State`.

```dotty
object State:
  extension [S, A](underlying: State[S, A])
    def flatMap[B](f: A => State[S, B]): State[S, B] =
      s0 =>
        val (a, s1) = run(s0)
        f(a)(s1)
```

Пример показывает ветвление логики в зависимости от промежуточного результата:

```dotty
val stateA = State[SimpleMachine, Int](sm => (sm.candies - 1, sm.next))
val f: Int => State[SimpleMachine, String] = candies =>
  if candies <= 0 then State(sm => ("Конфеты кончились", sm))
  else State(sm => ("Конфеты ещё есть", sm))

val stateB = stateA.flatMap(f)

stateB.run(initial)
// Результат: (Конфеты ещё есть, SimpleMachine(99, 1))
```

### Синтаксический сахар

#### for-comprehension

Благодаря наличию `map` и `flatMap`, `State` можно использовать в for-нотации, 
что значительно улучшает читаемость последовательных операций:

```dotty
val stateB =
  for
    candies <- stateA      // извлекаем значение candies
    message <- f(candies)  // передаем его в следующее вычисление
  yield message            // возвращаем результат

stateB.run(initial)
// Результат: (Конфеты ещё есть, SimpleMachine(99, 1))
```

### Базовые конструкторы

#### unit

Функция `unit` (также называемая `pure`) создает `State`, который:

- Не изменяет состояние
- Содержит переданное значение
- Является нейтральным элементом для `flatMap`

```dotty
object State:
  def unit[S, A](a: A): State[S, A] =
    s => (a, s)
```

Пример создания тривиального `State`:

```dotty
val stateA = State.unit[SimpleMachine, String]("Сообщение")
stateA.run(initial)
// Результат: (Сообщение, SimpleMachine(100, 0))
```

### Работа с состоянием

#### get, set и modify

Триада функций для непосредственной работы с состоянием:

1. `get` - получает текущее состояние, делая его доступным как значение
2. `set` - полностью заменяет текущее состояние новым
3. `modify` - трансформирует состояние с помощью функции

```dotty
object State:
  def get[S]: State[S, S] = s => (s, s)  // возвращает текущее состояние

  def set[S](s: S): State[S, Unit] = _ => ((), s)  // игнорирует старое состояние

  def modify[S](f: S => S): State[S, Unit] =
    for
      s <- get       // получаем текущее состояние
      _ <- set(f(s)) // устанавливаем преобразованное
    yield ()
```

Примеры использования:

```dotty
val initial = SimpleMachine(100, 0)
val other   = SimpleMachine(0, 100)

// Чтение состояния
State.get[SimpleMachine].run(initial)
// (SimpleMachine(100, 0), SimpleMachine(100, 0))

// Запись состояния
State.set(other).run(initial)
// ((), SimpleMachine(0, 100))

// Модификация состояния
State.modify[SimpleMachine](_.next).run(initial)
// ((), SimpleMachine(99, 1))
```

### Работа с коллекциями

#### traverse и sequence

Функции для обработки коллекций `State`-вычислений:

- `traverse` - преобразует список значений в `State`-вычисления с помощью функции и собирает результаты
- `sequence` - специальный случай `traverse`, где вход уже является списком `State`-вычислений

```dotty
object State:
  def sequence[S, A](list: List[State[S, A]]): State[S, List[A]] =
    traverse(list)(identity)  // применяет identity к каждому элементу

  def traverse[S, A, B](as: List[A])(f: A => State[S, B]): State[S, List[B]] =
    as.foldRight(unit[S, List[B]](Nil))((a, acc) => f(a).map2(acc)(_ :: _))
    // Правоассоциативное свертывание с накоплением результатов
```

Ключевые особенности:

- Вычисления выполняются последовательно
- Состояние передается от одного вычисления к следующему
- Результаты собираются в список в том же порядке

## Автомат, моделирующий раздачу конфет

Давайте реализуем более сложный автомат, моделирующий раздатчик конфет по принципу конечного автомата (_state machine_). 
Этот автомат демонстрирует классический пример управления состоянием 
с четко определенными правилами перехода между состояниями.

### Модель данных

Автомат имеет:

Два типа входа (взаимодействия пользователя):

```dotty
enum Input:
  case Coin  // Монета (платеж)
  case Turn  // Поворот ручки (получение товара)
```

Состояние, описываемое тремя параметрами:

```dotty
case class Machine(
  locked: Boolean,  // Текущий статус блокировки
  candies: Int,     // Остаток конфет
  coins: Int        // Количество собранных монет
)
```

### Правила работы автомата

Автомат реализует строгую бизнес-логику с помощью следующих правил:

(а) **Разблокировка при оплате**  
   
Если вставить монету (`Coin`) в заблокированный автомат (`locked = true`), он разблокируется (при наличии конфет), увеличивая счетчик монет.

(б) **Выдача товара**  
   
Поворот ручки (`Turn`) на разблокированном автомате (`locked = false`):

- Уменьшает количество конфет
- Автоматически блокирует машину

(в) **Игнорирование невалидных действий**  

Система игнорирует:

- Поворот ручки на заблокированном автомате
- Вставку монеты в уже разблокированный автомат

(г) **Режим "Товара нет"**

Машина с нулевым количеством конфет (`candies = 0`) полностью игнорирует любые входные данные.

### Реализация логики состояний

Функция `updateMachine` реализует детерминированный конечный автомат, 
где каждое сочетание (`Input`, `Machine`) однозначно определяет следующее состояние:

```dotty
object Candy:
  private val updateMachine: Input => Machine => Machine =
    (i: Input) =>
      (s: Machine) =>
        (i, s) match
          // (г) Режим отсутствия товара
          case (_, Machine(_, 0, _)) => s
          
          // (в) Некорректные действия
          case (Input.Coin, Machine(false, _, _)) => s
          case (Input.Turn, Machine(true, _, _))  => s
          
          // (а) Успешная оплата
          case (Input.Coin, Machine(true, candy, coin)) =>
            Machine(false, candy, coin + 1)
            
          // (б) Успешная выдача товара
          case (Input.Turn, Machine(false, candy, coin)) =>
            Machine(true, candy - 1, coin)
```

### Симулятор работы автомата

Метод `simulateMachine` обрабатывает последовательность действий, применяя State-модификации:

```dotty
object Candy:
  def simulateMachine(inputs: List[Input]): State[Machine, (Int, Int)] =
    for
      // Применяем все входные действия как State-трансформации
      _ <- State.traverse(inputs)(input => 
        State.modify(updateMachine(input)))
      
      // Получаем финальное состояние
      s <- State.get
    yield (s.coins, s.candies)
```

Ключевые моменты реализации:

1. `State.traverse` последовательно применяет каждое действие из списка `inputs`
2. `State.modify` преобразует машину согласно правилам `updateMachine`
3. Игнорируется результат промежуточных шагов (`List[Unit]`)
4. Финальное состояние извлекается через `State.get`
5. Возвращается кортеж `(coins, candies)` как результат

### Пример работы

Рассмотрим детальный пример с трассировкой состояния:

```dotty
val initialMachine = Machine(
  locked = true,  // Автомат заблокирован
  candies = 5,    // 5 конфет доступно
  coins = 10      // 10 монет уже в автомате
)

val inputs = List(
  Coin, // 1. Разблокировка (+1 монета)
  Turn, // 2. Выдача конфеты (-1 конфета)
  Coin, // 3. Разблокировка (+1 монета)
  Coin, // 4. Повторная оплата (игнорируется)
  Coin, // 5. Повторная оплата (игнорируется)
  Turn, // 6. Выдача конфеты (-1 конфета)
  Turn, // 7. Не сработает (заблокировано)
  Turn, // 8. Не сработает (заблокировано)
  Coin, // 9. Разблокировка (+1 монета)
  Turn  // 10. Финальная выдача (-1 конфета)
)

val ((totalCoins, remainingCandies), finalState) =
  Candy.simulateMachine(inputs).run(initialMachine)

// Результат: ((13, 2), Machine(true, 2, 13))
```

Пошаговая семантика:

1. Начальное состояние: (10 монет, 5 конфет)
2. Успешные операции: 1, 2, 3, 6, 9, 10
3. Игнорированные операции: 4, 5, 7, 8
4. Итог: +3 монеты (13), -3 конфеты (2)

### Архитектурные особенности

1. **Чистота вычислений** - Все преобразования состояний иммутабельны
2. **Композиционность** - Логика собрана из мелких компонентов
3. **Явное моделирование** - Все состояния и переходы четко определены
4. **Тестируемость** - Легко проверить любую последовательность действий

Такой подход демонстрирует эффективное применение функционального состояния 
для моделирования реальных процессов с сохранением контроля над сложностью.
