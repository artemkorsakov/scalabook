# TailRec: прыжки на батуте

## Проблема переполнения стека в функциональных программах

Рассмотрим проблему стека в функциональном программировании на примере типа `IO`, 
который представляет отложенные вычисления с эффектами.

### Исходное определение IO

```dotty
trait IO[A]:
  self =>

  def unsafeRun(): A

  def map[B](f: A => B): IO[B] = new:
    def unsafeRun(): B = f(self.unsafeRun())

  def flatMap[B](f: A => IO[B]): IO[B] = new:
    def unsafeRun(): B = f(self.unsafeRun()).unsafeRun()

  def forever[B]: IO[B] =
    lazy val t: IO[B] = self.forever
    self.flatMap(_ => t)
    
object IO:
  def apply[A](a: => A): IO[A] = new:
    def unsafeRun(): A = a    
```

Проблема возникает при выполнении бесконечных операций, например:

```dotty
def PrintLine(msg: String): IO[Unit] = IO(println(msg))

val p = PrintLine("Still going...").forever
p.unsafeRun()  // Вызывает StackOverflowError
```

### Почему происходит переполнение стека?

Пошагово рассмотрим реализацию `flatMap` для типа `IO`:

```dotty
def flatMap[B](f: A => IO[B]): IO[B] = new IO[B]:
  def unsafeRun(): B =
    val a: A          = self.unsafeRun() // Шаг 1: выполнение текущего IO
    val nextIO: IO[B] = f(a)             // Шаг 2: создание следующего IO
    nextIO.unsafeRun() // Шаг 3: выполнение следующего IO
```

#### Пошаговый процесс выполнения:

1. **Первый вызов `flatMap`:**
    - Создается новый экземпляр `IO[B]`
    - При вызове `unsafeRun()`:
        - Выполняется `self.unsafeRun()` (текущая операция)
        - Применяется функция `f` к результату
        - Немедленно вызывается `unsafeRun()` для результата `f(a)`

2. **Последующие вызовы:**
    - Каждый следующий `flatMap` добавляет новый вызов `unsafeRun()` в стек:
      ```dotty
      IO(1)
          .flatMap(x => IO(x + 1)) // Уровень 1
          .flatMap(y => IO(y * 2)) // Уровень 2
          .unsafeRun()
      ```
    - Стек вызовов:
      ```
      unsafeRun (Уровень 2)
      unsafeRun (Уровень 1)
      unsafeRun (Исходный IO)
      ```

3. **Проблема переполнения:**
    - Каждый `flatMap` требует нового кадра стека
    - При длинных цепочках (например, в цикле) происходит `StackOverflowError`
    - Глубина стека типично ограничена ~1000-10000 вызовов

#### Коренная причина:

Реализация использует **не-хвостовую рекурсию**, так как:

- Вызов `nextIO.unsafeRun()` не является последней операцией (после него идет неявный возврат)
- JVM не может выполнить оптимизацию хвостового вызова

## Явное моделирование потока управления

Традиционный подход к реализации `IO` обычно скрывает детали управления потоком выполнения внутри методов, 
таких как `flatMap`, полагаясь на скрытое состояние или стек вызовов. 
В предлагаемом подходе **поток управления материализуется явно** в виде структуры данных, 
что дает несколько преимуществ:

1. **Прозрачность**: структура программы становится видимой и инспектируемой
2. **Контроль**: мы получаем полный контроль над выполнением программы
3. **Гибкость**: можем реализовать различные стратегии выполнения

### Новое определение IO через алгебраический тип данных

```dotty
enum IO[A]:
  self =>

  // Это чистое вычисление, которое последовательно возвращает A без каких-либо шагов.
  case Return(a: A)

  // Это приостановка вычисления, где возобновление — это функция,
  // которая не принимает аргументов, но оказывает некоторое воздействие и выдает результат.
  case Suspend(resume: () => A)

  // Это композиция из двух шагов.
  // Она материализует FlatMap как конструктор данных, а не как функцию.
  case FlatMap[B, C](sub: IO[B], k: B => IO[C]) extends IO[C]

  def flatMap[B](f: A => IO[B]): IO[B] =
    FlatMap(self, f)

  def map[B](f: A => B): IO[B] =
    flatMap(a => Return(f(a)))

  def forever[B]: IO[B] =
    lazy val t: IO[B] = self.forever
    self.flatMap(_ => t)
end IO

object IO:
  def apply[A](a: => A): IO[A] =
    Suspend(() => a)
```

### Конструкторы данных

1. **`Return(a: A)`**:
    - Представляет завершенное вычисление с результатом `a`
    - Когда интерпретатор встречает `Return`, он знает, что достиг конца вычисления

2. **`Suspend(resume: () => A)`**:
    - Инкапсулирует побочный эффект, который нужно выполнить
    - `resume` - это "замороженный" эффект, который можно выполнить позже
    - Позволяет отделить описание эффекта от его выполнения

3. **`FlatMap[B, C](sub: IO[B], k: B => IO[C])`**:
    - Представляет последовательную композицию двух вычислений
    - `sub` - первое вычисление
    - `k` - продолжение, которое получает результат `sub` и возвращает следующее вычисление
    - Ключевое отличие от традиционного `flatMap`: это не метод, а конструктор данных

### Методы типа `IO`

1. **`flatMap`**:
    - Реализация теперь тривиальна - просто создает конструктор `FlatMap`
    - Не выполняет никакой работы, только строит структуру данных
    - Откладывает реальную работу до момента интерпретации

2. **`map`**:
    - Реализован через `flatMap` и `Return`
    - Преобразует результат, не добавляя новых эффектов

### Сопутствующий объект `IO`

- **`apply`** (фабричный метод):
    - Создает приостановленное вычисление
    - Принимает по имени параметр (`a: => A`), чтобы отложить вычисление

### Пример построения программы

```dotty
def printLine(s: String): IO[Unit] =
  IO(println(s))

val p = printLine("Still going...").forever
```

Эта программа строится как вложенная структура:

```dotty
FlatMap(
  Suspend(() => println("Still going...")),
  _ => FlatMap(
    Suspend(() => println("Still going...")),
    _ => FlatMap(...)))
```

## Интерпретатор с хвостовой рекурсией

### Реализация unsafeRun

```dotty
@annotation.tailrec
final def unsafeRun(): A =
  self match
    case Return(a)  => a   // Базовый случай - возвращаем результат
    case Suspend(r) => r() // Выполняем эффект
    case FlatMap(x, f) =>
      x match
        case Return(a)  => f(a).unsafeRun()   // Продолжаем с результатом
        case Suspend(r) => f(r()).unsafeRun() // Выполняем эффект и продолжаем
        case FlatMap(y, g) =>
          // В этом случае io — это выражение вроде FlatMap(FlatMap(y, g), f).
          // Переписываем левоассоциативную цепочку в правоассоциативную, 
          // чтобы вызвать unsafeRun в хвостовой позиции
          y.flatMap(a => g(a).flatMap(f)).unsafeRun()
```

Интерпретатор `unsafeRun` выполняет программу, представленную в виде структуры данных `IO`, 
гарантируя стекобезопасность через хвостовую рекурсию. 
Это означает, что программа может выполняться бесконечно (например, сервер) без риска переполнения стека.

### Аннотация `@annotation.tailrec`

```dotty
@annotation.tailrec
final def unsafeRun(): A
```

- Гарантирует, что компилятор проверит, что метод действительно является хвостовой рекурсией
- Если проверка не проходит - ошибка компиляции
- `final` предотвращает переопределение метода

### Сопоставление с шаблоном

**Случай `Return(a)`**:

```dotty
case Return(a) => a
```

- Базовый случай рекурсии
- Просто возвращает вычисленное значение
- Останавливает выполнение программы

**Случай `Suspend(r)`**:

```dotty
case Suspend(r) => r()
```

- Выполняет отложенный эффект (вызывает функцию `r`)
- Возвращает результат выполнения эффекта

**Случай `FlatMap(x, f)`** (самый сложный случай):

```dotty
case FlatMap(x, f) =>
  x match
    case Return(a)  => f(a).unsafeRun()  
    case Suspend(r) => f(r()).unsafeRun()
    case FlatMap(y, g) =>
      y.flatMap(a => g(a).flatMap(f)).unsafeRun()
```

- Здесь происходит основная магия стекобезопасности
- Разбираем внутреннюю структуру `x`

#### Подслучай `Return(a)`:

```dotty
case Return(a) => f(a).unsafeRun()
```

- Если подвычисление уже завершено (`Return`)
- Применяем продолжение `f` к результату `a`
- Рекурсивно вызываем `unsafeRun` для результата

#### Подслучай `Suspend(r)`:

```dotty
case Suspend(r) => f(r()).unsafeRun()
```

- Выполняем эффект `r()`
- Передаем результат в продолжение `f`
- Рекурсивно вызываем `unsafeRun`

#### Подслучай `FlatMap(y, g)` (вложенные FlatMap):

```dotty
case FlatMap(y, g) => y.flatMap(a => g(a).flatMap(f)).unsafeRun()
```

Это самая важная часть для обеспечения стекобезопасности.

**Что происходит**:

1. Имеем структуру `FlatMap(FlatMap(y, g), f)`
2. Итоговая картина типов до преобразования: `FlatMap(FlatMap(y: IO[A], g: A => IO[B]), f: B => IO[C])`.
   Цель — вычислить значение типа `C`.
3. Переписываем ее в эквивалентную правоассоциативную форму:
    - Было: `y.flatMap(g).flatMap(f)`
    - Стало: `y.flatMap(a => g(a).flatMap(f))`
4. Используем [монадический закон ассоциативности](../../typeclass/monad/monad.md):
   `(x.flatMap(f)).flatMap(g) == x.flatMap(a => f(a).flatMap(g))`

Выражение `y.flatMap(a => g(a).flatMap(f))` разберем по шагам:

1. **Внутренний `flatMap` (`g(a).flatMap(f)`)**:
   - `a: A` (значение, извлеченное из `y`)
   - `g(a): IO[B]` (результат применения продолжения `g` к `a`)
   - `f: B => IO[C]` (продолжение внешнего `FlatMap`)
   - **`g(a).flatMap(f): IO[C]`** — применяем функцию `f` к результату вычисления `g(a)`. Тип результата этого выражения — `IO[C]`.
2. **Лямбда-функция (`a => ...`)**:
   - `a: A` (входной параметр)
   - Тело функции: `g(a).flatMap(f): IO[C]` (результат шага 1)
   - **Тип лямбды: `A => IO[C]`**. Это функция, которая принимает значение типа `A` и 
     возвращает новую программу `IO`, которая в итоге вычисляет тип `C`.
3. **Внешний `flatMap` (`y.flatMap(...)`)**:
   - `y: IO[A]` (исходное вычисление)
   - Лямбда: `A => IO[C]` (результат шага 2)
   - **`y.flatMap(a => g(a).flatMap(f)): IO[C]`** — применяем нашу новую лямбду к результату вычисления `y`. 
     Тип результата — `IO[C]`, который полностью соответствует типу исходного выражения.

**Визуализация преобразования**

Было (левоассоциативная цепочка, опасная для стека):

```dotty
val program: IO[C] =
  y.flatMap(g) // IO[B]
   .flatMap(f) // IO[C]
```

Стало (правоассоциативная цепочка, стекобезопасная):

```dotty
val transformedProgram: IO[C] =
  y.flatMap { a: A => // Внешний flatMap
    g(a)              // IO[B]
      .flatMap(f)     // IO[C] (это выражение является телом лямбды)
  }
```

Преобразование **не меняет итоговый тип вычисления**, который всегда остается `IO[C]`. 
Меняется лишь _структура_ монадической цепочки:

- Исходная структура: `FlatMap(FlatMap(y, g), f)`
- Цель преобразования: `FlatMap(y, h)`, где `h` — это функция `a => FlatMap(g(a), f)`.

Это преобразование позволяет следующему вызову `unsafeRun()` находиться в хвостовой позиции не для вложенной цепочки, 
а для самого внешнего вычисления `y`, что и обеспечивает стекобезопасность. 
Интерпретатор теперь будет сначала рекурсивно обрабатывать `y`, 
и только потом, когда дойдет до его результата, применять к нему продолжение `h`.

### Пример выполнения программы

Рассмотрим конкретный пример:

```dotty
val p = IO(println("A"))
  .flatMap(_ => IO(println("B")))
  .flatMap(_ => IO(println("C")))
```

### Исходная структура

```dotty
FlatMap(
  FlatMap(
    Suspend(() => println("A")),
    _ => Suspend(() => println("B"))
  ),
  _ => Suspend(() => println("C"))
)
```

### После перезаписи

```dotty
FlatMap(
  Suspend(() => println("A")),
  _ => FlatMap(
    Suspend(() => println("B")),
    _ => Suspend(() => println("C"))
  )
)
```

### Шаги выполнения:

1. Начинаем с верхнего уровня:
   ```dotty
   FlatMap(Suspend(() => println("A")), продолжение1)
   ```
2. Выполняем `println("A")`
3. Применяем **продолжение1**:
   ```dotty
   FlatMap(Suspend(() => println("B")), продолжение2)
   ```
4. Выполняем `println("B")`
5. Применяем **продолжение2**:
   ```dotty
   Suspend(() => println("C"))
   ```
6. Выполняем `println("C")`

### Почему это стекобезопасно

Ключевые моменты:

1. Все рекурсивные вызовы `unsafeRun` находятся в хвостовой позиции
2. Глубокие левоассоциативные цепочки `flatMap` переписываются в правоассоциативные
3. Компилятор преобразует хвостовую рекурсию в цикл (не использует стек)

Это позволяет:

- Выполнять бесконечные программы (например, `forever`)
- Обрабатывать глубокие цепочки операций
- Гарантировать отсутствие `StackOverflowError`

### Сравнение с наивной реализацией

**Наивная (не стекобезопасная) реализация**:

```dotty
def unsafeRunNaive(): A =
  self match
    case Return(a)     => a
    case Suspend(r)    => r()
    case FlatMap(x, f) => f(x.unsafeRunNaive()).unsafeRunNaive() // Опасность!
```

Два рекурсивных вызова `unsafeRunNaive` в случае `FlatMap` - не хвостовая рекурсия.

## Принцип батута (Trampolining)

### Основная проблема выполнения программ

На JVM (и в большинстве других сред выполнения) при вызове функций:

1. Каждый вызов добавляет новый **кадр стека** (stack frame), чтобы запомнить, куда вернуться после завершения вызова, 
   чтобы выполнение могло продолжиться.
2. Этот кадр содержит:
    - Параметры функции
    - Локальные переменные
    - Адрес возврата
3. При глубокой рекурсии стек переполняется → `StackOverflowError`

### Как принцип батута решает эту проблему

#### Основная идея

Вместо использования стека вызовов JVM:

1. **Программа представляется как данные** (алгебраический тип `IO`)
2. **Интерпретатор (`unsafeRun`)** последовательно выполняет шаги
3. **Управление явно передается** между программой и интерпретатором

#### Аналогия с батутом

1. **Программа** - это прыгун на батуте
    - Делает "прыжок" (выполняет один шаг)
    - Возвращает управление "батуту" (интерпретатору)
2. **Интерпретатор** - это сам батут
    - Получает контроль после каждого прыжка
    - Решает, что делать дальше

#### Детализированный процесс

1. **Программа инициирует шаг**:
    - Вариант 1: возвращает `Suspend(effect)` или `Return(value)` - нужно выполнить эффект или вернуть вычисленное значение
    - Вариант 2: возвращает `FlatMap(sub, continuation)` - нужно выполнить подпрограмму

2. **Интерпретатор получает контроль**:
    - Вариант 1: выполняет эффект (для `Suspend`) или возвращает значение (для `Return`)
    - Вариант 2: анализирует подпрограмму (для `FlatMap`)

3. **Программа получает результат**:
    - Для `Suspend` и `Return` - значение результата эффекта или вычисленное значение
    - Для `FlatMap` - результат подпрограммы

4. **Цикл повторяется**:
    - Программа решает, что делать дальше
    - Возвращает новую инструкцию интерпретатору

### Заключение

Таким образом, наша `IO` программа является своего рода сопрограммой, которая выполняется совместно с `unsafeRun`.
Она постоянно делает запросы `Suspend` или `FlatMap`, и каждый раз, когда она это делает,
то приостанавливает собственное выполнение и возвращает управление `unsafeRun`.
И это на самом деле `unsafeRun` движет выполнением программы вперед, по одной такой приостановке за раз.

Функция типа `unsafeRun` часто называется _батут_,
а общая методика возврата управления к одному циклу для устранения стека называется _прыжки на батуте_.

Подход "прыжков на батуте" решает фундаментальную проблему стековой безопасности в функциональных программах через:

1. **Явное представление** потока управления в виде данных
2. **Интерпретатор с хвостовой рекурсией**, который последовательно выполняет шаги
3. **Перезапись левоассоциативных цепочек** в правоассоциативные

Это позволяет без риска переполнения стека выполнять:

- Бесконечные рекурсии
- Глубокие цепочки операций
- Сложные комбинации эффектов

## Общее решение проблемы переполнения стека

Функция `resume` в `IO` необязательно должна выполнять побочные эффекты.
Тип `IO` на самом деле является общей структурой данных для трамплинных вычислений —
даже чистых вычислений, которые вообще не выполняют никаких операций ввода-вывода!

В традиционном программировании при вызове функций каждый новый вызов добавляет новый уровень в стек вызовов. 
Когда таких вызовов становится слишком много (например, при глубокой рекурсии), 
происходит переполнение стека (StackOverflowError).

**Пример проблемы:**

```dotty
val f = (x: Int) => x  // Простая функция-тождество

// Создаем композицию 100.000 функций
val g = List.fill(100000)(f).foldLeft(f)(_ compose _)

g(42)  // Вызывает StackOverflowError
```

Здесь мы строим цепочку из 100.000 вложенных вызовов функций, что превышает размер стека.

### Решение через Trampoline (TailRec)

#### Основная идея

Мы можем избежать переполнения стека, преобразовав:

- Обычные вызовы функций → в **структуру данных**
- Рекурсию → в **последовательность шагов**, обрабатываемых интерпретатором

Но это на самом деле не концепция для ввода-вывода, а концепция для устранения стека вызовов!

Давайте изменим имя `IO` на `TailRec`, чтобы отразить это:

```dotty
enum TailRec[A]:
  // Чистое значение
  case Return(a: A)

  // Отложенное вычисление (может содержать эффект)
  case Suspend(resume: () => A)

  // Композиция вычислений
  case FlatMap[B, C](sub: TailRec[B], k: B => TailRec[C]) extends TailRec[C]

  def flatMap[B](f: A => TailRec[B]): TailRec[B] =
    FlatMap(this, f)

  def map[B](f: A => B): TailRec[B] =
    flatMap(a => Return(f(a)))

  // Переименовали функцию запуска в run, 
  // поскольку она больше не используется для захвата эффектов.
  @annotation.tailrec
  final def run: A = this match
    case Return(a)  => a   // Базовый случай
    case Suspend(r) => r() // Выполняем вычисление
    case FlatMap(x, f) => x match
        case Return(a)  => f(a).run   // Продолжаем с результатом
        case Suspend(r) => f(r()).run // Выполняем и продолжаем
        case FlatMap(y, g) =>
          y.flatMap(a => g(a).flatMap(f)).run // Переписываем цепочку
```

#### Как это работает?

1. **Преобразуем функции**:
   Вместо `A => B` используем `A => TailRec[B]`

2. **Композиция через flatMap**:
   ```dotty
   val f: Int => TailRec[Int] = x => Return(x)
   val g: Int => TailRec[Int] = x => Suspend(() => f(x))
   ```

3. **Пример безопасной композиции**:
   ```dotty
   val safeCompose: (Int => TailRec[Int]) => 
                    (Int => TailRec[Int]) => 
                    Int => TailRec[Int] = 
     f => g => x => Suspend(() => f(x).flatMap(g))
   ```

4. **Выполнение через run**:
   Интерпретатор обрабатывает структуру данных без роста стека

### Практический пример

#### Проблемный код (со стеком)

```dotty
def factorial(n: BigInt): BigInt =
  if n <= 1 then 1
  else n * factorial(n - 1) // Рекурсия -> растет стек

factorial(100_000) // StackOverflowError
```

#### Безопасная версия (с TailRec)

```dotty
def factorial(n: BigInt): TailRec[BigInt] =
  if n <= 1 then Return(1)
  else
    Suspend(() => factorial(n - 1)).flatMap: r =>
      r.flatMap(m => Return(n * m))

// Использование
factorial(100000).run // Работает без StackOverflow
```

### Ключевые преимущества

1. **Стекобезопасность**:
    - Можно делать глубокие рекурсии
    - Нет риска StackOverflowError

2. **Чистота вычислений**:
    - Может работать без побочных эффектов
    - Подходит для чисто функциональных вычислений

3. **Гибкость**:
    - Можно комбинировать с эффектами
    - Поддерживает сложные сценарии композиции

### Производительность и компромиссы

#### Замедление

- Каждый шаг требует обработки структуры данных
- Дополнительные аллокации объектов
- В среднем в 10-100 раз медленнее прямых вызовов

#### Когда использовать

1. **Глубокая рекурсия** (обычно > 1000 уровней)
2. **Композиция многих функций**
3. **Гарантированное выполнение** без переполнения стека

### Вывод

Тип `TailRec` предоставляет общее решение для:

- Устранения стека вызовов
- Безопасной композиции функций
- Контроля над выполнением программ

Это фундаментальная техника в функциональном программировании 
для обеспечения надежности выполнения программ с предсказуемым использованием памяти.

## `TailRec` в стандартной библиотеке

Определенный здесь тип `TailRec` встроен в стандартную библиотеку Scala в объекте `scala.util.control.TailCalls`. 
Объект определяет тип `TailRec[A]`, а также конструкторы `done` и `tailcall`, 
которые соответствуют `Return` и `Suspend`. 

Тип `TailRec` содержит метод `result`, который интерпретирует значение `TailRec[A]` в значение `A`. 

Вот тот же пример, использующий `TailCalls` вместо `TailRec`:

```dotty
import scala.util.control.TailCalls.*

def factorial(n: BigInt): TailRec[BigInt] =
  if n <= 1 then done(1)
  else tailcall(factorial(n - 1)).flatMap(r => done(n * r))

// Использование
factorial(100000).result // Работает без StackOverflow
// val res0: BigInt = 28242294079603478742934215780245355184...
```

def fibonacci(n: Int): TailRec[BigInt] =

@:note(🔍 Показать решение)

Это решение вычисляет N-е число Фибоначчи через хвостовую рекурсию с использованием `TailRec` 
для избежания переполнения стека. 
Внутренняя функция `loop` последовательно накапливает значения (a, b), 
где каждое следующее число равно сумме двух предыдущих, пока не достигнет N-го шага. 
Базовый случай (n ≤ 1) возвращает `n`, а для остальных случаев запускается `loop` с начальными значениями 0 и 1. 
Использование `tailcall` гарантирует стекобезопасность даже для очень больших N.

```dotty
def fibonacci(n: Int): TailRec[BigInt] =
  def loop(a: BigInt, b: BigInt, step: Int): TailRec[BigInt] =
    if step >= n then done(a)
    else tailcall(loop(b, a + b, step + 1))

  if n <= 1 then done(n)
  else loop(0, 1, 0)
```

@:note(🔍 Показать решение)

Это решение вычисляет сумму факториалов двух чисел через стекобезопасную рекурсию с использованием `TailRec`. 
Функция `factorial` считает факториал числа через хвостовую рекурсию

а `sumFactorials` комбинирует два факториала через for-нотацию, вызывая их через `tailcall` и складывая результаты.

```dotty
def factorial(n: BigInt): TailRec[BigInt] =
  if n <= 1 then done(1)
  else tailcall(factorial(n - 1)).flatMap(r => done(n * r))
  
def sumFactorials(a: Int, b: Int): TailRec[BigInt] =
  for
    fa <- tailcall(factorial(a))
    fb <- tailcall(factorial(b))
  yield fa + fb
```

**Задание:**

Реализуйте две взаимно рекурсивные функции (например, проверку чётности/нечётности), 
которые не падают с `StackOverflowError`.

```dotty
def isEven(n: Int): TailRec[Boolean] =
  ??? // Для 0 возвращает true, для остальных n вызывает isOdd для n-1

def isOdd(n: Int): TailRec[Boolean] =
  ??? // Для 0 возвращает false, для остальных n вызывает isEven для n-1
```

**Примеры:**

```dotty
isEven(100001).result // Должно вернуть false
```

@:note(🔍 Показать решение)

Это решение реализует взаимную рекурсию для проверки чётности чисел через `TailRec`, избегая переполнения стека. 
Функции `isEven` и `isOdd` вызывают друг друга, уменьшая `n` до базового случая (`n == 0`), 
где возвращают `true` для чётности и `false` для нечётности. 
Использование `tailcall` делает вызовы стекобезопасными, 
преобразуя взаимную рекурсию в последовательность хвостовых вызовов, 
что позволяет корректно работать даже с большими числами.

```dotty
def isEven(n: Int): TailRec[Boolean] =
  if n == 0 then done(true)
  else tailcall(isOdd(n - 1))

def isOdd(n: Int): TailRec[Boolean] =
  if n == 0 then done(false)
  else tailcall(isEven(n - 1))
```
