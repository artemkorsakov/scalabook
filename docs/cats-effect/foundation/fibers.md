# Волокна

## Введение

Cats Effect — это библиотека для функционального программирования с эффектами в Scala, 
которая вводит ряд мощных концепций для работы с асинхронностью, одновременностью и побочными эффектами. 
Эти концепции, будучи простыми и элегантными по отдельности, могут показаться необычными для разработчиков, 
привыкших к традиционным подходам (потоки Java, `Future`, `Promise` и т.д.). 
Более того, Cats Effect использует свою собственную терминологию, 
которая может отличаться от терминов, используемых в других фреймворках.

Цель этой документации — дать высокоуровневое понимание среды выполнения Cats Effect, 
познакомить с ключевыми концепциями и терминологией, которые будут использоваться в дальнейших обсуждениях.

## Волокна (Fibers) — сердце Cats Effect

### Что такое волокна?

**Волокна (fibers)** — это фундаментальная абстракция Cats Effect. 
Термин выбран намеренно, чтобы напомнить о **потоках (threads)**, 
поскольку волокна — это по сути **облегчённые потоки** (их также называют «зелёными потоками» или «корутинами»).

Подобно обычным потокам ОС (Java `Thread`), волокна представляют собой последовательность действий, 
которые выполняются в заданном порядке. Однако между ними есть критические различия:

| Характеристика | Потоки ОС                       | Волокна Cats Effect                       |
|----------------|---------------------------------|-------------------------------------------|
| Вес            | Тяжёлые (~1 МБ на поток)        | Сверхлёгкие (~150 байт на волокно)        |
| Создание       | Дорогое, ограниченное ОС        | Дешёвое, можно миллионы                   |
| Переключение   | Через планировщик ОС            | Внутри JVM, быстрее                       |
| Асинхронность  | Блокирующие вызовы              | Неблокирующие, на основе обратных вызовов |
| Отмена         | Через `interrupt` (небезопасно) | Кооперативная, безопасная, с гарантиями   |

### Почему "лёгкость" — это важно?

Из-за своей лёгкости вы можете создавать **десятки миллионов волокон** в одном процессе, 
и основным ограничением будет только доступная память. 
Это открывает новые архитектурные возможности:

- **Каждый запрос — волокно**: Типичное клиент-серверное приложение на Cats Effect создаёт новое волокно 
  для каждого входящего запроса, подобно тому, как классический Java-сервер на `ServerSocket` создаёт поток на запрос. 
  Но в отличие от потоков, создание волокна настолько дёшево, 
  что вы можете создавать даже **очень короткоживущие** волокна для микро-задач.
- **Волокна без явного параллелизма**: Многие функции Cats Effect (например, мемоизация) используют волокна внутри себя, 
  даже если снаружи это не выглядит как конкурентный код.

### Асинхронность первого класса

Волокна Cats Effect имеют **первоклассную поддержку асинхронных обратных вызовов**. 
Что это означает на практике?

В традиционном программировании есть два вида операций:

- **Синхронные**: выполняются сразу, возвращают результат или ошибку.
- **Асинхронные**: регистрируют обратный вызов, который будет вызван позже (например, чтение из сети, таймер).

В Cats Effect **нет принципиальной разницы** между этими двумя типами с точки зрения композиции. 
И синхронный, и асинхронный шаг — это просто «шаг волокна». 
Вы можете писать бизнес-логику, которая проходит через асинхронные вызовы, так же естественно, как и синхронные.

> **Ключевая идея**: В мире волокон Cats Effect **нет разницы между обратным вызовом и возвратом**. 
> Всё — просто последовательность эффектов.

### Как определяются волокна?

Каждый шаг волокна — это **эффект** (значение типа `IO[_]`). 
Шаги компонуются последовательно с помощью метода `flatMap` (или синтаксического сахара for-comprehension):

```dotty
import cats.effect.*

// Явный flatMap
IO.println("Hello").flatMap: _ =>
  IO.println("World")

// for-comprehension (синтаксический сахар)
for
  _ <- IO.println("Hello")
  _ <- IO.println("World")
yield ()
```

Обратите внимание: `flatMap` — это обычный метод, такой же, как `map`, `filter` и т.д. 
Благодаря этому мы можем создавать удобные операторы для распространённых паттернов. 
Например, оператор `*>` (или `>>`) игнорирует результат первого эффекта и возвращает второй:

```dotty
IO.println("Hello") *> IO.println("World")
IO.println("Hello") >> IO.println("World")  // синоним
```

### Главное волокно (Main Fiber)

Каждое приложение Cats Effect имеет **главное волокно** — точку входа, с которой начинается выполнение. 
Это аналог метода `main` в обычной Scala/Java программе. 
Главное волокно определяется в объекте, наследующем `IOApp`:

```dotty
object Hi extends IOApp.Simple:
  val run: IO[Unit] = IO.println("Hello") *> IO.println("World")
```

Когда приложение запускается, создаётся главное волокно, которое выполняет эффект `run`. 
После его завершения процесс заканчивается.

### Родительские и дочерние волокна

Когда одно волокно запускает другое (через `.start`), первое называется **родителем**, второе — **дочерним**. 
Важные свойства этих отношений:

- **Не строгая иерархия**: Родитель может завершиться раньше дочернего — это нормально.
- **Отслеживание ошибок**: Родитель может отслеживать ошибки дочернего волокна через `.join` и обрабатывать их (как `try/catch`).
- **Отмена**: Родитель может отменить дочернее волокно через `.cancel`.
- **Невозможность восстановиться после отмены**: Волокно, которое было отменено, 
  не может продолжить выполнение — только выполнить финализаторы (освобождение ресурсов) и завершиться.

## Отмена (Cancellation) — контролируемое прерывание

### Зачем нужна отмена?

По умолчанию **выполнение любого волокна может быть отменено в любой момент**. Это позволяет:

- **Тайм-ауты**: Прерывать долгие операции.
- **Гонки (race)**: Как только один участник гонки победил, остальные отменяются.
- **Ошибки в параллельных вычислениях**: Если одно из параллельных вычислений упало с ошибкой, остальные отменяются.
- **Остановка сервера**: При безопасном завершении (graceful shutdown) все обрабатываемые запросы получают сигнал отмены.

### Пример: тайм-аут

```dotty
import scala.concurrent.duration.*

lazy val loop: IO[Unit] = IO.println("Hello, World!") >> loop

loop.timeout(5.seconds)  // => IO[Unit]
```

Что здесь происходит:

1. Создаётся волокно, которое бесконечно выводит "Hello, World!".
2. Метод `timeout(5.seconds)` запускает это волокно и одновременно запускает таймер на 5 секунд.
3. Через 5 секунд таймер вызывает `.cancel` для волокна `loop`.
4. Волокно `loop` получает сигнал отмены, завершается, освобождая ресурсы.
5. Внешнее `IO` завершается (с результатом `Unit` или ошибкой, если тайм-аут был критическим).

### Отмена vs Thread.interrupt

Если вы знакомы с Java-потоками, вы можете провести параллель с `Thread.interrupt()`. 
Но есть **три важных отличия**, которые делают отмену в Cats Effect безопаснее и надёжнее:

| Аспект              | Java Thread.interrupt                              | Cats Effect Cancellation                             |
|---------------------|----------------------------------------------------|------------------------------------------------------|
| **Кооперативность** | Мгновенный возврат, даже если поток не прерван     | Асинхронное ожидание, пока отмена станет возможной   |
| **Подавление**      | Невозможно (можно проверить флаг, но не отключить) | Можно через `IO.uncancelable` для критических секций |
| **Детализация**     | Проверяется только в блокирующих вызовах           | Проверяется **между каждым оператором** `flatMap`    |

Рассмотрим каждое отличие подробнее.

#### 1. Кооперативная отмена

Когда один поток вызывает `.cancel` для другого, это **запрос**, а не приказ. 
Если целевое волокно в данный момент не может быть отменено (например, находится в критической секции), 
отменяющий поток будет **асинхронно ждать**, пока отмена станет возможной. 
Как только отмена начинается, целевое волокно выполняет все свои финализаторы (освобождает файлы, соединения и т.д.) 
и только после этого передаёт управление обратно.

В Java `interrupt()` возвращает управление немедленно, даже если целевой поток игнорирует прерывания. 
Это приводит к состоянию гонки и утечкам ресурсов.

#### 2. Подавление отмены через uncancelable

Бывают ситуации, когда несколько действий должны выполниться **атомарно** — либо все, либо ни одного. 
Например, выделение ресурса и его регистрация в пуле. 
Если отмена произойдёт «посередине», ресурс может утечь.

Cats Effect предоставляет `IO.uncancelable { poll => ... }` — область, 
внутри которой сигнал отмены **маскируется** (откладывается) до выхода из блока:

```dotty
import cats.effect.IO

val criticalSection: IO[Resource] = IO.uncancelable { poll =>
  for
    resource <- allocateResource()
    // poll(resource.register()) - здесь отмена разрешена, если нужно
    _ <- poll(registerInPool(resource))
  yield resource
}
```

- Внутри `uncancelable` сигнал отмены **не теряется**, а откладывается.
- Если внутри нужна точка отмены (например, долгая операция), можно обернуть её в `poll(...)`.
- Это значительно безопаснее, чем `synchronized` или атомарные флаги в Java.

#### 3. Высокая детализация отмены

В Cats Effect **каждый шаг волокна** (каждый оператор `flatMap`) содержит **проверку отмены**. 
Это означает, что даже бесконечный цикл без блокировок может быть отменён:

```dotty
// Бесконечный цикл без блокировок
lazy val busyLoop: IO[Unit] = IO.unit >> busyLoop

// Но он всё равно может быть отменён!
busyLoop.timeout(1.second)
```

В Java `Thread.interrupt()` не проверяется в обычных вычислениях — только в методах, которые бросают `InterruptedException`. 
Бесконечный цикл `while(true) {}` невозможно прервать извне.

Благодаря такой детализации отмена в Cats Effect работает **предсказуемо и надёжно** даже в самых сложных сценариях.

## Практические примеры и паттерны

### Пример 1: Запуск дочернего волокна

```dotty
import cats.effect.*
import scala.concurrent.duration.*

object Main extends IOApp.Simple:
  val run: IO[Unit] =
    for
      // Запускаем дочернее волокно, которое "тикает" каждую секунду
      ticker <- (IO.sleep(1.second) *> IO.println("Tick")).foreverM.start

      // Ждём 5 секунд
      _ <- IO.sleep(5.seconds)

      // Отменяем тикер
      _ <- ticker.cancel

      _ <- IO.println("Ticker stopped")
    yield ()
```

Вывод:

```
Tick
Tick
Tick
Tick
Ticker stopped
```

### Пример 2: Гонка (race) с автоматической отменой

```dotty
import cats.effect.*
import scala.concurrent.duration.*

object Main extends IOApp.Simple:
  val run: IO[Unit] =
    val task1 = IO.sleep(2.seconds) *> IO.println("Task 1 done")
    val task2 = IO.sleep(1.seconds) *> IO.println("Task 2 done")

    IO.race(task1, task2).flatMap:
      case Left(value)  => IO.println("Task 1 won")
      case Right(value) => IO.println("Task 2 won")
      
// Вывод: Task 2 done, затем Task 1 отменяется, и вывод "Task 2 won"
```

### Пример 3: Атомарная операция с uncancelable

```dotty
import cats.effect.{IO, Ref}

def transferMoney(
    from: Ref[IO, Int],
    to: Ref[IO, Int],
    amount: Int
): IO[Unit] =
  IO.uncancelable: poll =>
    for
      balance <- from.get
      _ <- IO.raiseWhen(balance < amount)(new Exception("Insufficient funds"))
      // Здесь мы разрешаем отмену, потому что это долгая операция
      _ <- poll(from.update(_ - amount))
      _ <- poll(to.update(_ + amount))
    yield ()
```

В этом примере проверка баланса и обновление счетов защищены от отмены, 
но сами обновления (которые могут быть долгими) могут быть отменены.

## Терминологический словарь

| Термин           | Описание                                                                                 |
|------------------|------------------------------------------------------------------------------------------|
| **Fiber**        | Легковесный поток (~150 байт), основная единица выполнения                               |
| **Effect**       | Описание вычисления с эффектами (тип `IO[_]`)                                            |
| **Cancelation**  | Механизм безопасного прерывания волокна с освобождением ресурсов                         |
| **Uncancelable** | Область, где отмена откладывается до выхода                                              |
| **Poll**         | Функция внутри `uncancelable`, разрешающая отмену в точке вызова                         |
| **Main Fiber**   | Главное волокно, точка входа приложения                                                  |
| **Parent/Child** | Отношения между волокнами при запуске через `.start`                                     |
| **Finalizer**    | Действие, выполняемое при отмене или завершении волокна (например, освобождение ресурса) |

## Резюме

1. **Волокна** — это сверхлёгкие потоки (~150 байт), позволяющие создавать миллионы конкурентных задач.
2. **Асинхронность** — первоклассная концепция; нет разницы между синхронными и асинхронными шагами.
3. **Композиция** — через `flatMap`, for-comprehension и операторы (`*>` и др.).
4. **Отмена** — кооперативная, с гарантиями, с возможностью подавления через `uncancelable`.
5. **Безопасность** — проверка отмены на каждом шаге, автоматическое выполнение финализаторов.
6. **Иерархия** — родительские и дочерние волокна, возможность отслеживания и отмены.

Эти концепции делают Cats Effect одной из самых мощных и безопасных платформ 
для одновременного и асинхронного программирования на JVM.
