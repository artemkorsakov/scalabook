## Глава 1. Фундаментальные концепции

### 1.1 Фунциональное программирование

#### 1.1.1 Сессии и скрипты

Некоторые определения:

```dotty
def square(x: Int): Int = x * x
def min(a: Int, b: Int): Int = if a < b then a else b
```

Важные моменты:

1. Скрипты представляют собой наборы определений, предоставленных программистом.
2. Определения выражаются в виде уравнений между определенными видами выражений и описывают математические функции.
3. Во время выполнения выражения отправляются на вычисление; эти выражения могут содержать ссылки на функции, определенные в скрипте.

##### Упражнение 1.1.1.

```dotty
def quad(x:Int): Int = square(square(x))
quad(2) // 16
```

### 1.2 Выражения и значения

Понятие выражения является центральным в функциональном программировании. 
Существует множество видов математических выражений, не все из которых разрешены в нотации, которую мы опишем, 
но все они обладают определенными общими характеристиками. 
Наиболее важной особенностью математической нотации является то, что выражение используется исключительно для описания (или _обозначения_) _значения_. 
Другими словами, смысл выражения является его значением, и нет никаких других эффектов, скрытых или иных, в любой процедуре его фактического получения. 
Более того, значение выражения зависит только от значений его составляющих выражений (если таковые имеются), 
и эти подвыражения могут быть свободно заменены другими, имеющими то же значение. 
Выражение может содержать определенные «имена», которые обозначают неизвестные величины, 
но в математической нотации обычно предполагается, что различные вхождения одного и того же имени 
относятся к одной и той же неизвестной величине (в пределах очевидных синтаксических ограничений). 
Такие имена обычно называются «переменными», но каждый математик понимает, что переменные не меняются: 
они всегда обозначают одну и ту же величину, при условии, что мы остаемся в том же контексте определений, связанных с ними. 
Характерное свойство математических выражений, описанное здесь, называется _ссылочной прозрачностью_.

#### 1.2.1 Редукция

Компьютер оценивает выражение, сводя его к «простейшей эквивалентной форме» и печатая результат. 
Термины «оценка» (_evaluation_), «упрощение» (_simplification_) и «сокращение» (_reduction_) будут использоваться взаимозаменяемо для описания этого процесса. 
Мы можем кратко ощутить суть сокращения, рассмотрев вычисление выражения `square(3 + 4)`. 
Предположим, что мы позволяем знаку `=>` означать «сводится к».

Одна из возможных последовательностей редукции выглядит следующим образом: `square(3 + 4) => square(7) => 7 * 7 => 49`.
Выражение `49` не может быть сокращено дальше.
Однако существует другая возможная последовательность сокращения: `square(3 + 4) => (3 + 4) * (3 + 4) => 7 * (3 + 4) => 7 * 7 => 49`.
Мы будем говорить, что выражение является _каноническим_ (или _в нормальной форме_), если его нельзя далее сократить.

##### Упражнение 1.2.1 

> Подсчитайте количество различных способов, которыми: `square(square(3 + 7))` можно привести к нормальной форме.

Есть два способа резукции: вычислить аргумент или выполнить функцию, а здесь - три выражения. 
Это означает, что всего \\(2^3 = 8\\) способов приведения к нормальной форме.

##### Упражнение 1.2.2

> Рассмотрим определение: `three x = 3`. Сколькими способами можно привести `three (3 + 4)` к нормальной форме?

##### Упражнение 1.2.3

> Представьте себе язык выражений для представления целых чисел, определяемый правилами синтаксиса: 
> (i) `zero` — это выражение; (ii) если `e` — это выражение, то также являются выражениями `(succ e)` и `(pred e)`. 
> Разработчик сокращает выражения на этом языке, многократно применяя следующие правила до тех пор, 
> пока это возможно:
>
> - succ1: `(succ(pred e)) => e`  
> - pred1: `(pred(succ e)) => e`
>
> Упростите выражение `(succ(pred(succ(pred(pred zero)))))`.

Алгоритм упрощения:

1. ищем первую последовательность `succ -> pred` или `pred -> succ`
2. если такой последовательности нет, то редукция завершена
3. если последовательность  `succ -> pred` или  `succ -> pred` найдена, то сокращаем её
4. возвращаемся в пункт 1

Результат упрощения:

`(succ(pred(succ(pred(pred zero))))) => (succ(pred(pred zero))) => pred zero`

Реализация алгоритма:

```dotty
enum Expr:
  self =>

  case Zero
  case Succ(expr: Expr)
  case Pred(expr: Expr)

  def normalize: Expr =
    self match
      case Succ(Pred(e)) => e.normalize
      case Pred(Succ(e)) => e.normalize
      case Succ(e)       => Succ(e.normalize)
      case Pred(e)       => Pred(e.normalize)
      case _             => self

import Expr.*
val expr = Succ(Pred(Succ(Pred(Pred(Zero)))))
expr.normalize // Pred(Zero)
```

> Сколькими способами можно применить правила редукции к этому выражению? 
> Все ли они приводят к одному и тому же конечному результату? 

Правила редукции можно применять тремя способами:

1. Сокращать первый найденный `succ1` или `pred1` и так по кругу.
2. Вначале сократить все `succ1`, потом - все `pred1`.
3. Вначале сократить все `pred1`, а затем - все `succ1`.

Да, все приводят к одному и тому же результату.

> Докажите, что процесс редукции должен завершиться для всех данных выражений. 
> (Подсказка: определите соответствующее понятие размера выражения и покажите, что редукция действительно уменьшает размер.)

Размер выражения можно определить по алгоритму:

- если выражение равно `zero`, то размер равен 0
- в ином случае, размер выражения на 1 больше размера выражения, которое находится внутри `succ` или `pred`

```dotty
def size: Int =
  self match
    case Zero    => 0
    case Succ(e) => 1 + e.size
    case Pred(e) => 1 + e.size    
```

Редукция конечна, т.к. при любом сокращении размер выражения уменьшается на 2.
А это означает, что рано или поздно либо сокращение невозможно, либо выражение становится равным `zero`. 

> Предположим, что в язык добавлено дополнительное синтаксическое правило: 
> (iii) если `el` и `ez` являются выражениями, то также является выражением `(add el e2)`. 
> Соответствующие правила редукции:
> 
> - add1: `(add zero ez) => ez`
> - add2: `(add (succ el) e2) => (succ (add el ez))`
> - add3: `(add (pred el) ez) => (pred (add el e2))`
> 
> Упростите выражение: `(add (succ (pred zero)) zero)`.
> 
> Подсчитайте количество различных способов применения правил редукции к приведенному выше выражению. 
> Всегда ли они приводят к одному и тому же конечному результату? 
> Докажите, что процесс редукции всегда должен заканчиваться для любого заданного начального выражения. 
> (Подсказка: Расширьте понятие размера выражения.)

Расширим определение выражения, добавив операцию сложения, правила сокращения и доработав размер:

```dotty
enum Expr:
  self =>

  case Zero
  case Succ(expr: Expr)
  case Pred(expr: Expr)
  case Add(expr1: Expr, expr2: Expr)

  def normalize: Expr =
    self match
      case Succ(Pred(e))     => e.normalize
      case Pred(Succ(e))     => e.normalize
      case Succ(e)           => Succ(e.normalize)
      case Pred(e)           => Pred(e.normalize)
      case Add(Zero, expr2)  => expr2
      case Add(Succ(e1), e2) => Succ(Add(e1, e2))
      case Add(Pred(e1), e2) => Pred(Add(e1, e2))
      case _                 => self

  def size: Int =
    self match
      case Zero        => 0
      case Succ(e)     => 1 + e.size
      case Pred(e)     => 1 + e.size
      case Add(e1, e2) => 1 + e1.size + e2.size
end Expr
```

Теперь мы можем упростить выражение `(add(succ(pred zero)) zero`:

`(add(succ(pred zero)) zero => (succ(add(pred zero) zero) => (succ(pred(add zero zero)) => (succ(pred zero)) => zero`.

Сокращение всегда приводит к одному и тому же результату, т.к. сдвиг вправо `Add` конечен и доходит до того момента,
когда левый аргумент равен `Zero`, а значит, после применения правила add1, 
размер выражения уменьшается на 2 и вычеркивается само выражение `Add`.
Таким образом из исходного выражения можно вычеркнуть все `Add` и получить выражение из предыдущего пункта, которое сократимо.

### 1.3 Типы

Область значений разделена на организованные коллекции, называемые _типами_. 
Типы можно разделить на два вида. 
Во-первых, есть базовые типы, значения которых заданы как примитивные. 
Например, числа составляют базовый тип (типы `Byte`, `Short`, `Int`, `Long`), как и истинностные значения (тип `Boolean`) и символы (тип `Char`). 
Во-вторых, есть _составные_ (или _производные_) типы, значения которых построены из значений других типов.
Примеры производных типов включают: `(Int, Char)`, тип пар значений, первый компонент которых является числом, а второй — символом; 
`(Int => Int)`, тип функций из чисел в числа; и `(Char)`, тип списков символов. 
Каждый тип связан с определенными операциями, которые не имеют смысла для других типов. 
Например, нельзя разумно сложить число с символом или умножить две функции вместе.

Важный принцип нотации, которую мы собираемся описать, заключается в том, 
что каждому правильно сформированному выражению может быть назначен тип, 
который может быть выведен только из составляющих выражения. 
Другими словами, как значение выражения зависит только от значений его компонентных выражений, так же зависит и его тип. 
Этот принцип называется _строгой типизацией_.

Главным следствием дисциплины, налагаемой строгой типизацией, является то, 
что любое выражение, которому нельзя присвоить «разумный» тип, считается неправильно сформированным 
и отклоняется компьютером до выполнения кода. 
Такие выражения не имеют никакой ценности: они просто считаются недопустимыми.

Вот пример скрипта, содержащего определение, которому нельзя присвоить осмысленный тип:

- _ay_ x 'A'
- _bee_ x x + _ay_ x

Выражение `'A'` в этом скрипте обозначает символ `A`. Для любого `x` значение `ay x` равно `'A'` и, следовательно, имеет тип `Char`. 
Поскольку `+` зарезервировано для обозначения операции числового сложения, 
правая часть определения `bee` не является правильно типизированной: нельзя складывать символы численно. 
Из этого следует, что функция `bee` не обладает осмысленным типом, и скрипт отклоняется компьютером. 

Существует два этапа анализа, когда выражение отправляется на выполнение. 
Сначала выражение проверяется, соответствует ли оно правильному синтаксису, установленному для выражений. 
Если это не так, компьютер сигнализирует об ошибке синтаксиса. 
Этот этап называется _синтаксическим анализом_. 
Если этот этап успешен, то выражение анализируется, чтобы увидеть, обладает ли оно разумным типом. 
Этот этап называется _анализом типа_. 
Если выражение не проходит этот этап, компьютер сигнализирует об ошибке типа. 
Только если выражение проходит оба этапа, может начаться процесс выполнения. 
Аналогичные замечания применимы к определениям до того, как сценарий будет принят.

Строгая типизация важна, поскольку соблюдение дисциплины может помочь в разработке четких и хорошо структурированных программ. 
Более того, широкий спектр логических ошибок может быть обнаружен любым компьютером, который ее применяет.

### 1.4 Функции и определения

Самым важным видом понятия в функциональном программировании является понятие _функции_. 
Математически говоря, функция `f` — это правило соответствия, 
которое связывает с каждым элементом заданного типа `A` уникальный элемент второго типа `B`. 
Тип `A` называется _исходным типом_, а `B` — _целевым типом_ функции. 
Выразим эту информацию следующим образом: `def f: A => B`.

Эта формула утверждает, что тип `f` — это `A => B`. 
Другими словами, выражение типа `A => B` обозначает тип всякий раз, когда типами являются `A` и `B`, 
и описывает тип функций из `A` в `B`.

Говорят, что функция `def f: A => B` принимает аргументы из `A` и возвращает результаты в `B`. 
Если `x` обозначает элемент `A`, то мы пишем `f(x)` или просто `f x`, чтобы обозначить результат применения функции `f` к `x`. 
Это значение является уникальным элементом `B`, связанным с `x` по правилу соответствия для `f`. 

В функциональном программировании функции являются значениями с точно таким же статусом, как и все другие значения; 
в частности, они могут передаваться в качестве аргументов функциям и возвращаться в качестве результатов. 

Важно помнить о различии между значением функции и конкретным его определением. 
Существует множество возможных определений для одной и той же функции. 
Например, мы можем определить функцию, которая удваивает свой аргумент, следующими двумя способами:

- `double(x: Int) = x + x`
- `double2(x: Int) = 2 * x`

Два определения описывают разные процедуры получения соответствия, 
но `double` и `double'` обозначают одну и ту же функцию, и мы можем утверждать `double = double'` как математическую истину. 

#### 1.4.1 Информация о типе

При определении функций в скрипте допускается включение информации о типе функции. 
Например, мы можем определить функцию `square` в скрипте, написав:

```dotty
def square: Int => Int = x => x * x
```

Хотя часто бывает хорошей практикой включать типы, определения функций не обязательно должны сопровождаться их объявлениями. 
Тип функции можно вывести из определяющего её уравнения. 
Это пример дисциплины строгой типизации, упомянутой в предыдущем разделе. 
Оператор `*` зарезервирован исключительно для умножения числовых величин, 
поэтому назначение типа `def square: Int => Int = x => x * x` можно вывести механически.

Некоторые функции имеют очень общие исходные и целевые типы. 
Рассмотрим следующее определение: `def id = x => x`.
Это уравнение определяет функцию тождества: оно отображает каждый элемент исходного типа на себя. 
Таким образом, его тип `A => A` для некоторого подходящего типа `A`.
Но каждый тип `A` подходит, поскольку в определении `id` не требуется никаких конкретных свойств элементов `A`. 
Проблема придания `id` разумного типа решается введением _переменных типа_. 
Тип, присваиваемый `id`, — это \\(\lambda \to \lambda\\): `def id[A]: A => A = x => x`.
Здесь \\(\lambda\\) обозначает переменную типа. 
Для обозначения переменных типа обычно используются греческие буквы \\(\alpha, \beta, \gamma\\) и так далее. 
Как и другие виды переменных, переменная типа может быть инстанциирована для различных типов в различных обстоятельствах. 
Например, выражение `id(3)` является правильно сформированным и имеет тип `Int`, 
потому что \\(\lambda\\) может быть заменен на `Int` в типе `id`, что даст версию `Int => Int`. 
Аналогично, выражение `id(square)` является правильно сформированным и имеет тип `Int => Int`, 
потому что `Int => Int` (тип функции `square`) может быть заменен на \\(\lambda\\), что даст версию `(Int => Int) => (Int => Int)`. 
Наконец, выражение `id(id)` также является правильно сформированным, 
потому что тип \\(\lambda \to \lambda\\) сам по себе может быть заменен на \\(\lambda\\). 
Таким образом, тип `id(id)` - \\(\lambda \to \lambda\\). 
И, конечно, получим `id(id) = id`. 

Вот еще один пример допустимого определения, связанный тип которого содержит переменные. 
Вспомним определение функции `ay` из предыдущего раздела: `def ay[T](x: T) = 'A'`.
Тип, связанный с `ay`, — это `T => Char`. 
Исходный тип `ay` может быть любым типом.
Теперь есть зачатки языка выражений, обозначающих типы. 
Этот язык содержит константные выражения, такие как `Int` или `Char`, 
переменные, такие как \\(\alpha\\) и \\(\beta\\), и операторы, такие как `=>`. 
Если такое выражение содержит переменные, то мы говорим, что оно обозначает _полиморфный тип_. 
В частности, функции `id` и `ay` имеют полиморфные типы.

#### 1.4.2 Виды определения

Во многих ситуациях можно определить значение функции с помощью анализа условия. 
Рассмотрим снова функцию `min`: \\(min(x, y) = x\\), если \\(x \leq y\\) или \\(y\\) если \\(x > y\\).

Это определение состоит из двух выражений, каждое из которых является выражениями с булевыми значениями, называемыми ограничителями. 
Выражение с булевыми значениями — это выражение, которое оценивается как одно из значений истинности `true` или `false`. 
Первая альтернатива определения гласит, что значение `min(x, y)` определяется как `x`, 
при условии, что выражение \\(x \leq y\\) оценивается как `true`. 
Вторая альтернатива гласит, что `min(x, y)` определяется как `y`, при условии, что выражение \\(x > y\\) оценивается как `true`. 
Два случая, \\(x \leq y\\) и \\(x > y\\), исчерпывают все возможности, поэтому значение `min` определяется для всех чисел `x` и `y`. 
Неважно, в каком порядке мы записываем альтернативы, поскольку эти два случая не пересекаются.

Другой способ определить `min` — записать: \\(min(x, y) = x\\), если \\(x \leq y\\), в противном случае - \\(y\\).

Специальное словосочетание «в противном случае» можно рассматривать как удобное сокращение для условия, 
которое возвращает значение `true`, когда все предыдущие ограничительные функции возвращают значение `false`.

Последняя часть обозначения, которую мы здесь введем, называется _локальным определением_.
В математических описаниях часто встречается выражение, определенное фразой вида «где ... ». 
Например, можно найти «f(x, y) = (a + 1)(a + 2), где a = (x + y)/2». 
Тот же прием можно использовать в формальном определении: \\(f(x, y) = (a + 1) \times (a + 2)\\), где a = (x + y)/2.

Здесь специальное слово «где» используется для введения локального определения, 
контекстом (или _областью действия_) которого является выражение в правой части определения f. 

Локальное определение можно использовать вместе с определением с помощью анализа условия. 

Рассмотрим следующее:

- f(x, y) = x + a , если x > 10
  - = x - a , в противном случае
  - где a = square(y + 1)

В этом определении раздел «где» определяет оба элемента правой части. 
Хотя для удобства чтения в анализе условия для `f` есть два вхождения знака `=`, 
есть только одно уравнение, и область действия раздела «где» включает его все.

#### 1.4.3 Карирование

Рассмотрим два определения `min`:

```dotty
def min(x: Int)(y: Int): Int = if x < y then x else y
def min2(x: Int, y: Int): Int = if x < y then x else y
```

Две функции, `min` и `min2`, очень тесно связаны, но есть тонкое различие: у них разные типы. 
Функция `min2` принимает один аргумент, который является структурированным значением, состоящим из пары чисел; 
ее тип задается как: `(Int, Int) => Int`.
Функция `min`, с другой стороны, принимает два аргумента по одному за раз. 
Её тип задается как: `Int => (Int => Int)`.

Другими словами, `min` — это функция, которая принимает число и возвращает функцию (из чисел в числа). 
Для каждого значения `x` выражение `min(x)` обозначает функцию, 
которая принимает аргумент `y` и возвращает минимум из `x` и `y`.

Вот еще один пример. Функция `add`, определяемая как: `def add(x: Int)(y: Int) = x + y` 
также имеет тип `Int => (Int => Int)`. 
Для каждого `x` функция `add(x)` «добавляет `x` к переменным». 
В частности, `add(1)` — это функция-последователь, которая увеличивает свой аргумент на `1`, 
а `add(0)` — это функция тождественности чисел.

Этот простой прием для замены структурированных аргументов последовательностью 
простых аргументов известен как _«каррирование»_ в честь американского логика H. B. Curry.
Для того, чтобы каррирование работало правильно и согласованно, требуется, 
чтобы операция функционального применения ассоциировалась слева. 
То есть, `min(x)(y)` означает `(min(x))(y)`, а не `min(x, y)`.

##### Упражнение 1.4.1

> как это используется во фразе «интеграл f от a до b».

Функцию можно определить так: `def integral(f: Int => Int, a: Int, b: Int): Int = ???`.
Тогда её тип будет `(Int => Int, Int, Int) => Int`.

##### Упражнение 1.4.2 

> Приведите примеры функций со следующими типами:
> 
> - `(num => num) => num`
> - `num => (num => num)`
> - `(num => num) => (num => num)`

- Пример: `(num => num) => num` - применение аргумента к заданной функции: `def apply(f: Int => Int, x: Int): Int = f(x)`
- Пример: `num => (num => num)` - уменьшение аргумента на заданное число: `def sub(x: Int): Int => Int = (y: Int) => (y - x)`
- Пример: `(num => num) => (num => num)` - двойное применение функции: `def double(f: Int => Int): Int => Int = (x: Int) => f(f(x))`

### 1.5 Спецификации и реализации

В компьютерном программировании _спецификация_ (_specification_) — это математическое описание задачи, 
которую должна выполнить программа, в то время как _реализация_ (_implementation_) — это программа, которая удовлетворяет спецификации. 
Спецификации и реализации по своей природе совершенно различны и служат разным целям. 
Спецификации — это выражения намерений программиста (или ожиданий клиента), и их цель — быть максимально краткими и ясными; 
реализации — это выражения для выполнения компьютером, 
и их цель — быть достаточно эффективными для выполнения в пределах доступного времени и пространства. 
Связь между ними заключается в требовании, чтобы реализация удовлетворяла или соответствовала спецификации, 
и серьезный программист обязан предоставить _доказательство_ того, что это действительно так.

Спецификация для значения функции — это некоторое утверждение предполагаемой связи между значениями аргументов и результатами. 
Простой пример — следующая спецификация функции `increase :: num => num`: `increase x > square x` для всех \\(x \geq 0\\). 
Спецификация говорит о том, что результат `increase` должен быть больше квадрата его аргумента, 
когда аргумент больше или равен нулю.

##### Упражнение 1.5.1

> Используя любую подходящую нотацию, запишите спецификацию функции `isSquare`, 
> которая определяет, является ли ее аргумент целым числом, являющимся квадратом другого целого числа. 
> Предположим, что значение `(intsqrt x)` является наибольшим целым числом, 
> которое не больше \\(\sqrt{x}\\). 
> 
> Будет ли следующее определение соответствовать вашей спецификации? 
> `isSquare x = (square(intsqrt x) = x)`

`isSquare :: num => bool`: `true`, если существует такое `y`, что `square y = x`, иначе - `false`.

Да, будет удовлетворять. 
Потому что если `x` - квадрат целого числа, то тогда `square(intsqrt x)` равно `x`.
Иначе, если `x` не является квадратом целого числа, то `(intsqrt x)` < \\(\sqrt{x}\\) => `square(intsqrt x) < x`.
