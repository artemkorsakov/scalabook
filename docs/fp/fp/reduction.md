# Редукция

## Понятие редукции

_Редукция_ (или _сокращение_, от англ. _reduction_) — это процесс последовательного преобразования сложного выражения
к его простейшей эквивалентной форме через применение правил преобразования.
Этот процесс аналогичен математическим вычислениям, где мы постепенно упрощаем выражения до их окончательного значения.

## Пример редукции на практике

Рассмотрим детальный разбор вычисления выражения `square(3 + 4)`:

1. **Первая стратегия вычислений** (внутреннее сокращение): `square(3 + 4) => square(7) => 7 * 7 => 49`
2. **Альтернативный подход** (внешнее сокращение): `square(3 + 4) => (3 + 4) * (3 + 4) => 7 * (3 + 4) => 7 * 7 => 49`

Ключевые наблюдения:

- Оба пути приводят к одинаковому результату (`49`)
- Конечное выражение `49` является _канонической формой_ (нормальной формой) — его нельзя сократить дальше
- Порядок применения редукций может различаться, но сохраняется свойство
  _конфлюэнтности_ ([Church-Rosser property](https://ru.wikipedia.org/wiki/%D0%A2%D0%B5%D0%BE%D1%80%D0%B5%D0%BC%D0%B0_%D0%A7%D1%91%D1%80%D1%87%D0%B0_%E2%80%94_%D0%A0%D0%BE%D1%81%D1%81%D0%B5%D1%80%D0%B0))

## Формальная система выражений

Рассмотрим формальный язык для представления целых чисел с операциями:

- Базовый случай: `zero` — атомарное выражение
- Рекурсивные случаи:
    - `(succ e)` — следующее число (_successor_)
    - `(pred e)` — предыдущее число (_predecessor_)

**Правила редукции**:

1. `(succ (pred e)) => e`
2. `(pred (succ e)) => e`

## Алгоритм нормализации выражений

Пошаговый процесс упрощения выражения `(succ(pred(succ(pred(pred zero)))))`:

1. **Первая итерация**:
   Находим вложенную пару `succ(pred ...)`:
   ```
   (succ (pred (succ (pred (pred zero)))))
   => (succ (pred (pred zero)))
   ```
2. **Вторая итерация**:
   Применяем то же правило:
   ```
   (succ (pred (pred zero)))
   => (pred zero)
   ```
3. **Результат**:
   Выражение `(pred zero)` не содержит сократимых пар `succ/pred`, следовательно:
    - Это каноническая форма
    - Дальнейшая редукция невозможна

## Реализация

```dotty
enum Expr:
  self =>

  case Zero
  case Succ(expr: Expr)
  case Pred(expr: Expr)

  def normalize: Expr =
    self match
      case Succ(Pred(e)) => e.normalize // Правило 1
      case Pred(Succ(e)) => e.normalize // Правило 2
      case Succ(e)       => Succ(e.normalize) // Рекурсивный случай
      case Pred(e)       => Pred(e.normalize) // Рекурсивный случай
      case _             => self // Базовый случай

import Expr.*
val expr = Succ(Pred(Succ(Pred(Pred(Zero)))))
expr.normalize // Результат: Pred(Zero)
```

## Значение редукции в функциональном программировании

Вот несколько причин, почему редукция применима в функциональном программировании:

- **Чистые функции**: Функциональный язык программирования опирается на чистые функции,
  которые не имеют побочных эффектов и возвращают одно и то же значение при одинаковых входных данных.
  Это делает возможным использование редукции, потому что каждая функция может быть сведена к своему значению независимо
  от контекста.
- **Рефакторинг и оптимизация**: Благодаря тому, что функции могут быть сведены к своим значениям,
  код становится легче рефакторить и оптимизировать.
  Например, можно заменить сложные выражения простыми значениями, не изменяя поведение программы.
- **Простота анализа и проверки корректности**: Поскольку каждое выражение может быть сведено к своему значению,
  анализ программы становится проще. Можно проверить корректность программы,
  рассматривая каждую функцию отдельно и убеждаясь, что она возвращает правильное значение.

## Упражнение 1.3.1: Пошаговая редукция арифметических выражений

> [Репозиторий с упражнениями и инструкцией по выполнению][sample]

**Цель:** Реализовать функцию для выполнения одного шага редукции арифметических выражений.

**Контекст:**

Арифметические выражения представлены с помощью алгебраического типа данных (АДТ) `Expr`, который включает:

- Числовые литералы (`Num`)
- Арифметические операции (`Add`, `Sub`, `Mul`)
- Переменные (`Var`)

**Задача:**

Реализуйте функцию `oneStepReduction`, которая выполняет один шаг редукции выражения по следующим правилам:

1. Если оба операнда бинарной операции являются числами - вычисляется результат
2. Если хотя бы один операнд не является числом - редукция применяется рекурсивно к подвыражениям
3. Переменные и числа не редуцируются дальше

```dotty
enum Expr:
  case Num(value: Int)
  case Add(left: Expr, right: Expr)
  case Sub(left: Expr, right: Expr)
  case Mul(left: Expr, right: Expr)
  case Var(name: String)

def oneStepReduction(expr: Expr): Expr = ???
```

**Требования:**

1. Функция должна возвращать выражение того же типа `Expr`
2. На каждом вызове выполняется ровно один шаг редукции
3. Редукция выполняется по стратегии "call-by-value" (сначала аргументы)

**Примеры:**

```dotty
// Вычисление сложения
Add(Num(2), Num(3))                  => Num(5)   
// Редукция правого подвыражения       
Add(Var("x"), Mul(Num(2), Num(3)))   => Add(Var("x"), Num(6)) 
// Невозможно редуцировать
Mul(Var("y"), Sub(Var("x"), Num(1))) => Без изменений   
```

@:note(🔍 Показать решение)

```dotty
def oneStepReduction(expr: Expr): Expr =
  import Expr.*
  expr match
    // Базовые случаи - не редуцируем дальше
    case Num(_) | Var(_) => expr
    
    // Редукция сложения
    case Add(Num(x), Num(y)) => Num(x + y)
    case Add(e1, e2) => Add(reduction(e1), reduction(e2))
    
    // Редукция вычитания
    case Sub(Num(x), Num(y)) => Num(x - y)
    case Sub(e1, e2) => Sub(reduction(e1), reduction(e2))
    
    // Редукция умножения
    case Mul(Num(x), Num(y)) => Num(x * y)
    case Mul(e1, e2) => Mul(reduction(e1), reduction(e2))
```

## Упражнение 1.3.2: Проверка канонической формы выражения

**Цель:** Реализовать функцию проверки, находится ли выражение в канонической (нормальной) форме.

**Определение:**

Выражение считается каноническим, если оно не может быть редуцировано дальше (т.е. применение `oneStepReduction` не
изменяет его).

**Задача:**

Реализуйте функцию `isCanonical`, которая возвращает `true`, если выражение находится в канонической форме.

```dotty
def isCanonical(expr: Expr): Boolean = ???
```

**Требования:**

1. Функция должна корректно определять, возможно ли применить дальнейшую редукцию
2. Должна работать для всех вариантов `Expr`

**Примеры:**

```dotty
Num(5)                     => true   // Число - каноническая форма
Var("x")                   => true   // Переменная - каноническая форма
Add(Num(2), Num(3))        => false  // Может быть редуцировано до Num(5)
Add(Var("x"), Num(3))      => true   // Не может быть редуцировано дальше
```

@:note(🔍 Показать решение)

```dotty
// Если редукция не изменяет выражение - оно каноническое
def isCanonical(expr: Expr): Boolean =
  oneStepReduction(expr) == expr
```

## Упражнение 1.3.3: Полная редукция выражения

**Цель:** Реализовать функцию для полной редукции выражения до канонической формы.

**Задача:**

Реализуйте функцию `reduction`, которая последовательно применяет `oneStepReduction` до тех пор,
пока выражение не достигнет канонической формы.

```dotty
def reduction(expr: Expr): Expr = ???
```

**Требования:**

1. Функция должна использовать рекурсию для эффективности
2. Должна корректно обрабатывать все варианты выражений
3. Должна завершаться, когда достигнута каноническая форма

**Примеры:**

```dotty
Add(Num(2), Num(3))                           => Num(5)
Sub(Mul(Add(Num(1), Num(1)), Num(3)), Num(2)) => Num(4)
```

@:note(🔍 Показать решение)

```dotty
def reduction(expr: Expr): Expr =
  def loop(current: Expr): Expr =
    if isCanonical(current) then current
    else loop(oneStepReduction(current))
  
  loop(expr)
```

Функция использует вспомогательную рекурсивную функцию `loop` для эффективного выполнения многократных редукций.
Проверка на каноничность выполняется на каждом шаге для определения момента завершения.

## Упражнение 1.3.4: Оптимизация арифметических выражений через расширенную редукцию

**Цель:**  

Реализовать усовершенствованный механизм пошаговой редукции арифметических выражений, 
который не только вычисляет простые операции, но и применяет базовые алгебраические оптимизации для упрощения выражений.

**Контекст:**  

В реальных компиляторах и интерпретаторах простые арифметические оптимизации (вроде сокращения операций с `0` или `1`) 
значительно улучшают производительность. В этом упражнении расширим базовую редукцию, добавив такие оптимизации.

**Задача:**  

Модифицировать функцию `oneStepReduction` для поддержки следующих оптимизаций:

1. Упрощение операций с нулём:
    - `x + 0` → `x`
    - `0 + x` → `x`
    - `x - 0` → `x`
    - `x - x` → `0`
    - `0 * x` → `0`
    - `x * 0` → `0`
2. Упрощение операций с единицей:
    - `x * 1` → `x`
    - `1 * x` → `x`

**Требования:**

1. Сохранить все возможности из предыдущей версии редукции
2. Добавить обработку граничных случаев с `0` и `1`
3. Гарантировать, что каждое применение функции выполняет ровно один шаг редукции
4. Поддерживать корректную работу с переменными

**Примеры входных и выходных данных:**

```dotty
// Базовые случаи
Add(Num(2), Num(3))             => Num(5)       // Обычное вычисление
Add(Var("x"), Num(0))           => Var("x")     // Оптимизация +0
Sub(Num(5), Num(0))             => Num(5)       // Оптимизация -0
Mul(Num(0), Var("y"))           => Num(0)       // Оптимизация *0

// Комплексные случаи
Add(Add(Num(2), Num(0)), Num(3)) => Add(Num(2), Num(3))
Mul(Sub(Num(1), Num(1)), Var("x")) => Mul(Num(0), Var("x"))

// Случаи без изменений
Add(Var("x"), Var("y"))         => Add(Var("x"), Var("y"))
```

@:note(🔍 Показать решение)

```dotty
def oneStepReduction(expr: Expr): Expr =
  import Expr.*
  expr match
    // Базовые случаи - не изменяем
    case Num(_) | Var(_) => expr

    // Оптимизации для сложения
    case Add(Num(0), e) => e // 0 + x → x
    case Add(e, Num(0)) => e // x + 0 → x
    case Add(Num(x), Num(y)) => Num(x + y)
    case Add(e1, e2) => Add(reduction(e1), reduction(e2))

    // Оптимизации для вычитания
    case Sub(e, Num(0)) => e // x - 0 → x
    case Sub(e1, e2) if e1 == e2 => Num(0) // x - x → 0 
    case Sub(Num(x), Num(y)) => Num(x - y)
    case Sub(e1, e2) => Sub(reduction(e1), reduction(e2))

    // Оптимизации для умножения
    case Mul(Num(0), _) => Num(0) // 0 * x → 0
    case Mul(_, Num(0)) => Num(0) // x * 0 → 0
    case Mul(Num(1), e) => e // 1 * x → x (доп. оптимизация)
    case Mul(e, Num(1)) => e // x * 1 → x (доп. оптимизация)
    case Mul(Num(x), Num(y)) => Num(x * y)
    case Mul(e1, e2) => Mul(reduction(e1), reduction(e2))
```

Это упражнение демонстрирует, как даже простые оптимизации могут значительно улучшить эффективность вычислений, 
особенно при работе с большими или сложными выражениями.
