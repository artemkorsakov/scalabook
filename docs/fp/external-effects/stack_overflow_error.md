# TailRec: прыжки на батуте

Напомним определение `IO`:

```dotty
trait IO[A]:
  self =>

  def unsafeRun(): A

  def map[B](f: A => B): IO[B] = new:
    def unsafeRun(): B = f(self.unsafeRun())

  def flatMap[B](f: A => IO[B]): IO[B] = new:
    def unsafeRun(): B = f(self.unsafeRun()).unsafeRun()

  // Продолжает действие своего аргумента бесконечно
  def forever[B]: IO[B] =
    lazy val t: IO[B] = self.forever
    self.flatMap(_ => t)

object IO:
  def apply[A](a: => A): IO[A] = new:
    def unsafeRun(): A = a
```

Чтобы лучше понять `StackOverflowError`, рассмотрим эту очень простую программу, демонстрирующую проблему:

```dotty
def PrintLine(msg: String): IO[Unit] = IO(println(msg))

val p = PrintLine("Still going...").forever
p.unsafeRun()
// Still going...
// Still going...
// Still going...
// ...
// StackOverflowError
```

Если мы вызовем `p.unsafeRun`, он вылетит со `StackOverflowError` после печати нескольких тысяч строк. 
Если вы посмотрите на трассировку стека, то увидите, что `unsafeRun` вызывает себя снова и снова. 
Проблема в определении `flatMap`:

```dotty
def flatMap[B](f: A => IO[B]): IO[B] = new:
  def unsafeRun(): B = f(self.unsafeRun()).unsafeRun()
```

Этот метод создает новый объект `IO`, определение которого вызывается снова перед вызовом `unsafeRun`. 
Это будет продолжать накапливать вложенные вызовы в стеке и в конечном итоге переполнять его. 
Что мы можем с этим сделать?

## Реификация потока управления в качестве конструкторов данных

Ответ на удивление прост. 
Вместо того, чтобы позволить управлению программой просто проходить через вызовы функций, 
мы явно запаковывает поток управления, который мы хотим поддерживать, в нашем типе данных. 
Например, вместо того, чтобы создавать метод `flatMap`, который конструирует `new IO` в терминах `unsafeRun`, 
мы можем просто сделать его конструктором данных типа данных `IO`, 
а затем интерпретатор может быть хвостовым рекурсивным циклом. 
Всякий раз, когда он сталкивается с конструктором вроде `FlatMap(x, k)`, 
он будет интерпретировать `x`, а затем вызовет результат `k`. 
Вот новый тип `IO`, который реализует эту идею.

```dotty
enum IO[A]:
  self =>

  // Это чистое вычисление, которое последовательно возвращает A без каких-либо шагов.
  // Когда unsafeRun видит этот конструктор, он знает, что вычисление завершено.
  case Return(a: A)

  // Это приостановка вычисления, где возобновление — это функция,
  // которая не принимает аргументов, но оказывает некоторое воздействие и выдает результат.
  case Suspend(resume: () => A)

  // Это композиция из двух шагов.
  // Она материализует FlatMap как конструктор данных, а не как функцию.
  // Когда run это увидит, он должен сначала обработать подвычисление sub,
  // а затем продолжить с k, как только sub выдаст результат.
  case FlatMap[B, C](sub: IO[B], k: B => IO[C]) extends IO[C]

  def flatMap[B](f: A => IO[B]): IO[B] =
    FlatMap(self, f)

  def map[B](f: A => B): IO[B] =
    flatMap(a => Return(f(a)))

  def forever[B]: IO[B] =
    lazy val t: IO[B] = self.forever
    self.flatMap(_ => t)
end IO
```

Этот новый `IO` тип имеет три конструктора данных, представляющих три различных вида потока управления, 
которые мы хотим, чтобы интерпретатор этого типа данных поддерживал. 
`Return` представляет `IO` действие, которое было завершено, 
то есть мы хотим вернуть значение `a` без каких-либо дальнейших шагов. 
`Suspend` означает, что мы хотим выполнить некоторый эффект для получения результата, 
а конструктор данных `FlatMap` говорит, что мы **расширяем** или **продолжаем** существующее вычисление, 
используя результат первого вычисления для создания второго вычисления.
Реализация метода `flatMap` теперь может просто вызвать конструктор данных `FlatMap` и немедленно вернуться.
Когда интерпретатор встречает `FlatMap(sub, k)`, он может интерпретировать подвычисление `sub` 
и затем не забыть вызвать продолжение `k` для результата. 
Затем `k` продолжит выполнение программы. 

Давайте также добавим несколько удобных конструкторов:

```dotty
object IO:
  // Задерживает вычисление до тех пор, 
  // пока не будет интерпретирована возвращенная программа.
  def apply[A](a: => A): IO[A] =
    suspend(Return(a))

  // Задерживает вычисление программы ioa до тех пор, 
  // пока возвращенная программа не будет интерпретирована.
  def suspend[A](ioa: => IO[A]): IO[A] =
    Suspend(() => ioa).flatMap(identity)
```

Обратите внимание, что определения `apply` и `suspend` не оценивают свои аргументы по имени — 
скорее, оценка откладывается до более позднего времени, 
когда принудительно передается преобразование во внутреннее значение `Suspend`.

Скоро мы перейдем к интерпретатору, но сначала давайте перепишем наш пример `printLine`, 
чтобы использовать этот новый `IO` тип:

```dotty
def printLine(s: String): IO[Unit] =
  IO(println(s))

val p = printLine("Still going...").forever
```

На самом деле это создает бесконечную вложенную структуру, очень похожую на `LazyList`. 
**Голова** потока — это `Function0`, а остальная часть вычисления похожа на **хвост**:

```dotty
FlatMap(
  FlatMap(
    Suspend(() => Return(println(s))),
    identity
  ),
  _ => FlatMap(
    FlatMap(
      Suspend(() => Return(println(s))),
      identity
    ),
    _ => FlatMap(...)))
```

Ниже представлен интерпретатор с хвостовой рекурсией, определенный как метод на `IO`, 
который обходит структуру и выполняет эффекты:

```dotty
@annotation.tailrec
final def unsafeRun(): A =
  self match
    case Return(a)  => a
    case Suspend(r) => r()
    // Мы могли бы просто сказать здесь f(x.unsafeRun()).unsafeRun(),
    // но тогда внутренний вызов unsafeRun не будет в хвостовой позиции.
    // Вместо этого мы сопоставляем x, чтобы увидеть, что это такое.
    case FlatMap(x, f) => x match
        case Return(a) => f(a).unsafeRun()
        // Здесь x — это Suspend(r), поэтому мы вызываем r-переходник 
        // и вызываем f для результата.
        case Suspend(r) => f(r()).unsafeRun()
        // В этом случае io — это выражение вроде FlatMap(FlatMap(y, g), f).
        // Мы повторно связываем это с правым шансом, 
        // чтобы вызвать unsafeRun в хвостовой позиции,
        // и следующая итерация будет соответствовать y.
        case FlatMap(y, g) =>
          y.flatMap(a => g(a).flatMap(f)).unsafeRun()
```

Вместо того, чтобы вызывать `f(x.unsafeRun()).unsafeRun()` в случае `FlatMap(x, f)` (теряя тем самым хвостовую рекурсию), 
мы сопоставляем шаблон с `x`, поскольку он может быть только одним из трех вариантов. 
Если это `Return`, мы можем просто вызвать чистое значение внутри `f`. 
Если это `Suspend`, то мы можем просто выполнить его возобновление, 
передать результат в `f` из внешнего `FlatMap`, и выполнить рекурсию. 
Но если `x` - это само по себе конструктор `FlatMap`, то мы знаем, 
что он состоит из двух вложенных конструкторов `FlatMap` слева `io`, вот так: `FlatMap(FlatMap(y, g), f)`.

Чтобы продолжить выполнение программы в этом случае, нам нужно проверить `y`, 
является ли она другой конструктор `FlatMap`, но выражение может быть произвольно глубоким, 
а мы хотим остаться хвостовой рекурсией. 
Мы переассоциируем это вправо, фактически превращая `y.flatMap(g).flatMap(f)` в `y.flatMap(a => g(a).flatMap(f))`. 
Мы пользуемся преимуществом закона ассоциативности [монады](../../typeclass/monad/monad.md)! 
Затем мы вызываем переписанное выражение `unsafeRun`, позволяя нам оставаться хвостовой рекурсией. 
Таким образом, когда мы фактически интерпретируем нашу программу, 
она будет инкрементно переписана, чтобы стать правоассоциированной последовательностью конструкторов `FlatMap`:

```dotty
FlatMap(a1, a1 =>
  FlatMap(a2, a2 =>
    FlatMap(a3, a3 =>
      ...
      FlatMap(aN, aN => Return(aN)))))
```

Если мы теперь вызовем `unsafeRun` наш пример программы `p`, 
она продолжит работать бесконечно без переполнения стека, что нам и нужно. 
Наша функция `unsafeRun` не переполнит стек, даже для бесконечно рекурсивных `IO` программ.

Что мы здесь сделали? 
Когда программа, работающая на JVM, вызывает функцию, она помещает кадр в стек вызовов, 
чтобы запомнить, куда вернуться после завершения вызова, чтобы выполнение могло продолжиться. 
Мы сделали этот контроль программы явным в нашем типе данных `IO`. 
Когда `unsafeRun` интерпретирует `IO` программу, она определяет, 
запрашивает ли программа выполнение некоторого эффекта с помощью `Suspend(s)` 
или хочет вызвать подпрограмму с помощью `FlatMap(x, f)`. 
Вместо того, чтобы программа использовала стек вызовов `unsafeRun`, она вызовет `x()`, 
а затем продолжит, вызвав результат этого `f`, и `f` немедленно вернет либо `Suspend`, `FlatMap`, 
либо `Return`, снова передав управление `unsafeRun`. 
Таким образом, наша `IO` программа является своего рода сопрограммой, которая выполняется совместно с `unsafeRun`. 
Она постоянно делает запросы `Suspend` или `FlatMap`, и каждый раз, когда она это делает, 
она приостанавливает собственное выполнение и возвращает управление `unsafeRun`. 
И это на самом деле `unsafeRun` движет выполнением программы вперед, по одной такой приостановке за раз. 
Функция типа `unsafeRun` иногда называется _батут_, 
а общая методика возврата управления к одному циклу для устранения стека называется _прыжки на батуте_.

## Прыжки на батуте: общее решение проблемы переполнения стека

Нет необходимости в том, чтобы функции `resume` в нашей `IO` выполняли побочные эффекты. 
Тип `IO`, который у нас есть до сих пор, на самом деле является общей структурой данных для трамплинных вычислений — 
даже чистых вычислений, которые вообще не выполняют никаких операций ввода-вывода!

Проблема `StackOverflowError` проявляется в Scala, где бы у нас ни была составная функция, 
состоящая из большего количества вызовов функций, чем есть места в стеке вызовов. 
Эту проблему легко продемонстрировать:

```dotty
scala> val f = (x: Int) => x
val f: Int => Int = <function1>
 
// Мы строим составную функцию g, состоящую из 100 000 функций, где возникает эта функция. 
scala> val g = List.fill(100000)(f).foldLeft(f)(_ compose _)
val g: Int => Int = <function1>
 
scala> g(42)
java.lang.StackOverflowError
```

К счастью, мы можем решить это с помощью нашей `IO`:

```dotty
val f = (x: Int) => IO.Return(x)

val g =
  List.fill(100000)(f).foldLeft(f)((a, b) => x => IO.suspend(a(x).flatMap(b)))

val x1 = g(0).unsafeRun()  // 0
val x2 = g(42).unsafeRun() // 42
```

Но здесь вообще нет ввода-вывода. 
Так что `IO` - это немного неправильное название. 
На самом деле оно получило это название из-за того, что `Suspend` может содержать функцию с побочным эффектом. 
Но то, что у нас есть, на самом деле не концепция для ввода-вывода — 
это на самом деле концепция для устранения хвостового вызова! 
Давайте изменим его имя, чтобы отразить это:

```dotty
enum TailRec[A]:
  case Return(a: A)
  case Suspend(resume: () => A)
  case FlatMap[B, C](sub: TailRec[B], k: B => TailRec[C]) extends TailRec[C]

  def flatMap[B](f: A => TailRec[B]): TailRec[B] =
    FlatMap(this, f)

  def map[B](f: A => B): TailRec[B] =
    flatMap(a => Return(f(a)))

  // Мы переименовали эту функцию в run, 
  // поскольку она больше не используется для захвата эффектов.
  @annotation.tailrec
  final def run: A = this match
    case Return(a)  => a
    case Suspend(r) => r()
    case FlatMap(x, f) => x match
        case Return(a)     => f(a).run
        case Suspend(r)    => f(r()).run
        case FlatMap(y, g) => y.flatMap(a => g(a).flatMap(f)).run
```

Мы можем использовать этот тип данных `TailRec` для добавления трамплина к любому типу функции `A => B`, 
изменив возвращаемый тип `B` на `TailRec[B]` вместо этого. 
Мы только что видели пример, где мы изменили программу, которая использовала `Int => Int` на `Int => TailRec[Int]`.
Программу просто нужно было изменить для использования `flatMap` в композиции функций 
и `Suspend` перед каждым вызовом функции.

Использование `TailRec` может быть медленнее, чем прямые вызовы функций, 
но его преимущество в том, что мы получаем предсказуемое использование стека.

> `TailRec` в стандартной библиотеке
> 
> Тип `TailRec`, который мы здесь определили, 
> встроен в стандартную библиотеку Scala в объекте `scala.util.control.TailCalls`. 
> Объект определяет тип `TailRec[A]`, а также конструкторы `done` и `tailcall`, 
> которые соответствуют `Return` и `suspend` конструктору удобства. 
> Тип `TailRec` имеет метод `result`, который интерпретирует значение `TailRec[A]` в значение `A`. 
> 
> Вот тот же пример, использующий `TailCalls` вместо нашего `TailRec`:
> 
> ```dotty
> import scala.util.control.TailCalls.*
> 
> val f = (x: Int) => done(x)
> val g = List.fill(100000)(f).foldLeft(f)((a, b) => x => tailcall(a(x).flatMap(b)))
> 
> val x1 = g(0).result  // 0
> val x2 = g(42).result // 42
> ```
