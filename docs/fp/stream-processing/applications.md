# Применение

## Что такое потоковая обработка?

Представьте, что вам нужно перенести воду из озера в бассейн. Вы можете:

1. **Вычерпать всё озеро сразу** (загрузить весь файл в память) — это долго, требует огромной тары (памяти) 
   и может привести к катастрофе, если тара лопнет (закончится память).
2. **Использовать шланг** (потоковую обработку) — вода передается небольшими порциями непрерывно. 
   Это эффективно, безопасно и вы можете начать наполнять бассейн, пока озеро еще не полностью "обработано".

**Потоковая обработка** — это именно такой "шланг" для данных. 
Вы обрабатываете информацию не всю сразу, а по частям (порциями, "чанками"), по мере их поступления. 
Это ключевая абстракция для работы с большими, бесконечными или медленными источниками данных.

## Где применяется потоковая обработка?

Идеи из главы "Потоковая обработка" — это не сухая теория, а мощный инструмент, 
который вы уже не раз видели, возможно, не осознавая этого.

- **Файловый ввод/вывод (I/O)**
    - **Что это:** Самый классический пример. Чтение и запись файлов.
    - **Как это выглядит в коде:**
        - **Без потоков:** `val entireFile: String = readFile("huge_log.txt")` → Ждем, пока файл в 100 ГБ 
          целиком загрузится в оперативную память (скорее всего, программа упадет).
        - **С потоками:** `Stream[IO, String] = readFileLineByLine("huge_log.txt")` → Файл читается построчно. 
          Каждая строка обрабатывается и сразу же забывается, освобождая память. Можно обработать файл любого размера.
    - **Детализация:** Работает не только с текстом! 
      Таким же образом можно Stream-ами обрабатывать аудио, видео, изображения — любые бинарные данные.
- **Обработка сообщений, конечные автоматы и акторы**
    - **Что это:** Архитектура больших систем (например, микросервисов), 
      где компоненты общаются, отправляя друг другу сообщения (например, через Kafka, RabbitMQ).
    - **Как это выглядит:** Каждый компонент (например, "Сервис обработки заказов") можно представить 
      как `Stream[IO, Order]` — поток входящих сообщений-заказов. 
      Он преобразует их в другой поток — `Stream[IO, Invoice]` (поток накладных). 
      Это и есть высокоуровневое описание сложного поведения системы через композицию простых потоков.
- **Серверы и веб-приложения**
    - **Что это:** Любой веб-сервер.
    - **Как это выглядит:** Сервер — это гигантский `Pipe[IO, Request, Response]` (труба, преобразующая запросы в ответы).
        - **Входной поток:** Бесконечный поток HTTP-запросов от пользователей: `Stream[IO, Request]`.
        - **Выходной поток:** Поток сгенерированных ответов: `Stream[IO, Response]`.
    - **Пример (http4s):** Фреймворк [http4s](https://github.com/http4s/http4s), построенный на [FS2][fs2], именно так и работает.
- **Программирование пользовательского интерфейса (UI)**
    - **Что это:** Реактивные интерфейсы, где действия пользователя мгновенно влияют на отображение 
      (как в современных SPA-фреймворках типа React, но на концептуальном уровне).
    - **Как это выглядит:**
        - **Поток событий:** `val clickStream: Stream[IO, MouseClick]` — поток кликов мыши.
        - **Поток данных:** `val apiDataStream: Stream[IO, Data]` — поток данных, приходящих с сервера.
    - **UI — это функция:** Интерфейс — это функция, которая комбинирует эти потоки 
      и определяет, как должен измениться экран в ответ на каждое новое событие или данные.
- **Большие данные и распределенные системы**
    - **Что это:** Обработка петабайтов данных (например, в Apache Spark, Flink).
    - **Детализация:** Узлы потокового графа (этапы обработки) можно раскидать по разным компьютерам в кластере. 
      Один компьютер фильтрует данные, другой — агрегирует, третий — сохраняет в базу. Поток данных течет между ними. 
      Библиотеки вроде [FS2][fs2] предоставляют абстракции, которые позволяют описывать такую логику, а затем "масштабировать" ее на кластер.

## Библиотека FS2: Промышленная реализация

**[FS2][fs2] (Functional Streams for Scala)** — это не учебный пример, а полноценная, battle-tested библиотека, 
которая реализует все описанные выше идеи для языка Scala.

- **Что она дает:** `Stream`, `Pull`, `Pipe` — это основные типы данных, с которыми вы работаете.
- **Ключевые возможности:**
    - **Параллелизм:** Легко запускать части потокового графа параллельно.
    - **Разветвление:** Направить данные по разным "каналам" для обработки.
    - **Безопасная работа с ресурсами:** Гарантированное закрытие файлов, сокетов и т.д., даже если в середине потока произошла ошибка.
    - **Работа с эффектами:** Глубокая интеграция с современными библиотеками для функционального программирования 
      ([Cats Effect](https://github.com/typelevel/cats-effect), [ZIO](https://zio.dev/)), что делает код предсказуемым и надежным.
- **Экосистема:** На FS2 построено [множество популярных библиотек](https://fs2.io/#/ecosystem), 
  что доказывает ее мощь и универсальность. Например:
    - **http4s:** Веб-фреймворк, где и сервер, и клиент — это потоки.
    - **doobie:** Библиотека для работы с базами данных. Ваши SQL-запросы и результаты их выполнения можно представлять как потоки.

## Краткое содержание (Ключевые концепции простыми словами)

- **Императивный I/O vs. Потоковый I/O:**
    - **Императивный:** "Прочитай весь файл, потом сделай с ним что-то" — монолитный и небезопасный.
    - **Потоковый:** "Начни передавать данные из файла, и по мере поступления каждой порции применяй к ней операции" — 
      инкрементальный, композиционный и безопасный.
- **Основные типы:**
    - **`Stream[F, O]`:** Это и есть сам "шланг" с данными. Он выдает значения типа `O`, 
      выполняя побочные эффекты (вроде чтения из файла) в контексте `F` (например, `IO`).
    - **`Pull[F, O, R]`:** Это "инструкция" или "план" по построению потока. 
      Он может выводить значения `O` и в конце вернуть некий финальный _результат_ `R` 
      (например, количество обработанных байт).
    - **Связь:** `Stream` — это готовый поток данных. `Pull` — это инструмент для его гибкой сборки. 
      Их можно легко преобразовать друг в друга.
- **`Pipe[F, I, O]`:** Это **преобразователь** потоков. Псевдоним для функции `Stream[F, I] => Stream[F, O]`. 
  Представьте себе отрезок трубы, который принимает поток одних данных (вход `I`) и возвращает поток других (выход `O`).
    - **Примеры `Pipe`:**
        - `filter(_ > 0)`: Фильтрует числа, оставляя только положительные.
        - `map(_.toUpperCase)`: Преобразует каждую строку в верхний регистр.
    - **Композиция:** "Трубы" можно соединять. `cleanData andThen validate andThen saveToDB` — классическая цепочка обработки.
- **Безопасность ресурсов:** Одно из главных преимуществ. 
  FS2 гарантирует, что если вы открыли файл через `Stream.resource`, он будет **обязательно закрыт**, 
  даже если при обработке произошла ошибка или вы взяли только первые 10 строк (`take(10)`).
- **Работа с состоянием:** `Ref` — это просто "безопасная переменная", доступ к которой осуществляется внутри эффекта `F`. 
  Полезно, когда разным элементам потока нужно иметь доступ к общему изменяемому состоянию (например, счетчику).

## Итог

Потоковая обработка — это **стиль мышления** о том, как данные перемещаются и трансформируются в вашей программе. 
Вместо работы с целыми массивами данных вы работаете с их непрерывным потоком, применяя к нему серию мелких преобразований. 
Это приводит к коду, который:

- **Эффективен:** Потребляет мало памяти.
- **Надежен:** Безопасно управляет ресурсами.
- **Композируем:** Сложные задачи собираются как Lego из простых кусочков (`map`, `filter`, `flatMap`).
- **Универсален:** Применим от чтения файлов до построения распределенных систем.

Библиотека [FS2][fs2] предоставляет все необходимые инструменты для применения этого подхода в Scala на промышленном уровне.
