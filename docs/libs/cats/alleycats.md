# Alleycats

## Обзор

**Alleycats** — это модуль проекта [Cats](https://github.com/typelevel/cats), 
существующий для поддержки типов, не являющихся полностью «законопослушными» 
или безупречными с точки зрения формальных законов, 
но которые могут оказаться полезными или необходимыми в некоторых ситуациях.

**Почему «Alleycats»?**  
Название обыгрывает слово _alley cat_ (беспризорная, дворовая кошка) — в противовес «благородным» кошкам из основного проекта. 
Это подчёркивает «нереспектабельный» статус модуля.

### Мотивация создания

В некоторых случаях экземпляр класса типов может почти (но не полностью) соблюдать требуемые законы. 
Например, экземпляр `Monad` для `scala.util.Try` — он нарушает законы функтора/монады 
из-за перехвата исключений в `map` и `flatMap`, но на практике его часто удобно использовать.

В других случаях классы типов, у которых нет строгих законов или ограничений, всё равно могут быть полезны. 
Например, `Empty[_]` — класс типов, предоставляющий некоторое понятие «пустоты».

Вместо того чтобы вести бесконечные споры о том, стоит ли включать такие типы в основной Cats, 
разработчики предоставили для них отдельный «дом» — чуть сомнительный, но гостеприимный.

> **Важно:** Если экземпляр класса типов полностью соблюдает законы — его место в основном Cats. 
> Всё остальное попадает сюда, в Alleycats.

## Классы типов, вводимые Alleycats

Alleycats вводит несколько новых классов типов, отсутствующих в основном Cats. Рассмотрим их подробнее.

### `Empty[A]`, `Zero[A]` и `One[A]`

**Проблема:** В Cats для представления «пустого» значения используется `Monoid[A]`, 
который требует наличия ассоциативной бинарной операции (`combine`). 
Но иногда понятие пустоты существует независимо от конкретной операции сложения/объединения.

**Решение:** Alleycats вводит `Empty[A]` — класс типов, который предоставляет доступ 
к _нейтральному элементу_ (пустому значению) через метод `.empty`.

**Дополнительные возможности:** Если доступен экземпляр `Eq[A]` (сравнение на равенство), 
то `Empty[A]` также предоставляет методы `.isEmpty` и `.nonEmpty` для проверки, является ли значение «пустым».

**`Zero[A]` и `One[A]`:** Это аналоги `Empty`, но для кольцеподобных структур из пакета `algebra.ring`:

- `Zero[A]` соответствует _аддитивному_ нейтральному элементу (метод `.zero`).
- `One[A]` соответствует _мультипликативному_ нейтральному элементу (метод `.one`).

**Важное требование (закон):** Хотя сами эти классы типов не имеют собственных формальных законов, 
они **обязаны** не нарушать законы моноидов, когда это применимо. Это означает:

- Если одновременно доступны `Empty[A]` и `Semigroup[A]`, то `Empty[A].empty` **обязан** 
  быть нейтральным элементом для `Semigroup[A].combine`. 
  Вместе эти экземпляры образуют полноценный `Monoid[A]` (и в Alleycats есть неявное преобразование, создающее такой экземпляр).
- Аналогичное правило действует для `Zero[A]` (с `Semigroup` или `AdditiveSemigroup`) и `One[A]` (с `MultiplicativeSemigroup`).

### `Pure[F[_]]` и `Extract[F[_]]`

**Проблема:** Иногда хочется иметь только часть функциональности существующего класса типов, 
но при этом гарантировать совместимость, если остальные части тоже появятся.

**`Pure[F]`**:

- Представляет метод `.pure` из `Applicative[F]`, но без методов `.map` и `.ap`.
- Если одновременно доступны `Pure[F]` и `Apply[F]`, то они **обязаны** быть согласованными 
  и вместе предоставлять корректный экземпляр `Applicative[F]`.

**`Extract[F]`**:

- Представляет метод `.extract` (извлечение значения из контекста) из `Comonad[F]`, но без методов `.coflatMap` и `.map`.
- Если одновременно доступны `Extract[F]` и `CoflatMap[F]`, то они должны предоставлять корректный экземпляр `Comonad[F]`.

**Практический смысл:** Эти классы типов позволяют описывать частичные возможности. 
Например, вы можете написать функцию, которой нужна только возможность «поднять» значение в контекст (`pure`), 
и ей не требуется полный `Applicative`.

### `EmptyK[F[_]]`

**`EmptyK[F]`** — это обобщение метода `.empty[A]` из `MonoidK[F]` на уровне конструкторов типов.

**Принцип тот же:** если доступны `SemigroupK[F]` (объединение на уровне контейнеров) и `EmptyK[F]` (пустой контейнер), 
то вместе они должны предоставлять корректный экземпляр `MonoidK[F]`.

**Пример:** Для `List` `EmptyK` предоставляет пустой список; для `Option` — `None`. 
Это позволяет использовать операции вроде «пустого» значения для любого типа-контейнера.

## Экземпляры (Instance) классов типов, предоставляемые Alleycats

Alleycats также предоставляет несколько «сомнительных» экземпляров классов типов для стандартных типов Scala.

### Экземпляры для `Set[_]`

**Проблема:** `Set` в Scala опирается на универсальную доступность методов `.hashCode` и `.equals` для элементов. 
Это затрудняет использование **параметричности** (parametricity) — возможности рассуждать о поведении кода только по типам, 
не зная конкретных реализаций. Из-за этого возникают сомнения в корректности использования `Set` с функторами и монадами.

**Почему `Set` не является законопослушным `Functor` (и, следовательно, `Applicative`, `Monad` и т.д.):**

Хотя во многих случаях `Set` действительно ведёт себя как `Functor`, существуют пограничные ситуации, где это не так. 
Например, `Set` может нарушать закон композиции функтора:

```
fa.map(f).map(g) <-> fa.map(f.andThen(g))
```

Этот закон гласит, что применение двух отображений последовательно должно давать тот же результат, 
что и применение их композиции за один проход.

Поскольку внутренне `Set` основан на универсальном хешировании и сравнении (через `hashCode` и `equals`), 
он нарушает этот закон при работе с типами данных, которые переопределяют `equals` и `hashCode` таким образом, 
что их экземпляры могут казаться равными, но фактически содержать разные значения.

**Реальный пример нарушения:**

```dotty
import scala.concurrent.duration.*

val f: String => Duration = Duration.apply
val g: Duration => String = _.toString

val set = Set("1 minute", "60 seconds", "60000 milliseconds")

set.map(f).map(g)
// Результат: Set("1 minute")
set.map(f.andThen(g))
// Результат: Set("1 minute", "60 seconds", "60000 milliseconds")
```

В этом примере:

- Строки `"1 minute"`, `"60 seconds"` и `"60000 milliseconds"` парсятся в эквивалентные объекты `Duration` (все представляют 60 секунд).
- Для `Duration` метод `equals` считает эти объекты равными, но метод `hashCode` может давать разные значения для разных способов представления.
- При первом отображении (`set.map(f).map(g)`) промежуточный `Set[Duration]` схлопывает эквивалентные значения 
  в один элемент (из-за `equals`), а затем преобразует его обратно в строку.
- При втором отображении (`set.map(f.andThen(g))`) композиция применяется за один проход, 
  и `Set` не успевает «схлопнуть» эквивалентные элементы, поэтому результат содержит все три строки.

**Другой реальный пример:** [CIString](https://typelevel.org/case-insensitive) — регистронезависимая строка, 
где строки, отличающиеся только регистром, считаются равными, но могут иметь разные хеш-коды.

**Что предоставляет Alleycats:** Несмотря на эти проблемы, Alleycats предоставляет экземпляры `Monad[Set]` и `Traverse[Set]`.

**Импорт:** `import alleycats.std.set.*`

**Пример использования:**

```dotty
import cats.syntax.all.*
import alleycats.std.set.*

val sets = Set(1, 2) flatMap (x => Set(x, x * 2))
// Результат: Set(1, 2, 4) — но порядок не гарантирован!
```

**Важное предостережение:** Используйте `Monad[Set]` из Alleycats **на свой страх и риск**! 
Убедитесь, что типы данных, с которыми вы работаете, не нарушают законы функтора. 
В частности, избегайте использования `Set` с типами, где `equals` и `hashCode` 
могут давать противоречивые результаты (например, `Duration`, `CIString` или подобные). 
Если вы не уверены в поведении ваших типов данных, лучше избегать использования `Set` 
в функторных/монадных операциях или применять другие коллекции, 
такие как `List` или `Vector`, которые не нарушают законы.

### Экземпляры для `Try[_]`

**Проблема:** `scala.util.Try` был создан для замены конструкции `try { ... } catch { ... }` и упрощения обработки ошибок, 
а также для передачи исключений как данных. 
Однако из-за того, что `Try` прозрачно перехватывает исключения в методах `.map` и `.flatMap`, 
многие разработчики сомневаются, что `Try` выполняет законы функтора/монады.

**Что предоставляет Alleycats:** Экземпляр `Monad[Try]`.

**Импорт:** `import alleycats.std.try_.*`

**Пример использования:**

```dotty
import scala.util.Try
import cats.syntax.all.*
import alleycats.std.try_.*

val result = Try(10).map(_ / 2) 
// Success(5)
val failed = Try(10).map(_ / 0) 
// Failure(java.lang.ArithmeticException: / by zero)
```

### Экземпляры для `Iterable[_]`

**Проблема:** `scala.collection.Iterable[_]` в Scala не даёт гарантий неизменяемости, 
так как абстрагируется как над изменяемыми (`mutable`), так и над неизменяемыми (`immutable`) коллекциями. 
Однако этот тип используется, например, для представления коллекции значений (`values`) в `Map`. 
И часто бывает удобно рассматривать эти значения как `Foldable` коллекцию для свёртки.

**Что предоставляет Alleycats:** Экземпляр `Foldable[Iterable]`.

**Импорт:** `import alleycats.std.iterable.*`

**Пример использования:**

```dotty
import cats.syntax.all.*
import alleycats.std.iterable.*

// Объединяем все значения Map в одну строку
val result = Map(1 -> "Apple", 2 -> "Orange").values.combineAll
// Результат: "AppleOrange"
```

Обратите внимание: `values` возвращает `Iterable[String]`, и благодаря экземпляру `Foldable[Iterable]` 
мы можем использовать `.combineAll` (суммирование через моноид).

## Краткий итог

| Компонент          | Назначение                                   | Ключевой импорт                   |
|:-------------------|:---------------------------------------------|:----------------------------------|
| **Empty/Zero/One** | Нейтральные элементы без привязки к операции | `import alleycats.Empty.*`        |
| **Pure/Extract**   | Частичные функторы/аппликативы/комонады      | `import alleycats.Pure.*`         |
| **EmptyK**         | Пустые контейнеры (аналог MonoidK)           | `import alleycats.EmptyK.*`       |
| `Set[_]`           | Монада и обход для множеств                  | `import alleycats.std.set.*`      |
| `Try[_]`           | Монада для Try                               | `import alleycats.std.try_.*`     |
| `Iterable[_]`      | Свёртка для Iterable                         | `import alleycats.std.iterable.*` |
