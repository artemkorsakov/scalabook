# CountDownLatch — Ожидание заданного количества событий

`CountDownLatch[F[_]]` — это **одноразовый примитив синхронизации**, 
который позволяет одному или нескольким волокнам **блокироваться** до тех пор, 
пока не произойдёт заданное количество событий (освобождений защёлок). 
После достижения нуля все ожидающие волокна разблокируются, и дальнейшие вызовы `await` не блокируются.

**Аналогия:** Представьте себе забег на 100 метров с тремя участниками. 
Главный судья не даст старт, пока **все три бегуна** не будут на линии старта. 
Каждый подошедший бегун "освобождает" одну защёлку. 
Когда подошли все трое — защёлка открывается, и судья даёт команду "старт!".

```
Инициализация: n = 3
[Защёлка открыта? НЕТ]
    ↓
Бегун 1 подошёл → release() → n = 2
Бегун 2 подошёл → release() → n = 1
Бегун 3 подошёл → release() → n = 0
    ↓
[Защёлка открыта!] → все ожидающие (судья) пробуждаются
```

```dotty
trait CountDownLatch[F[_]]:
  /** Уменьшает счётчик защёлок на 1. Если счётчик достигает 0, пробуждает все
    * ожидающие волокна.
    */
  def release: F[Unit]

  /** Блокирует текущее волокно, пока счётчик защёлок не станет 0. Если счётчик
    * уже 0, возвращается немедленно.
    */
  def await: F[Unit]
```

**Ключевые характеристики:**

- **Одноразовый** — после того как счётчик достиг 0, его нельзя сбросить или увеличить снова.
- **Накопительный** — не важно, какое волокно вызывает `release`, важен общий счётчик.
- **Отменяемый** — волокно, ожидающее на `await`, можно отменить, и оно будет удалено из очереди ожидания.

## Создание `CountDownLatch`

```dotty
import cats.effect.IO
import cats.effect.std.CountDownLatch

val latch: IO[CountDownLatch[IO]] = CountDownLatch[IO](3) // ждём 3 события
```

Параметр `n` должен быть **положительным целым числом**. 
Если передать 0, защёлка считается сразу открытой, и `await` никогда не блокируется.

## Подробный пример: Координация трёх рабочих

В этом примере главное волокно ждёт, пока три рабочих не сообщат о своей готовности.

```dotty
import cats.effect.{IO, IOApp}
import cats.effect.std.CountDownLatch
import scala.concurrent.duration.*
import cats.syntax.all.*

object LatchDemo extends IOApp.Simple:
  val run: IO[Unit] =
    for
      latch <- CountDownLatch[IO](3) // ждём 3 события

      // Запускаем 3 рабочих волокна
      _ <- (1 to 3).toList.traverse { id =>
        val worker =
          for
            _ <-
              IO.sleep((id * 500).millis) // каждый рабочий трудится своё время
            _ <- IO.println(s"Рабочий $id: готов!")
            _ <- latch.release // сигнализируем о готовности
          yield ()
        worker.start
      }

      // Главное волокно ждёт всех
      _ <- IO.println("Главный: ожидаю всех рабочих...")
      _ <- latch.await // блокируется, пока 3 release не вызваны
      _ <- IO.println("Главный: все готовы! Начинаем работу!")
    yield ()
end LatchDemo
```

**Вывод:**

```
Главный: ожидаю всех рабочих...
Рабочий 1: готов!
Рабочий 2: готов!
Рабочий 3: готов!
Главный: все готовы! Начинаем работу!
```

**Что произошло:**

- Главное волокно вызывает `await` и блокируется.
- Три рабочих по очереди завершаются и вызывают `release`.
- После третьего `release` счётчик становится 0, главное волокно пробуждается.

## Отмена ожидания

`await` полностью поддерживает отмену. Если ожидающее волокно отменяется, оно корректно удаляется из очереди, и **счётчик защёлок не изменяется**.

```dotty
import cats.effect.IO
import cats.effect.std.CountDownLatch
import scala.concurrent.duration.*

val program =
  for
    latch <- CountDownLatch[IO](2)

    // Волокно, которое будет отменено
    fiber <-
    (IO.println("Начинаю ждать...") *> latch.await *>
      IO.println("Никогда не напечатаюсь")).start
    _ <- IO.sleep(1.second)
    _ <- IO.println("Отменяю ожидание!")
    _ <- fiber.cancel // волокно отменяется, защёлка не освобождена

    // Проверяем: защёлка всё ещё ждёт 2 события
    _ <- latch.release // one
    _ <- IO.println("Первый release")
    _ <- latch.release // two
    _ <- IO.println("Второй release")
  yield ()
```

**Вывод:**

```
Начинаю ждать...
Отменяю ожидание!
Первый release
Второй release
```

## Пример: несколько ожидающих волокон

Если несколько волокон вызывают `await` до того, как защёлка открыта, **все они** будут разбужены, когда счётчик достигнет 0.

```dotty
import cats.effect.IO
import cats.effect.std.CountDownLatch

val program =
  for
    latch <- CountDownLatch[IO](1)

    // 5 волокон ждут одно событие
    fibers <- (1 to 5).toList.traverse { id =>
      (IO.println(s"  Волокно $id: жду...") *> latch.await *>
        IO.println(s"  Волокно $id: проснулось!")).start
    }

    _ <- IO.sleep(1.second)
    _ <- IO.println("Открываю защёлку!")
    _ <- latch.release // → пробуждаются ВСЕ 5 волокон
    _ <- fibers.traverse_(_.join)
  yield ()
```

**Вывод:** 

```
  Волокно 1: жду...
  Волокно 2: жду...
  Волокно 3: жду...
  Волокно 4: жду...
  Волокно 5: жду...
Открываю защёлку!
  Волокно 4: проснулось!
  Волокно 1: проснулось!
  Волокно 3: проснулось!
  Волокно 5: проснулось!
  Волокно 2: проснулось!
```

## Сравнение с другими примитивами

| Примитив                 | Механизм                   | Одноразовый?                        | Кол-во ожидаемых событий     | Пробуждает              |
|:-------------------------|:---------------------------|:------------------------------------|:-----------------------------|:------------------------|
| **`CountDownLatch`**     | Счётчик, уменьшаемый до 0  | ✅ Да                                | `n` (задаётся при создании)  | Всех ожидающих          |
| **`CyclicBarrier`**      | Счётчик, после 0 — сброс   | ❌ Нет (циклический)                 | `n` (задаётся при создании)  | Всех ожидающих          |
| **`Deferred[F, Unit]`**  | Однократный сигнал         | ✅ Да                                | 1                            | Всех ожидающих          |
| **`Semaphore(0)`**       | Разрешения                 | ❌ Нет (можно `release` много раз)   | Переменное                   | По одному на `release`  |
| **`Queue`**              | Очередь элементов          | ❌ Нет                               | Переменное                   | По одному на `take`     |

**Ключевые отличия `CountDownLatch`:**

- Требует **чётко заданного количества** событий (в отличие от `Deferred[Unit]`).
- Пробуждает **всех** ожидающих одновременно (в отличие от `Semaphore`).
- **Не циклический** (в отличие от `CyclicBarrier`).

## Ограничения и подводные камни

### 1. Слишком много `release` не вредят

Если вызвать `release` больше `n` раз, лишние вызовы игнорируются. Это безопасно, но может скрывать логические ошибки.

```dotty
for
  latch <- CountDownLatch[IO](2)
  _     <- latch.release // n=1
  _     <- latch.release // n=0, открыто
  _     <- latch.release // игнорируется (n остаётся 0)
  _     <- latch.await   // немедленный возврат
yield ()
```

### 2. `n == 0` — специальный случай

`CountDownLatch[IO](0)` сразу открыт, `await` не блокируется. Используйте это осторожно.

### 3. Отмена `await` не уменьшает счётчик

Если волокно отменяется во время ожидания, это **не** вызывает `release`. 
Счётчик остаётся неизменным, и система продолжит ждать другие `release`.

### 4. Нельзя сбросить после достижения 0

В отличие от `CyclicBarrier`, `CountDownLatch` нельзя использовать повторно. 
Если нужно циклическое поведение, используйте [CyclicBarrier](cyclic-barrier.md).

## Итог: когда использовать `CountDownLatch`?

✅ **Используйте `CountDownLatch`, если:**

- Нужно, чтобы одно или несколько волокон **подождали, пока несколько независимых событий** не произойдут.
- Вы заранее знаете **точное количество** событий (`n`).
- Вы хотите, чтобы все ожидающие **проснулись одновременно**.
- Вам нужен **одноразовый** механизм (нет необходимости сбрасывать).

❌ **Не используйте `CountDownLatch`, если:**

- Нужно ожидать **бесконечное или неизвестное** количество событий (используйте `Deferred` или `Queue`).
- Нужно **циклическое** поведение (используйте `CyclicBarrier`).
- Вам нужно ограничить параллелизм (используйте `Semaphore`).
- Вам нужен **обмен сообщениями** (используйте `Queue`).

**Ключевая идея:** `CountDownLatch` — это идеальный инструмент для сценария "главный ждёт, пока все подготовятся". 
Он лёгок, понятен и точно выражает намерение: дождаться `n` событий, а затем продолжить.
