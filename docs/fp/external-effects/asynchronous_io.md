# Неблокируемый и асинхронный ввод-вывод

Теперь обратимся к последней оставшейся проблеме нашей исходной `IO` монады: 
выполнению **неблокирующего (асинхронного) ввода-вывода**. 

В программировании ввод-вывод (I/O) часто связан с операциями, 
которые могут длительное время ждать внешних данных или устройств, но не загружают процессор. 
Например:

- чтение из файла,
- чтение из сетевого сокета,
- запись больших объёмов данных.

Если такие операции выполняются в **блокирующем режиме**, поток выполнения программы будет ожидать завершения операции, 
что может привести к потере производительности. 
Особенно это критично в многопользовательских системах, где нужно обслуживать множество одновременных запросов.

## Асинхронность через `Free`

С использованием [свободных монад](free_monad.md) (`Free[F, A]`) мы можем абстрагировать операции ввода-вывода от их реализации. 
Это позволяет нам писать чистые функции, которые описывают последовательность действий, 
но не зависят от конкретного способа их выполнения.

### Пример: интерпретатор для `Console`

Предположим, у нас есть программа, которая взаимодействует с консолью:

```dotty
def p: Free[Console, Unit] =
  for
    _ <- printLn("What's your name?")
    n <- readLn
    _ <- n match
      case Some(n) => printLn(s"Hello, $n!")
      case None => printLn(s"Fine, be that way.")
  yield ()
```

Эта программа имеет тип `Free[Console, Unit]`, то есть она описывает последовательность консольных операций, 
но не выполняет их сразу. Чтобы её запустить, нам нужен интерпретатор.

#### Синхронный интерпретатор (`Function0`)

Если мы хотим выполнить эту программу синхронно, то можем использовать интерпретатор, который переводит `Console[A]` в `() => A`:

```dotty
val q = p.toThunk
q() // Выполняет программу синхронно
```

Однако такой подход блокирует поток выполнения на время ожидания ввода или вывода.

#### Асинхронный интерпретатор (`Par`)

Чтобы сделать программу асинхронной, мы можем использовать монаду `Par`, которая поддерживает параллельное и неблокирующее выполнение:

```dotty
val q = p.toPar
```

Здесь `toPar` — это функция, которая преобразует `Free[Console, A]` в `Par[A]`. 
Это достигается с помощью метода `runFree`, который принимает функцию перевода `Console[A]` в `Par[A]`.

### Как работает `runFree`

Метод `runFree` обобщает интерпретацию `Free[F, A]` в другую монаду `G`, 
если у нас есть способ перевести `F[x]` в `G[x]`. Вот его сигнатура:

```dotty
def runFree[G[_]](t: [x] => F[x] => G[x])(using G: Monad[G]): G[A]
```

Пример использования:

```dotty
def toPar(x: Console[x]): Par[x] = x match
  case ReadLine        => Par.lazyUnit(Try(readLine()).toOption)
  case PrintLine(line) => Par.lazyUnit(println(line))

val q = p.runFree(toPar)
```

Таким образом, `Free[Console, A]` становится `Par[A]`, и его можно выполнять асинхронно, 
используя механизм распределённого вычисления от `Par`.

### Неблокирующий ввод-вывод

Для реального асинхронного I/O, мы должны использовать библиотеки, которые предоставляют неблокирующие операции. 
Например, рассмотрим интерфейс для неблокирующего источника данных:

```dotty
trait Source:
  def readBytes(
      numBytes: Int,
      callback: Either[Throwable, Array[Byte]] => Unit
  ): Unit
```

Здесь `readBytes` не блокирует поток выполнения. 
Вместо этого он принимает обратный вызов, который вызывается, когда данные становятся доступны или при ошибке. 
Такие операции идеально подходят для асинхронного программирования.

#### Интеграция с `Free`

Чтобы интегрировать неблокирующий I/O в нашу программу, 
мы можем создать тип, который описывает возможные операции с `Source`:

```dotty
enum FileIO[A]:
  case Read(numBytes: Int)      extends FileIO[Array[Byte]]
  case Write(data: Array[Byte]) extends FileIO[Unit]
```

Затем мы можем использовать `Free[FileIO, A]` для описания программ, которые работают с файлами. 
Для интерпретации таких программ, мы создаем функцию перевода `FileIO` в `Par`:

```dotty
def fileToPar(x: FileIO[x]): Par[x] = x match
  case Read(n) =>
    val buffer = new Array[Byte](n)
    // Пример, должен быть заменен на реальный асинхронный вызов
    Par.lazyUnit(buffer)
  case Write(data) =>
    Par.lazyUnit(()) // Аналогично
```

Используя `runFree`, мы получаем программу в виде `Par[A]`, которую можно запускать асинхронно.

### Преимущества асинхронного I/O

1. **Производительность**: Потоки не блокируются ожиданием I/O, что позволяет эффективно использовать ресурсы.
2. **Гибкость**: Программы остаются чистыми и легко тестируемыми, так как эффекты отделены от логики.
3. **Расширяемость**: Можно легко добавлять новые виды I/O, просто меняя интерпретатор.

### Заключение

Использование свободных монад (`Free`) позволяет абстрагировать операции ввода-вывода от их реализации. 
Это делает программы более чистыми, тестируемыми и гибкими. 
С помощью интерпретаторов мы можем запускать такие программы как синхронно, 
так и асинхронно, подключаясь к различным библиотекам и системам I/O.

## Абстракция над асинхронным вводом-выводом с использованием `Par` и `Free`

Когда мы говорим о неблокирующих (асинхронных) операциях ввода-вывода таких, как чтение из файла или сетевого потока, 
важно не только эффективно использовать ресурсы системы, но и сохранять чистоту и композируемость программ. 
Прямое использование библиотек, таких как `java.nio`, может быть сложным, 
так как они часто работают с обратными вызовами (callbacks), 
что затрудняет их интеграцию в структурированные функциональные программы.

### Зачем абстрагироваться от деталей реализации?

Работать с низкоуровневыми API напрямую — это сложно, 
особенно если мы хотим создавать чистые, тестируемые и повторно используемые программы. 
Мы хотим:

- **Использовать монадический интерфейс**, чтобы удобно комбинировать операции.
- **Абстрагироваться от конкретной реализации** неблокирующего I/O.
- **Поддерживать асинхронность**, чтобы не блокировать поток выполнения.

Для этого мы можем использовать тип `Par`, который представляет собой параллельное вычисление, 
и `Free[F, A]`, позволяющая моделировать последовательность действий как дерево, 
которое можно интерпретировать различными способами.

### Что такое `Par` и как он работает?

`Par` — это абстракция для [параллельных вычислений](../parallelism.md). Он определяется следующим образом:

```dotty
opaque type Future[+A] = (A => Unit) => Unit
opaque type Par[+A] = ExecutorService => Future[A]
```

- `Future[A]` — это функция, которая принимает обработчик завершения (`A => Unit`) и возвращает результат, когда он становится доступен.
- `Par[A]` — это функция, которая принимает `ExecutorService` и возвращает `Future[A]`. 
- Это позволяет нам выполнять вычисления в фоновых потоках.

Таким образом, `Par` позволяет моделировать асинхронные вычисления, 
которые могут быть запущены в параллели и не блокируют основной поток.

### Адаптация асинхронных API к `Par`

Многие библиотеки I/O такие, как `java.nio`, используют модель на основе обратных вызовов. 
Например, метод `readBytes` может выглядеть так:

```dotty
trait Source:
  def readBytes(numBytes: Int, callback: Either[Throwable, Array[Byte]] => Unit): Unit
```

Это означает, что мы передаем функцию (`callback`), которая будет вызвана, когда данные будут доступны или произойдет ошибка.

Чтобы интегрировать такой API с `Par`, мы можем использовать вспомогательный метод `async`, 
преобразующий обратный вызов в `Par`:

```dotty
def async[A](f: (A => Unit) => Unit): Par[A] =
  es => cb => f(cb)
```

Теперь мы можем "оборачивать" асинхронные операции в `Par`, чтобы использовать их в чистом функциональном стиле.

### Обёртка для `Source.readBytes`

Предположим у нас есть источник данных `Source`, и мы хотим прочитать из него `numBytes` байтов. 
Мы можем определить функцию `nonblockingRead`, которая возвращает `Par`:

```dotty
def nonblockingRead(source: Source, numBytes: Int): Par[Either[Throwable, Array[Byte]]] =
  async: (cb: Either[Throwable, Array[Byte]] => Unit) =>
    source.readBytes(numBytes, cb)
```

Теперь, чтобы использовать это в контексте `Free`, мы можем создать функцию `readPar`, 
оборачивающую `nonblockingRead` в `Suspend`, 
чтобы его можно было использовать как шаг в программе `Free[Par, A]`:

```dotty
def readPar(source: Source, numBytes: Int): Free[Par, Either[Throwable, Array[Byte]]] =
  Suspend(nonblockingRead(source, numBytes))
```

Теперь мы можем строить цепочки асинхронных операций с помощью `for-comprehension`, как будто они работают с обычной монадой:

```dotty
val src: Source = ...
val prog: Free[Par, Unit] =
  for
    chunk1 <- readPar(src, 1024)
    chunk2 <- readPar(src, 1024)
  yield ()
```

Эта программа описывает две асинхронные операции чтения из источника `src`.


### Реализация асинхронного чтения из файла

Для примера, давайте рассмотрим, как мы можем использовать `AsynchronousFileChannel` 
из библиотеки `java.nio` для асинхронного чтения из файла.

#### Шаги реализации

1. Создаем `ByteBuffer`, куда будут записаны данные.
2. Используем `file.read(...)` с обработчиком завершения.
3. В случае успешного чтения — вызываем `cb(Right(arr))`.
4. В случае ошибки — вызываем `cb(Left(err))`.

Вот реализация функции `read`:

```dotty
import java.nio._
import java.nio.channels._

def read(
    file: AsynchronousFileChannel,
    fromPosition: Long,
    numBytes: Int
): Free[Par, Either[Throwable, Array[Byte]]] =
  Suspend(
    Par.async: (cb: Either[Throwable, Array[Byte]] => Unit) =>
      val buf = ByteBuffer.allocate(numBytes)
      file.read(
        buf,
        fromPosition,
        (),
        new CompletionHandler[Integer, Unit]:
          def completed(bytesRead: Integer, ignore: Unit): Unit =
            // Сдвигаем буфер, чтобы получить только прочитанные данные
            buf.flip()
            val arr = new Array[Byte](bytesRead)
            buf.get(arr, 0, bytesRead)
            cb(Right(arr))

          def failed(err: Throwable, ignore: Unit): Unit =
            cb(Left(err))
      )
  )
```

#### Как это работает?

- `Par.async` принимает функцию, которая получает `cb` — обработчик завершения.
- Мы вызываем `file.read(...)`, передавая `buf` и `CompletionHandler`.
- В методе `completed` мы извлекаем прочитанные данные и передаем их через `cb`.
- В методе `failed` мы передаем ошибку через `cb`.

Таким образом, `Par` значение, созданное внутри `Par.async`, завершается, когда вызывается обработчик завершения.

### Почему это полезно?

- **Чистота**: Наша программа отделена от реализации эффектов.
- **Композиция**: Мы можем легко комбинировать асинхронные операции.
- **Гибкость**: Мы можем изменить интерпретацию программы (например, заменить реальное чтение файла на симуляцию).
- **Производительность**: Операции выполняются асинхронно и не блокируют поток.

### Итог

Использование `Par` и `Free` позволяет абстрагироваться от деталей реализации асинхронных операций ввода-вывода. 
Это делает наши программы более чистыми, тестируемыми и гибкими. 
Мы можем легко комбинировать асинхронные действия с помощью `for-comprehension`, 
а также использовать готовые библиотеки, такие как `java.nio`, с минимальными усилиями.

## Составление свободных алгебр

В предыдущих разделах мы изучали, как использовать `Free[F, A]` для абстракции над различными эффектами, 
такими как ввод-вывод (`IO`, `Console`) и параллельные вычисления (`Par`). 
Однако часто возникает необходимость комбинировать несколько различных алгебр — 
например, работать с файловой системой и консолью одновременно. 
Ниже мы рассмотрим, как можно составлять свободные алгебры и объединять их в одну программу.

### Что такое "свободная алгебра"?

Свободная алгебра — это способ описания набора примитивных операций (например, чтение или запись), 
которые могут быть выполнены, но не выполняются сразу. 
Она определяется через алгебраический тип данных (enum) и моделируется с помощью `Free[F, A]`.

Например, для работы с консолью мы можем определить:

```dotty
enum Console[A]:
  case ReadLine                extends Console[Option[String]]
  case PrintLine(line: String) extends Console[Unit]

object Console:
  def readLn: Free[Console, Option[String]] = Free.Suspend(ReadLine)

  def printLn(line: String): Free[Console, Unit] =
    Free.Suspend(PrintLine(line))
```

Также мы можем создать аналогичную алгебру для работы с файлами:

```dotty
enum Files[A]:
  case ReadLines(file: String) extends Files[List[String]]
  case WriteLines(file: String, lines: List[String]) extends Files[Unit]

object Files:
  def readLines(file: String): Free[Files, List[String]] = 
    Free.Suspend(ReadLines(file))
    
  def writeLines(file: String, lines: List[String]): Free[Files, Unit] =
    Free.Suspend(WriteLines(file, lines))
```

Каждый из этих типов позволяет описывать последовательности операций, но они **независимы** друг от друга. 
Проблема возникает, когда нам нужно **объединить** программы, использующие разные алгебры.

### Проблема: Невозможность смешивания разных алгебр

Предположим, мы хотим написать утилиту `cat`, которая читает строки из файла и выводит их на консоль:

```dotty
def cat(file: String): Free[Files, Unit] =
  for
    lines <- Files.readLines(file)
    _     <- Console.printLn(lines.mkString("\n"))
  yield ()
```

Эта программа не скомпилируется! Ошибка будет примерно такой:

```
Found:    Free[Console, Unit]
Required: Free[Files, Unit]
```

Причина в том, что `Files.readLines(file)` возвращает значение типа `Free[Files, List[String]]`, 
а `Console.printLn(...)` возвращает `Free[Console, Unit]`. 
Но `Free[Console, Unit]` **не является подтипом** `Free[Files, Unit]`. 
Таким образом, Scala не может понять, как их объединить.

### Решение: Объединение алгебр

Чтобы решить эту проблему, мы можем использовать **объединение алгебр**. 
То есть, мы создаём новый тип, который включает в себя операции из обеих алгебр. 
В Scala 3 это делается с помощью **типов объединения**.

#### Шаг 1: Создание объединённой алгебры

Мы хотим создать новую алгебру, которая содержит все операции из `Console` и `Files`. 
Для этого мы объявляем обобщённый тип `[x] =>> Console[x] | Files[x]`, где `|` обозначает объединение.

#### Шаг 2: Использование метода `union`

Предоставим возможность преобразовать `Free[F, A]` в `Free[[x] =>> F[x] | G[x], A]`, используя метод `union`. 
Это позволяет нам **поднимать** значения из одной алгебры в объединённую.

Определение метода `union` выглядит следующим образом:

```dotty
enum Free[+F[_], A]:
  ...
  def union[G[_]]: Free[[x] =>> F[x] | G[x], A] = this match
    case Return(a) => Return(a)
    case Suspend(s) => 
      // s имеет тип F[A], поэтому мы можем приписать тип F[A] | G[A]
      Suspend(s: F[A] | G[A])
    case FlatMap(s, f) => 
      // Распространяем объединение через оба аргумента FlatMap
      FlatMap(s.union, a => f(a).union)
```

#### Шаг 3: Переписываем `cat` с использованием `union`

Теперь мы можем переписать функцию `cat`, используя `union`, чтобы объединить `Files` и `Console`:

```dotty
def cat(file: String): Free[[x] =>> Files[x] | Console[x], Unit] =
  for
    lines <- Files.readLines(file).union
    _     <- Console.printLn(lines.mkString("\n")).union
  yield ()
```

Здесь каждое выражение, возвращающее `Free[Console, ...]` или `Free[Files, ...]`, 
преобразуется в `Free[[x] =>> Files[x] | Console[x], ...]` с помощью `.union`.

### Преимущества объединения алгебр

1. **Гибкость**: Мы можем писать программы, использующие несколько эффектов.
2. **Чистота**: Все эффекты остаются отделены от логики программы.
3. **Разделение ответственности**: Каждая алгебра описывает свою собственную область.
4. **Легкость интерпретации**: Мы можем написать интерпретаторы для каждой алгебры по отдельности.

## Улучшение составления свободных программ с ковариантностью и `union`

В предыдущем пункте мы рассмотрели, как объединять разные алгебры (например, `Console` и `Files`) 
в рамках одного типа `Free`, чтобы создавать программы, которые могут использовать несколько эффектов. 
Однако, при этом возникала необходимость вручную вызывать метод `union` для каждого шага программы — 
это делало код неудобным и трудновыводимым.

Теперь мы увидим, как можно улучшить ситуацию с помощью **ковариантности** и корректного определения метода `flatMap`. 
Это позволит нам писать более чистый и удобный код, без необходимости явно вызывать `union`.

### Проблема: Необходимость ручного вызова `union`

Рассмотрим функцию `cat`, которая читает файл и выводит его содержимое на консоль:

```dotty
def cat(file: String) =
  Files.readLines(file).union[Console].flatMap: lines =>
    Console.printLn(lines.mkString("\n")).union[Files]
```

Этот код работает, но он выглядит сложным и требует вручную вызывать `.union` для каждого выражения. 
Почему так происходит?

Причина в том, что тип `Free[F, A]` по умолчанию **не является ковариантным** по параметру `F`. 
То есть, если у нас есть `Free[Console, A]`, мы не можем напрямую использовать его там, 
где ожидается `Free[[x] =>> Console[x] | Files[x], A]`. 
Поэтому мы должны вручную преобразовать тип с помощью `union`.

### Решение: Ковариантность и правильное определение `flatMap`

Чтобы избежать ручного вызова `union`, мы можем воспользоваться **ковариантностью**. 
Если мы объявим `Free` как ковариантный по параметру `F`, 
то `Free[F, A]` станет подтипом `Free[G, A]`, если `F` является подтипом `G`.

#### Объявление ковариантности

Мы объявляем `Free` следующим образом:

```dotty
enum Free[+F[_], A]:
  case Return(a: A) extends Free[Nothing, A]
  case Suspend(s: F[A])
  case FlatMap[F2[_], A, B](
    s: Free[F2, A],
    f: A => Free[F2, B]) extends Free[F2, B]

  def flatMap[F2[x] >: F[x], B](f: A => Free[F2, B]): Free[F2, B] =
    FlatMap(this, f)
```

Здесь:

- `+F[_]` говорит Scala, что `F` является ковариантным.
- В `FlatMap` мы добавляем параметр `F2[x] >: F[x]`, 
  который позволяет `flatMap` возвращать `Free[F2, B]`, где `F2` — супертип `F`.

#### Почему это важно?

Ковариантность позволяет автоматически превращать `Free[F, A]` в `Free[G, A]`, если `F` является подтипом `G`. 
Например, `Free[Console, A]` будет подтипом `Free[[x] =>> Console[x] | Files[x], A]`.

Благодаря этому, мы больше **не будем нуждаться в вызове `union` вручную**. 
Просто используем `Free` как обычно, и Scala сама будет делать необходимые преобразования.

### Упрощение `union` и введение `covary`

С ковариантностью `Free` становится проще определять метод `union`. Теперь он может быть просто:

```dotty
enum Free[+F[_], A]:
  ...
  def union[G[_]]: Free[[x] =>> F[x] | G[x], A] = this
```

Это возможно потому, что `Free[F, A]` уже является подтипом `Free[[x] =>> F[x] | G[x], A]`, 
и нет необходимости выполнять дополнительные преобразования.

Дополнительно можно ввести операцию `covary`, которая позволяет указывать супертип `F2`, 
не повторяя весь тип выражения:

```dotty
enum Free[+F[_], A]:
  ...
  def covary[F2[x] >: F[x]]: Free[F2, A] = this
```

Это просто синтаксический сахар. Например, вместо:

```dotty
Files.readLines("file.txt").union[Console]
```

мы могли бы написать:

```dotty
Files.readLines("file.txt").covary[[x] =>> Console[x] | Files[x]]
```

Однако, благодаря ковариантности, даже это не обязательно — 
достаточно просто использовать `Free` в контексте, где требуется объединённый тип.

### Переписываем `cat` без `union`

Теперь, когда у нас есть ковариантная версия `Free`, мы можем переписать функцию `cat` без использования `union`:

```dotty
def cat(file: String): Free[[x] =>> Files[x] | Console[x], Unit] =
  for
    lines <- Files.readLines(file)
    _     <- Console.printLn(lines.mkString("\n"))
  yield ()
```

Заметим:

- Мы больше не вызываем `.union`.
- Мы не изменяем сигнатуру `Files.readLines` или `Console.printLn`.
- Мы явно указываем тип возврата `cat`, поскольку Scala не выводит тип объединения автоматически.

### Почему это работает?

Работает всё благодаря тому, что:

1. `Free[F, A]` теперь ковариантен по `F`.
2. `Files.readLines(file)` возвращает `Free[Files, List[String]]`.
3. `Console.printLn(...)` возвращает `Free[Console, Unit]`.
4. Поскольку `Free[Files, ...]` и `Free[Console, ...]` являются подтипами `Free[[x] =>> Files[x] | Console[x], ...]`, 
   их можно использовать вместе в одной программе без ручного преобразования.

### Заключение

Ковариантность и правильное использование `flatMap` позволяют значительно упростить работу 
с несколькими алгебрами в рамках одного `Free`. Теперь:

- Нет необходимости вызывать `union` вручную.
- Программы становятся более чистыми и легче читаются.
- Scala помогает в автоматическом выводе типов, особенно если мы явно указываем типы возвращаемых значений.

Это делает `Free` ещё более мощным инструментом для моделирования эффектов в функциональном программировании.

### Упражнение 9.4.1: Определение `step` для `Free[+F[_], A]`

> [Репозиторий с упражнениями и инструкцией по выполнению][sample]

Доработайте метод `step` для ковариантного типа `Free[+F[_], A]`. 
Метод `step` используется для упрощения структуры `Free`, чтобы избежать вложенных `FlatMap`. 

```dotty
final def step: Free[F, A] = ???
```

@:note(🔍 Показать решение)

Метод `step` упрощает структуру `Free`, объединяя вложенные `FlatMap`, чтобы избежать их накопления. 
В ковариантной версии `Free[+F[_], A]` он обрабатывает случаи, когда `FlatMap` вложен в другой `FlatMap` 
или следует за `Return`, преобразуя их в более простую форму с помощью `flatMap`. 
При этом используется `covary`, чтобы сохранить корректность типов при переходе между алгебрами.

```dotty
@annotation.tailrec
final def step: Free[F, A] = this match
  case FlatMap(FlatMap(fx, f), g) =>
    fx.flatMap(x => f(x).flatMap(y => g(y).covary[F])).step
  case FlatMap(Return(x), f) => f(x).step
  case _                     => this
```

@:@

### Упражнение 9.4.2: Определение `run` для `Free[+F[_], A]`

Реализуйте метод `run` для `Free[+F[_], A]`. Этот метод выполняет программу `Free[F, A]` в контексте монады `F2`.

```dotty
def run[F2[x] >: F[x]](using F: Monad[F2]): F2[A] = ???
```

@:note(🔍 Показать решение)

Метод `run` выполняет программу `Free[F, A]`, используя монаду `F2`, которая является супертипом `F`. 
Он работает с упрощённой версией программы после вызова `step`: 
если программа завершена (`Return`), возвращает результат; 
если содержит `Suspend`, возвращает соответствующее значение; 
если начинается с `FlatMap(Suspend(...), ...)`, он выполняет `flatMap` и рекурсивно продолжает выполнение. 
Вложенные `FlatMap` должны быть исключены благодаря `step`, поэтому `sys.error` невозможен.

```dotty
def run[F2[x] >: F[x]](using F: Monad[F2]): F2[A] = step match
  case Return(a)               => F.unit(a)
  case Suspend(fa)             => fa
  case FlatMap(Suspend(fa), f) => fa.flatMap(a => f(a).run)
  case FlatMap(_, _) =>
    sys.error("Impossible, since `step` eliminates these cases")
```

@:@

### Упражнение 9.4.3: Определение `runFree` для `Free[+F[_], A]`

Реализуйте метод `runFree[G[_]]`, который позволяет интерпретировать `Free[F, A]` в другой монаде `G`, 
если у нас есть способ перевести `F[x]` в `G[x]`.

```dotty
def runFree[G[_]](t: [x] => F[x] => G[x])(using G: Monad[G]): G[A] = ???
```

@:note(🔍 Показать решение)

Метод `runFree` интерпретирует программу `Free[F, A]` в другой монаде `G`, 
используя функцию `t`, которая переводит `F[x]` в `G[x]`. 
Он обрабатывает упрощённую структуру после `step`: если программа завершена (`Return`), возвращает результат; 
если содержит `Suspend`, применяет `t`; если начинается с `FlatMap(Suspend(...), ...)`, 
рекурсивно продолжает выполнение через `flatMap`. 
Вложенные `FlatMap` исключаются благодаря `step`, поэтому `sys.error` невозможен.

```dotty
def runFree[G[_]](t: [x] => F[x] => G[x])(using G: Monad[G]): G[A] =
  step match
    case Return(a)  => G.unit(a)
    case Suspend(r) => t(r)
    case FlatMap(Suspend(r), f) =>
      t(r).flatMap[A](a => f(a).covary[F].runFree[G](t))
    case FlatMap(_, _) =>
      sys.error("Impossible, since `step` eliminates these cases")
```

@:@

## Запуск программы с несколькими алгебрами

Теперь, когда у нас есть `Free[[x] =>> Files[x] | Console[x], Unit]`, нам нужно определить, как его запустить. 
Для этого мы используем `runFree`, передавая функцию, которая интерпретирует каждую операцию.

```dotty
extension [A](fa: Free[[x] =>> Files[x] | Console[x], A])
  def toThunk: () => A =
    fa.runFree([x] => (fx: Files[x] | Console[x]) => fx match
      case c: Console[x] => c.toThunk
      case f: Files[x] => f.toThunk
    )
```

- Мы определяем расширение `toThunk` для `Free`, которое возвращает `() => A`.
- Внутри мы используем `runFree`, передавая функцию, которая:
    - Если получено значение типа `Console[x]`, использует `c.toThunk`.
    - Если получено значение типа `Files[x]`, использует `f.toThunk`.
- Таким образом, мы можем запустить программу, которая использует обе алгебры.
