# Чистые функции

## Определение и характеристики чистых функций

_Чистая функция_ — это фундаментальное понятие в функциональном программировании, означающее, что:

1. Результат функции зависит исключительно от её входных параметров (_детерминированность_)
2. Выполнение функции не вызывает _побочных эффектов_ (_side effects_)

**Побочный эффект** — это любое действие функции, выходящее за рамки простого возврата вычисленного значения, включая:

- Модификацию переменных (как локальных, так и глобальных)
- Изменение структур данных "на месте" (мутации)
- Обновление полей объектов
- Генерацию исключений или аварийное завершение
- Взаимодействие с внешним миром:
    - Ввод/вывод (консоль, файловая система)
    - Графические операции
    - Сетевые запросы
    - Работа с системным временем

## Формальная спецификация чистых функций

С математической точки зрения, чистая функция `f: A => B` представляет собой:

- Полное отображение из области определения (тип `A`) в область значений (тип `B`)
- Где каждому входному значению `a ∈ A` соответствует ровно одно выходное значение `b ∈ B`
- Причем значение `b` вычисляется исключительно на основе `a`, без учета:
    - Внутреннего состояния системы
    - Внешнего окружения
    - Времени выполнения

Это определение делает чистые функции аналогичными математическим функциям, где `f(x) = x²` всегда даст одинаковый результат для одинакового `x`.

## Ссылочная прозрачность: углубленный анализ

_Ссылочная прозрачность_ (_referential transparency_) — ключевое свойство функциональных программ, означающее что:

- Любое выражение может быть заменено его значением без изменения семантики программы
- Для одних и тех же аргументов результат всегда идентичен
- Не зависит от контекста выполнения или порядка вычислений

**Преимущества ссылочной прозрачности:**

1. **Проверка корректности**: Возможность формального доказательства правильности кода
2. **Упрощение рефакторинга**: Безопасная замена выражений на эквивалентные
3. **Оптимизации**:
    - Мемоизация (кэширование результатов)
    - Ленивые вычисления
    - Параллельное выполнение
4. **Предикативность**: Поведение программы становится полностью предсказуемым

В императивных языках большинство функций не являются ссылочно прозрачными из-за зависимостей от состояния.

## Упражнение 1.2.1: Идентификация чистых функций

> [Репозиторий с упражнениями и инструкцией по выполнению][sample]

Проанализируйте три реализации функции деления и выберите чистую версию:

```dotty
def pureFunction(a: Int, b: Int): Int =
  def innerFirst(a: Int, b: Int): Int = a / b

  def innerSecond(a: Int, b: Int): Int =
    if (b == 0) Int.MaxValue else a / b

  def innerThird(a: Int, b: Int): Int =
    require(b != 0, "Division by zero!")
    a / b

  // innerFirst(a, b)
  // innerSecond(a, b)
  // innerThird(a, b)
  ???
```

@:note(🔍 Показать решение)

Критерии анализа:

1. `innerFirst`:
    - Не чистая: при `b=0` генерирует исключение (побочный эффект)
    - Нарушает ссылочную прозрачность (разное поведение для `b=0`)
2. `innerSecond`:
    - Чистая: всегда возвращает значение
    - Детерминирована: одинаковые входы → одинаковые выходы
    - Нет побочных эффектов
3. `innerThird`:
    - Не чистая: `require` бросает `IllegalArgumentException`
    - Изменяет поток выполнения (побочный эффект)

Вывод: Только `innerSecond` удовлетворяет всем условиям чистоты:

- Полная обработка всех входных случаев
- Отсутствие исключений
- Независимость от внешнего состояния
