# Свободная монада

## Введение

Если мы используем `TailRec` в качестве нашего `IO` типа, то избегаем проблемы переполнения стека, 
но две другие проблемы все еще остаются:

1. `TailRec` **явно не указывает**, какие виды эффектов могут возникнуть.
2. У `TailRec` **нет механизма параллельности** или средств выполнения ввода-вывода без блокировки текущего потока.

Рассмотрим подробнее, как работает `TailRec`. 

### Проблемы интерпретации эффектов

При выполнении метода `run`, интерпретатор анализирует программу, представленную как `TailRec[A]`. 
Например, если программа выглядит так:

```dotty
FlatMap(Suspend(s), k)
```

интерпретатор выполняет следующие действия:

1. Вызывает `s()`, который представляет собой отложенное вычисление (`Function0[A]`: `() => A`).
2. Получает результат и передает его в продолжение `k`.
3. Результат `k` снова может быть `FlatMap`, и процесс повторяется.

Однако, интерпретатор **ничего не знает** о том, что именно делает `s()` — 
это может быть чтение файла, сетевой запрос, печать на консоль и т.д. 
Такое поведение делает программу **непрозрачной** для интерпретатора. 
Единственное, что он может сделать — это вызвать `s()` и дождаться результата.

Кроме того, интерпретатор **не может обрабатывать асинхронные эффекты**, потому что `s()` — это обычный синхронный вызов. 
Если бы мы хотели, чтобы наша программа поддерживала асинхронность, нам нужно было бы использовать другой подход.

## Асинхронные вычисления

Чтобы решить проблему асинхронности, можно заменить `Function0` на тип `Par[A]`, представляющий параллельное вычисление. 
Мы назовём такой тип `Async[A]`.

### Определение `Async`

```dotty
enum Async[A]:
  case Return(a: A)
  case Suspend(resume: Par[A])
  case FlatMap[A, B](sub: Async[A], k: A => Async[B]) extends Async[B]

  def flatMap[B](f: A => Async[B]): Async[B] =
    FlatMap(this, f)

  def map[B](f: A => B): Async[B] =
    flatMap(a => Return(f(a)))
```

Здесь `Suspend` принимает значение типа `Par[A]`, которое может быть выполнено асинхронно. 
Это позволяет интерпретатору запускать вычисления параллельно.

### Реализация `run`

Метод `run` теперь должен возвращать `Par[A]`, а не `A`. 
Также добавляется функция `step`, которая оптимизирует структуру программы перед выполнением:

```dotty
@annotation.tailrec
final def step: Async[A] = this match
  case FlatMap(FlatMap(x, f), g) => x.flatMap(a => f(a).flatMap(g)).step
  case FlatMap(Return(x), f)     => f(x).step
  case _                         => this

def run: Par[A] = step match
  case Return(a)  => Par.unit(a)
  case Suspend(r) => r
  case FlatMap(x, f) => x match
      case Suspend(r) => r.flatMap(a => f(a).run)
      case _ => sys.error("Impossible, since `step` eliminates these cases")
```

- **`step`**: упрощает структуру программы, разворачивая вложенные `FlatMap`.
- **`run`**: возвращает результат программы в виде `Par[A]`, что позволяет выполнять её асинхронно.

Таким образом, `Async` поддерживает **асинхронное выполнение** и **стекобезопасность**.

## Обобщение на свободную монаду

Хотя `Async` уже является хорошим решением, мы можем абстрагироваться дальше. 
Вместо фиксации на конкретном типе (например, `Function0` или `Par`), 
мы обобщим нашу конструкцию на любой конструктор эффекта `F`.

### Определение `Free`

```dotty
enum Free[F[_], A]:
  case Return(a: A)
  case Suspend(s: F[A])
  case FlatMap[F[_], A, B](s: Free[F, A], f: A => Free[F, B])
      extends Free[F, B]
 
  def flatMap[B](f: A => Free[F, B]): Free[F, B] =
    FlatMap(this, f)
 
  def map[B](f: A => B): Free[F, B] =
    flatMap(a => Return(f(a)))      
```

- **`Return`**: завершённое вычисление с результатом `a`.
- **`Suspend`**: приостановка, содержащая эффект `F[A]`.
- **`FlatMap`**: последовательное соединение двух вычислений.

Эта структура называется [**свободной монадой**][free] (Free Monad), 
поскольку она позволяет создавать программы, описывающие последовательность действий, 
без привязки к конкретной реализации этих действий.

### Псевдонимы типов

Теперь `TailRec` и `Async` можно выразить через `Free`:

```dotty
type TailRec[A] = Free[Function0, A]
type Async[A]   = Free[Par, A]
```

- **`TailRec`** использует `Function0` для описания эффектов.
- **`Async`** использует `Par` для поддержки асинхронности.

## Преимущества свободной монады

1. **Гибкость**:
    - Можно использовать любую реализацию эффекта (`Function0`, `Par`, `IO`, и т.д.).
    - Не зависим от конкретного способа выполнения эффектов.

2. **Прозрачность**:
    - Программа явно описывает свои эффекты через `Suspend`.
    - Интерпретатор может понимать и обрабатывать их.

3. **Стекобезопасность**:
    - Все рекурсивные вызовы находятся в хвостовой позиции.
    - Нет риска переполнения стека.

4. **Поддержка асинхронности**:
    - С помощью `Free[Par, A]` можно строить программы, которые работают в параллели.

5. **Интерпретируемость**:
    - Программу можно интерпретировать по-разному в зависимости от контекста (тестирование, логирование, реальное выполнение).

## Свободная монада

Свободная монада `Free[F[_], A]` предоставляет универсальный механизм для моделирования эффектов в функциональных программах. 
Она объединяет в себе:

- **Стекобезопасность** (через хвостовую рекурсию),
- **Асинхронность** (через выбор подходящего конструктора эффекта),
- **Гибкость** (поддержку различных реализаций эффектов).

Это делает `Free` мощным инструментом для построения сложных и надёжных функциональных приложений.

**Задание:**

`Free` является [монадой][monad] для любого выбора `F`.
Реализуйте методы `unit` и `flatMap` на перечислении `Free` и укажите экземпляр `Monad` для `Free[F, _]`.

```dotty
given freeMonad[F[_]]: Monad[[x] =>> Free[F, x]] with
  def unit[A](a: => A): Free[F, A] = ???
  extension [A](fa: Free[F, A])
    def flatMap[B](f: A => Free[F, B]): Free[F, B] = ???
```

Этот экземпляр делает `Free[F, _]` полноценной монадой, что позволяет использовать её в функциональных цепочках, 
for-нотации и других конструкциях, требующих монадического поведения.

@:note(🔍 Показать решение)

Метод `unit` должен принимать значение `A` и возвращать `Free[F, A]`, 
которое завершается сразу же, не вызывая никаких эффектов. 
Для этого используется конструктор `Return`.

Метод `flatMap` должен принимать `Free[F, A]` и функцию `A => Free[F, B]`, 
и возвращать новое `Free[F, B]`, представляющее последовательное выполнение двух шагов. 
Для этого используется конструктор `FlatMap`:

```dotty
object Free:
  given freeMonad[F[_]]: Monad[[x] =>> Free[F, x]] with
    def unit[A](a: => A): Free[F, A] = Return(a)

    extension [A](fa: Free[F, A])
      def flatMap[B](f: A => Free[F, B]): Free[F, B] = fa.flatMap(f)
```

### Упражнение 9.3.2: Реализация хвостово-рекурсивного интерпретатора `runTrampoline`

**Задание:**

Реализуйте специализированный хвостово-рекурсивный интерпретатор `runTrampoline` для запуска программы типа `Free[Function0, A]`. 
Этот интерпретатор должен безопасно выполнять программу, не вызывая переполнения стека.

```dotty
extension [A](fa: Free[Function0, A])
  @annotation.tailrec
  def runTrampoline: A = ???
```

@:note(🔍 Показать решение)

Метод `runTrampoline` реализуется с помощью рекурсивного сопоставления с шаблоном.
В зависимости от текущего состояния программы (`Return`, `Suspend`, или `FlatMap`),
мы выполняем соответствующие действия:

- Если текущий шаг — `Return(a)`, возвращаем результат `a`.
- Если текущий шаг — `Suspend(ta)`, вызываем функцию `ta()`.
- Если текущий шаг — `FlatMap(fx, f)`, анализируем `fx`:
    - Если `fx` — `Return(x)`, применяем `f(x)` и рекурсивно вызываем `runTrampoline`.
    - Если `fx` — `Suspend(tx)`, вызываем `tx()`, затем применяем `f` к результату.
    - Если `fx` — другой `FlatMap(fy, g)`, переассоциируем `flatMap` вправо, чтобы избежать вложенности, и продолжаем выполнение.

```dotty
extension [A](fa: Free[Function0, A])
  @annotation.tailrec
  def runTrampoline: A = fa match
    case Free.Return(a)   => a
    case Free.Suspend(ta) => ta()
    case Free.FlatMap(fx, f) => fx match
        case Free.Return(x)   => f(x).runTrampoline
        case Free.Suspend(tx) => f(tx()).runTrampoline
        case Free.FlatMap(fy, g) =>
          fy.flatMap(y => g(y).flatMap(f)).runTrampoline
```

### Упражнение 9.3.3: Реализация универсального интерпретатора `run` для `Free[F, A]`

**Задание:**

Реализуйте универсальный интерпретатор для типа `Free[F, A]`, который использует экземпляр `Monad[F]`. 
Этот интерпретатор должен преобразовывать программу `Free[F, A]` в вычисление типа `F[A]`. 
Используйте хвостово-рекурсивную функцию `step` для упрощения структуры программы перед выполнением.

```dotty
enum Free[F[_], A]:
  ...
 
  def run(using F: Monad[F]): F[A] = ???
 
  @annotation.tailrec
  final def step: Free[F, A] = ???
```

@:note(🔍 Показать решение step)

Метод `step` предназначен для упрощения структуры `Free[F, A]`, чтобы та содержала только базовые конструкторы.

```dotty
@annotation.tailrec
final def step: Free[F, A] = this match
  case FlatMap(FlatMap(fx, f), g) => fx.flatMap(x => f(x).flatMap(g)).step
  case FlatMap(Return(x), f)      => f(x).step
  case _                          => this
```

- Если мы встречаем вложенные `FlatMap`, то переассоциируем их вправо и повторно вызываем `step`.
- Если мы встречаем `FlatMap(Return(x), f)`, то применяем `f(x)` и продолжаем упрощение.
- Во всех остальных случаях возвращаем текущее значение, так как оно уже упрощено.

@:@

@:note(🔍 Показать решение run)

Метод `run` использует результат `step` для получения упрощённой версии программы и выполняет её с помощью `Monad[F]`.

```dotty
def run(using F: Monad[F]): F[A] = step match
  case Return(a) => F.unit(a)
  case Suspend(fa) => fa
  case FlatMap(Suspend(fa), f) => fa.flatMap(a => f(a).run)
  case FlatMap(_, _) =>
    sys.error("Impossible, `step` eliminates these cases")
```

- **`Return(a)`**: Возвращаем `F.unit(a)`, завершая вычисление.
- **`Suspend(fa)`**: Возвращаем сам `fa`, так как это уже значение `F[A]`.
- **`FlatMap(Suspend(fa), f)`**: Выполняем `fa` и связываем результат с продолжением `f`.
- **`FlatMap(_, _)`**: Невозможная ветка, так как `step` исключает такие случаи.
  Добавлено исключение для полноты сопоставления с шаблоном.

Этот интерпретатор:

1. Использует `step` для упрощения структуры программы.
2. Поддерживает выполнение программ через монаду `F`.
3. Гарантирует, что программа будет правильно интерпретирована, независимо от начальной формы.

@:@

## Итого: что такое `Free[F, A]`?

`Free[F, A]` — это универсальная структура данных в функциональном программировании, 
которая позволяет моделировать вычисления как последовательность операций. 
Она представляет собой **рекурсивное дерево**, где:

- **Корень** — текущий шаг вычисления.
- **Ветви** — описывают возможные действия или эффекты (через тип `F`).
- **Листья** — содержат результаты вычислений типа `A`.

Таким образом, можно представить `Free[F, A]` как **абстрактное синтаксическое дерево (AST)** программы, 
написанной на языке, где каждая инструкция определяется типом `F`, а переменные — типом `A`.

### Структура `Free[F, A]`

Тип `Free[F, A]` состоит из трёх основных конструкторов:

1. **`Return(a: A)`**  
   Это конечный шаг вычисления — "лист дерева".  
   Значение `a` — результат, который мы хотим получить.

2. **`Suspend(s: F[A])`**  
   Представляет приостановку вычисления.  
   Здесь `s` — значение типа `F[A]`, которое может быть выполнено позже.  
   Например, это может быть запрос к базе данных, чтение из файла и т.д.

3. **`FlatMap(s: Free[F, A], f: A => Free[F, B])`**  
   Описывает связывание двух шагов: сначала выполняется `s`, затем его результат передаётся в `f`, чтобы продолжить вычисление.  
   Это позволяет создавать цепочки действий.

### Почему `Free[F, A]` называется "свободной монадой"?

`Free[F, A]` является **монадой**, потому что реализует две ключевые операции:

- **`unit`** — создаёт начальное значение (`Return(a)`).
- **`flatMap`** — связывает два шага вычисления (`FlatMap`).

Именно благодаря этим операциям, `Free[F, A]` поддерживает композицию программ 
и может использоваться в функциональных конструкциях, таких как `for`-нотация, чистые цепочки вычислений и т.п.

Слово **"свободная"** здесь означает, что `Free[F, A]` не накладывает никаких ограничений на тип `F`. 
Это делает её очень гибкой: вы можете использовать любую структуру для описания эффектов, 
будь то `Function0`, `Par`, `IO`, или даже пользовательский тип, такой как `Console`.

### Как работает интерпретатор?

Чтобы получить результат из `Free[F, A]`, нужен **интерпретатор** — программа, которая обходит дерево и выполняет каждый шаг. 
Он должен уметь обрабатывать все слои `F`, которые могут встречаться в структуре.

Например, если `F` — это `Console`, то интерпретатор будет выполнять команды `ReadLine` и `PrintLine`. 
Если `F` — это `Par`, то он запускает параллельные вычисления.

### Протокол взаимодействия

Тип `F` определяет **протокол взаимодействия** между программой и её окружением. Например:

- Если `F = Function0`, то вычисления происходят синхронно.
- Если `F = Par`, то вычисления происходят асинхронно.

Выбирая разные `F`, вы можете точно контролировать, какие виды взаимодействий допустимы в вашей программе. 
Это делает `Free[F, A]` мощным инструментом для построения чистых, тестируемых и расширяемых систем.

### Вывод

Таким образом, `Free[F, A]` — это:

- Рекурсивное дерево вычислений.
- Гибкая монада, работающая с любым типом `F`.
- Средство моделирования программ как абстрактных синтаксических деревьев.
- Платформа для создания интерпретируемых, чистых и стекобезопасных программ.

Используя `Free[F, A]`, вы получаете возможность строить программы, которые легко тестировать, 
модифицировать и выполнять в разных средах, без потери чистоты и предсказуемости.

## Монада, поддерживающая только консольный ввод-вывод

Ранее мы рассматривали использование `Free[Function0, A]` для построения чистых программ с побочными эффектами.
Однако тип `Function0` слишком общий и не позволяет явно моделировать конкретные виды эффектов — 
например, чтение из консоли или печать на экране.

Чтобы получить более строгий контроль над эффектами, можно использовать **алгебраический тип данных**, 
описывающий только те операции, которые мы хотим поддерживать.
В данном случае мы ограничимся **консольным вводом-выводом**.

### Определение `Console[A]`

Мы определим тип `Console[A]`, который представляет собой вычисление, 
возвращающее значение типа `A`, но ограниченное двумя возможными действиями:

1. `ReadLine`: операция чтения строки из консоли.
2. `PrintLine(line: String)`: операция печати строки в консоль.

```dotty
enum Console[A]:
  case ReadLine                extends Console[Option[String]]
  case PrintLine(line: String) extends Console[Unit]

  def toPar: Par[A] = this match
    case ReadLine        => Par.lazyUnit(Try(readLine()).toOption)
    case PrintLine(line) => Par.lazyUnit(println(line))

  def toThunk: () => A = this match
    case ReadLine        => () => Try(readLine()).toOption
    case PrintLine(line) => () => println(line)
```

- `ReadLine` моделирует операцию ввода — она возвращает `Option[String]`, 
  потому что ввод может быть пустым или завершённым пользователем.
- `PrintLine(line)` моделирует операцию вывода — она ничего не возвращает (`Unit`), так как печать — это побочный эффект.
- `toPar` и `toThunk` — это интерпретаторы, которые преобразуют `Console[A]` 
  в асинхронное вычисление (`Par`) или отложенную функцию (`Function0`).

### Внедрение `Console` в `Free`

Теперь, чтобы использовать `Console` в рамках свободной монады `Free[F, A]`, мы можем создавать программы, используя конструктор `Suspend`.

```dotty
object Console:
  def readLn: Free[Console, Option[String]] =
    Suspend(ReadLine)
 
  def printLn(line: String): Free[Console, Unit] =
    Suspend(PrintLine(line))
```

- `readLn` создаёт программу `Free[Console, Option[String]]`, которая описывает чтение строки из консоли.
- `printLn` создаёт программу `Free[Console, Unit]`, которая описывает печать строки в консоль.

Эти программы **не выполняются сразу** — они просто описывают последовательность действий.
Выполнение будет происходить позже, когда мы передадим их интерпретатору.

### Пример программы с консольным вводом-выводом

С помощью `Free[Console, A]` мы можем писать программы, которые взаимодействуют с консолью:

```dotty
val f1: Free[Console, Option[String]] =
  for
    _  <- printLn("Я могу взаимодействовать только с консолью.")
    ln <- readLn
  yield ln
```

Эта программа делает следующее:

1. Печатает сообщение `"Я могу взаимодействовать только с консолью."`.
2. Читает строку из консоли.
3. Возвращает эту строку как результат.

Программа не содержит других побочных эффектов — только те, что описаны в `Console`.

> ⚠️ Scala не запрещает программисту использовать другие эффекты (например, работу с файлами или сетью),
> но если мы придерживаемся дисциплины и используем только `Console`, то программа остаётся чистой и легко тестируемой.

### Преимущества использования `Console` вместо `Function0`

- **Чёткость**: Мы точно знаем, какие эффекты могут возникнуть в программе.
- **Тестируемость**: Можно заменить `Console` на "чистый" интерпретатор, 
  который не выполняет реальных ввода-вывода, а сохраняет данные в буфер.
- **Повторное использование**: `Console` можно интерпретировать по-разному: 
  через `Par`, `Function0`, или даже через `Reader`, где ввод задаётся заранее.

## Как на самом деле запустить `Free[Console, A]`?

Ранее мы описали `Free[F, A]` как универсальную структуру данных, 
которая позволяет строить чистые программы с побочными эффектами. 
Однако, чтобы **запустить** такую программу и получить результат, нам нужен интерпретатор — 
функция, которая может "выполнить" все шаги, описанные в дереве `Free`.

В случае `Free[Console, A]`, где `Console[A]` — это тип, моделирующий консольные операции (например, `ReadLine` и `PrintLine`), 
возникает проблема: сам по себе `Console` **не является монадой**, 
и, следовательно, мы не можем напрямую использовать метод `run`, который требует наличие экземпляра `Monad[F]`.

### Почему `Console` не может быть монадой

Посмотрим на определение `Console`:

```dotty
enum Console[A]:
  case ReadLine                extends Console[Option[String]]
  case PrintLine(line: String) extends Console[Unit]
```

Это простой алгебраический тип, который описывает возможные действия: 
чтение строки из консоли или печать строки на экран. 
Но у него нет реализации `flatMap`, что делает его **неподходящим для использования в качестве монады**.

Если попытаться добавить `flatMap`, то получится что-то вроде:

```dotty
def flatMap[B](f: A => Console[B]): Console[B] = this match
  case ReadLine => ???
  case PrintLine(s) => ???
```

Проблема здесь в том, что для `ReadLine` нам нужно значение типа `Option[String]`, чтобы передать его в `f`. 
Но у нас его ещё нет — оно появится только тогда, когда кто-то выполнит реальный ввод с клавиатуры. 
То есть, мы **не можем реализовать `flatMap` без доступа к реальному эффекту**, который ещё не произошёл.

### Обобщаем `run` через `runFree`

Поскольку `Console` не образует монаду, но мы хотим иметь возможность выполнять программы `Free[Console, A]`, 
мы должны найти способ **преобразовать** `Console` в тип, который уже является монадой. 
Например, можно использовать `Function0` или `Par`, которые поддерживают `flatMap`.

Для этого мы обобщаем метод `run`, вводя новую сигнатуру `runFree`:

```dotty
enum Free[F[_], A]:
  ...
  def runFree[G[_]](t: [x] => F[x] => G[x])(using G: Monad[G]): G[A] =
    step match
      case Return(a)              => G.unit(a)
      case Suspend(r)             => t(r)
      case FlatMap(Suspend(r), f) => t(r).flatMap(a => f(a).runFree(t))
      case FlatMap(_, _) =>
        sys.error("Impossible, `step` eliminates these cases")
```

Эта функция принимает:

- `t`: **полиморфную функцию**, которая преобразует любой `F[x]` в `G[x]`.
- `G`: **экземпляр `Monad[G]`**, который позволяет работать с `flatMap`.

Таким образом, `runFree` позволяет интерпретировать `Free[F, A]` в любом другом монадическом контексте `G`, 
если мы умеем переводить `F[x]` в `G[x]`.

### Полиморфная функция: `[x] => F[x] => G[x]`

Параметр `t` в `runFree` имеет тип `[x] => F[x] => G[x]`. 
Это [**полиморфная функция**](https://docs.scala-lang.org/scala3/reference/new-types/polymorphic-function-types.html), которая работает для любого типа `x`. 
Она гарантирует, что мы можем перевести `F[Int]` в `G[Int]`, `F[String]` в `G[String]`, и т.д., 
но **не** можем перевести `F[Int]` в `G[Boolean]`.

Пример:

```dotty
val toThunk: [x] => Console[x] => () => x = [x] => (c: Console[x]) => c.toThunk
```

Здесь `toThunk` — это функция, которая принимает любой `Console[x]` и возвращает отложенное вычисление `() => x`. 
Такой подход позволяет нам сохранять типы и корректно связывать значения в монадических цепочках.

#### Почему обычного `F[A] => G[A]` недостаточно?

Давайте разберёмся, **зачем нужна именно полиморфная функция**, а не просто `F[A] => G[A]`.

Представьте, что у нас есть программа, например, которая считывает число с консоли:

```dotty
def readInt: Free[Console, Option[Int]] =
  for
    ln  <- readLn
  yield ln.flatMap(_.toIntOption)
```

Эта программа имеет тип `Free[Console, Option[Int]]`, но её внутренняя структура может содержать промежуточные шаги, 
которые работают с другими типами. 
Например, `readLn` возвращает `Option[String]`, и только внутри `FlatMap` мы преобразуем его в `Option[Int]`.

Таким образом, во время интерпретации программы `readInt` мы можем столкнуться с `Free[Console, String]`, 
`Free[Console, Int]`, и даже с `Free[Console, Unit]`, если где-то будет вызвана `PrintLine`.

Если мы попробуем использовать простую функцию `t: F[A] => G[A]`, 
то она будет работать **только для одного конкретного типа `A`**. 
Но такая функция **не подойдёт**, если внутри программы встречаются другие типы.

Допустим, мы хотели бы изменить сигнатуру `runFree` на:

```dotty
def runFree[G[_], B](t: F[B] => G[B])(using G: Monad[G]): G[A]
```

Эта сигнатура говорит: "У меня есть функция `t`, которая умеет переводить `F[B]` в `G[B]`, и я хочу применить её к программе `Free[F, A]`".

Но это **не сработает**, потому что `runFree` должна обрабатывать **любые** типы `x`, 
которые могут появиться в программе `Free[F, A]`. 
То есть, она должна принимать функцию, которая работает **для любого `x`**, а не только для конкретного `B`.

### Зависимость от экземпляров `Monad`

Для использования `runFree`, необходимо, чтобы целевая монада `G` имела реализацию методов `unit` и `flatMap`. 
Поэтому мы должны определить соответствующие экземпляры `Monad`:

```dotty
given Monad[Function0] with
  def unit[A](a: => A): () => A =
    () => a

  extension [A](fa: () => A)
    def flatMap[B](f: A => () => B): () => B =
      f(fa())

given parMonad: Monad[Par] with
  def unit[A](a: => A): Par[A] = Par.unit(a)

  extension [A](fa: Par[A])
    def flatMap[B](f: A => Par[B]): Par[B] =
      Par.flatMap(fa)(f)      
```

### Пример: Интерпретация `Free[Console, A]` в `Function0`

С помощью `runFree` мы можем легко создать интерпретатор, 
который преобразует нашу программу `Free[Console, A]` в отложенную функцию `() => A`, используя `Function0`:

```dotty
extension [A](fa: Free[Console, A])
  def toThunk: () => A =
    fa.runFree([x] => (c: Console[x]) => c.toThunk)
```

Теперь, чтобы выполнить программу, достаточно вызвать `toThunk()`:

```dotty
val program: Free[Console, Option[String]] =
  for
    _  <- printLn("Введите текст:")
    ln <- readLn
  yield ln

val result: Option[String] = program.toThunk()
```

### Асинхронный вариант: Интерпретация в `Par`

Аналогично, мы можем интерпретировать программу в асинхронном контексте, используя `Par`:

```dotty
extension [A](fa: Free[Console, A])
  def toPar: Par[A] =
    fa.runFree([x] => (c: Console[x]) => c.toPar)
```

Теперь `toPar` возвращает `Par[A]`, что позволяет запускать программу параллельно.

### Упражнение 9.3.4: Реализация `translate`

**Задание:**

Мы уже реализовали функцию `toThunk`, которая позволяет запускать программу `Free[Console, A]`,
преобразуя её в отложенную функцию `() => A`. Однако, оказалось, что `toThunk` **не является стекобезопасной**.

Причина в том, что метод `flatMap` для `Function0` не оптимизирован под хвостовую рекурсию.
Это приводит к тому, что при выполнении программы с большим количеством последовательных действий
(например, цепочки из десятков `FlatMap`), может произойти **переполнение стека**,
аналогично проблеме, с которой мы сталкивались при работе с наивным `IO`.

Чтобы решить эту проблему, мы должны найти способ **стекобезопасно** выполнять программу `Free[Console, A]`.

Функция `translate` — это обобщённый механизм, который позволяет **перевести программу `Free[F, A]`
в программу `Free[G, A]`**, используя некоторое преобразование между `F[x]` и `G[x]`.

В отличие от `runFree`, которая преобразует `Free[F, A]` в значение типа `G[A]`,
`translate` сохраняет структуру как `Free[G, A]`.

Реализуйте `translate`:

```dotty
enum Free[F[_], A]:
  def translate[G[_]](fToG: [x] => F[x] => G[x]): Free[G, A] = ???
```

@:note(🔍 Показать решение)

Реализуем `translate` через `runFree`.
Мы можем использовать `runFree`, чтобы получить `Free[G, A]`, если определим `H[x] = Free[G, x]`.
Тогда `runFree` будет работать следующим образом:

1. Принимает `Free[F, A]`.
2. Преобразует каждый `Suspend(f)` в `Free[G, A]`, используя `Suspend(fToG(f))`.
3. Возвращает новую программу `Free[G, A]`.

```dotty
enum Free[F[_], A]:
  ...
  def translate[G[_]](fToG: [x] => F[x] => G[x]): Free[G, A] =
    runFree([x] => (fx: F[x]) => Suspend(fToG(fx)))
```

Таким образом, `translate` преобразует нашу программу в новую программу, где все эффекты `F[x]` заменены на `G[x]`.

@:@

### Упражнение 9.3.5: Реализация стекобезопасного `unsafeRunConsole`

Теперь, когда у нас есть `translate`, мы можем использовать его вместе с `runTrampoline`, 
чтобы выполнить программу `Free[Console, A]` **стекобезопасно**.

Реализуйте `runTrampoline`:

```dotty
extension [A](fa: Free[Console, A])
  def unsafeRunConsole: A = ???
```

@:note(🔍 Показать решение)

1. Мы вызываем `translate`, передавая в него функцию, которая преобразует `Console[x]` в `Function0[x]` (отложенное вычисление).
2. Результат — программа `Free[Function0, A]`.
3. Эта программа может быть безопасно выполнена с помощью `runTrampoline`.

```dotty
extension [A](fa: Free[Console, A])
  def unsafeRunConsole: A =
    fa.translate([x] => (c: Console[x]) => c.toThunk).runTrampoline
```

- `translate([x] => (c: Console[x]) => c.toThunk)` — преобразует программу `Free[Console, A]` в `Free[Function0, A]`.
- `.runTrampoline` — выполняет программу безопасно, используя хвостовую рекурсию.

@:@

### Итог

Чтобы запустить программу типа `Free[Console, A]`, необходимо выполнить три ключевых шага:

1. **Определить интерпретацию каждого шага**:
   Каждый элемент программы, например `ReadLine` или `PrintLine`, должен быть переведён в соответствующее действие. 
   Это достигается с помощью функции-переводчика такой, как `toThunk`, `toPar`, `toState` и т.д.

2. **Преобразовать эффекты**:
   Мы переводим тип `Console[x]` в другой монадический тип, поддерживающий нужный способ выполнения — 
   будь то синхронное вычисление (`Function0`), асинхронная обработка (`Par`) или что-то другое.

3. **Использовать `runFree` для интерпретации**:
   Метод `runFree` применяет переводчик ко всем шагам программы, превращая её в значение целевой монады. 
   Таким образом, мы можем выполнить программу в любом контексте, который поддерживает `Monad`.

#### Сила `Free[F, A]`

Тип `Free[F, A]` представляет собой программу, написанную на языке, где каждая инструкция определяется через `F`. 
Например, если `F = Console`, то язык содержит две инструкции: `ReadLine` и `PrintLine`.

`Free` предоставляет:

- **Рекурсивную структуру** (`Suspend`, `Return`, `FlatMap`),
- **Механизм композиции действий**, позволяя строить сложные программы из простых шагов,
- **Гибкость** в выборе реализации эффектов (`F`).

Это делает `Free` универсальным средством моделирования эффектов: 
вы можете использовать его не только для консольного ввода-вывода, 
но и для работы с файловой системой, сетью, базами данных и многим другим, просто меняя тип `F`.

#### Примеры применения

- **Синхронное выполнение**: `Free[Function0, A]` → `() => A`
- **Асинхронное выполнение**: `Free[Par, A]` → `Par[A]`
- **Чистые тесты**: `Free[Console, A]` → `ConsoleReader[A]` или `ConsoleState[A]`

Каждый из этих вариантов позволяет сохранять чистоту и предсказуемость программы, даже при наличии побочных эффектов.

#### Преимущества использования `Free`

- **Чистота**: Программа отделена от реализации эффектов.
- **Тестируемость**: Можно заменить реальные эффекты на чистые симуляции.
- **Расширяемость**: Добавление новых видов эффектов не требует изменения существующего кода.
- **Стекобезопасность**: Хвостовая рекурсия предотвращает переполнение стека.

#### Заключение

`Free[F, A]` — это мощный абстрактный механизм, позволяющий писать программы с побочными эффектами, 
которые остаются чистыми, тестируемыми и гибкими. 
Он обеспечивает полный контроль над тем, как и когда эти эффекты выполняются, 
что делает его ценным инструментом в функциональном программировании.

## Чистые интерпретаторы

Одним из ключевых преимуществ свободных монад (`Free[F, A]`) является их **чистота и разделение программы от её выполнения**. 
Программа, описанная как `Free[Console, A]`, — это не что-то, что "выполняется" автоматически. 
Это просто **структура данных**, которая описывает последовательность действий. 
Как именно она будет выполняться — зависит от **интерпретатора**.

Интерпретатор — это функция, которая преобразует действия типа `F` в конкретные вычисления. Например:

- Интерпретатор может запустить программу на настоящей консоли.
- Он может сымитировать консольное взаимодействие для тестирования.
- Он может записать все действия в лог или сохранить их для последующего анализа.
- Или даже вообще **не выполнять никаких побочных эффектов**, а использовать чистые значения.

Рассмотрим, как можно создавать **чистые интерпретаторы** для `Free[Console, A]`, 
которые не вызывают реальных побочных эффектов, но всё равно корректно моделируют поведение программы.

### Почему интерпретатор может быть чистым?

Тип `Free[Console, A]` — это абстракция, которая **не обязывает** нас использовать какие-либо побочные эффекты. 
Никакой реализации чтения с клавиатуры или печати на экране **в самом типе нет**. 
Всё это делает интерпретатор.

Если мы хотим протестировать программу `Free[Console, A]`, то нам не нужно запускать её в реальном окружении. 
Мы можем использовать **чистый интерпретатор**, который будет:

- Возвращать заранее заданные входные данные вместо `ReadLine`.
- Записывать все `PrintLine` команды в список для проверки.
- Не использовать никаких побочных эффектов.

### Пример 1: Интерпретатор с фиксированным вводом — `ConsoleReader`

Допустим, мы хотим написать интерпретатор, который **всегда возвращает одну и ту же строку** при каждом вызове `ReadLine`. 
Это полезно для тестирования.

Мы можем создать тип `ConsoleReader[A]`, который представляет собой функцию `String => A`, 
где `String` — это входная строка (например, введённая пользователем), а `A` — результат программы.

```dotty
case class ConsoleReader[A](run: String => A):
  def map[B](f: A => B): ConsoleReader[B] =
    ConsoleReader(r => f(run(r)))
 
  def flatMap[B](f: A => ConsoleReader[B]): ConsoleReader[B] =
    ConsoleReader(r => f(run(r)).run(r))
```

Этот тип поддерживает `map` и `flatMap`, поэтому он может быть монадой:

```dotty
object ConsoleReader:
  given monad: Monad[ConsoleReader] with
    def unit[A](a: => A) = ConsoleReader(_ => a)
    
    extension [A](fa: ConsoleReader[A])
      def flatMap[B](f: A => ConsoleReader[B]) = fa.flatMap(f)
```

Теперь добавим в `Console` метод `toReader`, который позволяет преобразовать каждый шаг программы в чистое значение:

```dotty
enum Console[A]:
  ...
  def toReader: ConsoleReader[A] = this match
    case ReadLine     => ConsoleReader(in => Some(in))
    case PrintLine(_) => ConsoleReader(_ => ())
```

Затем, чтобы интерпретировать всю программу, мы используем `runFree`, передавая `toReader` в качестве переводчика:

```dotty
extension [A](fa: Free[Console, A])
  def toReader: ConsoleReader[A] =
    fa.runFree([x] => (c: Console[x]) => c.toReader)
```

Пример использования:

```dotty
val program: Free[Console, Option[String]] =
  for
    _  <- printLn("Введите текст:")
    ln <- readLn
  yield ln

val testInput = "Hello, world!"
val result: Option[String] = program.toReader.run(testInput)
// val result: Option[String] = Some(Hello, world!)
```

Результат будет `"Hello, world!"`, так как `readLn` вернёт эту строку, а `printLn` проигнорируется.

### Пример 2: Симуляция ввода-вывода с буферами — `ConsoleState`

Если нам нужно более **реалистичное моделирование** консольного взаимодействия, 
мы можем использовать **состояние** — два списка: один для входных данных, другой для выходных.

```dotty
case class Buffers(in: List[String], out: Vector[String])

case class ConsoleState[A](
  run: Buffers => (A, Buffers)
)

object ConsoleState:
  given monad: Monad[ConsoleState] with
    def unit[A](a: => A) = ConsoleState(b => (a, b))
    extension [A](fa: ConsoleState[A])
      def flatMap[B](f: A => ConsoleState[B]) =
        ConsoleState { buffers =>
          val (a, newBuffers) = fa.run(buffers)
          f(a).run(newBuffers)
        }
```

Теперь реализуем `toState` для `Console`:

```dotty
enum Console[A]:
  ...
  def toState: ConsoleState[A] = this match
    case ReadLine =>
      ConsoleState: bufs =>
        bufs.in match
          case Nil    => (None, bufs)
          case h :: t => (Some(h), bufs.copy(in = t))
    case PrintLine(line) =>
      ConsoleState(bufs => ((), bufs.copy(out = bufs.out :+ line)))
```

Интерпретатор для `Free[Console, A]`:

```dotty
extension [A](fa: Free[Console, A])
  def toState: ConsoleState[A] =
    fa.runFree([x] => (c: Console[x]) => c.toState)
```

Пример использования:

```dotty
val program: Free[Console, Option[String]] =
  for
    _  <- printLn("Введите текст:")
    ln <- readLn
  yield ln

val initialState         = Buffers(List("Hello"), Vector())
val (result, finalState) = program.toState.run(initialState)
// val result: Option[String] = Some(Hello)
// val finalState: FreeExercises.Buffers = Buffers(List(),Vector(Введите текст:))
```

### Почему это важно?

#### ✅ Тестируемость

С помощью таких интерпретаторов можно:

- Проверять, что программа возвращает правильный результат.
- Убедиться, что `PrintLine` вызывается нужное количество раз.
- Убедиться, что `ReadLine` использует правильные данные.

#### ✅ Чистота и предсказуемость

Чистые интерпретаторы позволяют:

- Избегать побочных эффектов в тестах.
- Упрощать отладку.
- Гарантировать детерминированное поведение.

#### ✅ Расширяемость

Вы можете создать множество интерпретаторов:

- Для тестирования.
- Для логирования.
- Для отладки.
- Для сохранения состояния.
- Для асинхронного выполнения.

### Основная идея

`Free[Console, A]` — это **чистая программа**, которая **не зависит от способа её выполнения**. 
Она лишь описывает последовательность действий. Как именно они будут выполнены — решает интерпретатор.

Благодаря `runFree`, мы можем легко **переводить** нашу программу в различные монадические контексты:

- `Function0` → синхронное выполнение.
- `Par` → асинхронное выполнение.
- `ConsoleReader` → тестирование с фиксированным вводом.
- `ConsoleState` → симуляция ввода-вывода.
- `IO` → реальное выполнение с побочными эффектами.

### Вывод

Использование **чистых интерпретаторов** демонстрирует гибкость и мощь свободных монад:

- Вы можете писать программы, которые остаются чистыми, но моделируют сложное поведение.
- Вы можете легко тестировать такие программы без запуска реальных побочных эффектов.
- Вы можете использовать одни и те же программы в самых разных средах: тестирование, логирование, производство и т.д.

Это делает `Free[F, A]` универсальным инструментом для построения чистых, тестируемых и расширяемых приложений.
