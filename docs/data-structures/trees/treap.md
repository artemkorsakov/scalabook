# Декартово дерево

**Определение:**

[Декартово дерево](https://ru.wikipedia.org/wiki/Декартово_дерево) (_treap_, от _tree_ + _heap_), 
также называемое дерамидой или пиВо (_пирамида_ + _дерево_), — это бинарное дерево поиска, 
в котором каждая вершина хранит пару из _ключа_ и _приоритета_. 
Структура одновременно сочетает в себе два свойства:

1. **По ключу** — дерево является бинарным деревом поиска: в корневом узле ключ больше 
   всех ключей левого поддерева и меньше всех ключей правого поддерева.
2. **По приоритету** — дерево является кучей: приоритет каждого узла больше либо равен 
   приоритету всех его потомков (max-heap по приоритету).

Благодаря этому свойству дерево легко построить геометрически: нанесём `n` точек на плоскость, 
где ось абсцисс (`x`) — это ключ, а ось ординат (`y`) — это приоритет. 
Выберем самую верхнюю точку (с наибольшим `y`) — она станет корнем. 
Точки слева от неё рекурсивно образуют левое поддерево, точки справа — правое. 
Если все ключи и приоритеты различны, такое дерево строится **однозначно**.

Название «декартово» связано не с автором алгоритма, а с декартовой системой координат, 
в которой удобно представлять структуру: оси `x` и `y` задают одновременно порядок 
дерева поиска (по `x`) и кучу (по `y`).

**Оценка:**

Если выбрать приоритеты случайно и независимо, то ожидаемая высота дерева 
логарифмическая, поэтому декартово дерево называют _рандомизированным_ деревом поиска. 
Все операции выполняются за время, пропорциональное высоте:

- _Поиск элемента_ (`search`)
    - **Время** - O(log n) (ожидаемое)
    - **Память** - O(log n)
- _Вставка элемента_ (`insert`)
    - **Время** - O(log n) (ожидаемое)
    - **Память** - O(log n) 
- _Удаление элемента_ (`remove`)
    - **Время** - O(log n) (ожидаемое)
    - **Память** - O(log n)
- _Разделение_ (`split`)
    - **Время** - O(log n) (ожидаемое)
    - **Память** - O(log n)
- _Объединение_ (`merge`)
    - **Время** - O(log n) (ожидаемое)
    - **Память** - O(log n)

## Структура

В отличие от обычного [двоичного дерева поиска](binary-search-tree.md), 
каждый узел декартова дерева хранит не только ключ, но и приоритет. 
В примерах ниже приоритет генерируется случайно, что и обеспечивает 
ожидаемое логарифмическое время работы операций.

**Код:**

```dotty
enum Treap[+K, +P]:
  case Leaf
  case Branch(key: K, priority: P, left: Treap[K, P], right: Treap[K, P])

  lazy val isEmpty: Boolean = this match
    case Leaf => true
    case _    => false

  lazy val size: Int = this match
    case Leaf                  => 0
    case Branch(_, _, l, r)    => 1 + l.size + r.size

  def keys: List[K] = this match
    case Leaf              => Nil
    case Branch(k, _, l, r) => l.keys ::: k :: r.keys
```

## Рассуждение об оценке

Интуиция, почему случайные приоритеты дают логарифмическую высоту: 
рассмотрим вершину `y` и произвольную другую вершину `x` (`x < y`). 
Вершина `x` будет предком `y` ровно тогда, когда приоритет `x` окажется наибольшим 
среди всех вершин на отрезке ключей `[x, y]`. Так как приоритеты распределены 
равномерно и независимо, вероятность этого равна `1 / (|x - y| + 1)`.

Суммируя эти вероятности по всем возможным предкам, получаем матожидание глубины:

\\(\mathbb{E}\[d\_{i}\] = \sum\_{j \neq i} \frac{1}{|i - j| + 1} 
\leq 2 \sum\_{k=2}^{n} \frac{1}{k} = O(\log n)\\)

где последняя сумма — гармонический ряд. Таким образом, ожидаемая глубина вершины 
(а значит, и высота дерева) ограничена логарифмической функцией.

## Реализация на основе split и merge

Базовые операции декартова дерева удобно выражать через две вспомогательные функции: 
`merge`, объединяющую два дерева, и `split`, разделяющую одно дерево на два. 
Через них легко реализуются вставка, удаление и поиск.

### Merge

`merge` принимает два дерева `A` и `B`, про которые известно, что **все ключи `A` меньше всех ключей `B`**, 
и возвращает корректное декартово дерево, состоящее из всех вершин.

Корнем результирующего дерева становится узел с большим приоритетом. 
Если это корень `A`, то его левое поддерево остаётся без изменений, а правое поддерево 
рекурсивно склеивается с деревом `B`. Симметрично поступаем, если больший приоритет у корня `B`.

**Код:**

```dotty
def merge[K, P: Ordering as ord](
    a: Treap[K, P],
    b: Treap[K, P]
): Treap[K, P] =
  (a, b) match
    case (Leaf, _)                                        => b
    case (_, Leaf)                                        => a
    case (Branch(ka, pa, la, ra), Branch(kb, pb, lb, rb)) =>
      if ord.gteq(pa, pb) then
        Branch(ka, pa, la, merge(ra, b))
      else
        Branch(kb, pb, merge(a, lb), rb)
```

### Split

`split` принимает дерево `t` и ключ `x` и возвращает пару деревьев `(l, r)` таких, 
что все ключи в `l` не больше `x`, а все ключи в `r` строго больше `x`.

Сначала определяем, в какую из частей должен попасть корень. 
Если ключ корня `<= x`, то корень остаётся в левой части, а его правое поддерево 
рекурсивно разделяется; иначе — симметрично.

**Код:**

```dotty
def split[K: Ordering as ord, P](
    t: Treap[K, P],
    x: K
): (Treap[K, P], Treap[K, P]) =
  t match
    case Leaf               => (Leaf, Leaf)
    case Branch(k, p, l, r) =>
      if ord.lteq(k, x) then
        val (ll, rr) = split(r, x)
        (Branch(k, p, l, ll), rr)
      else
        val (ll, rr) = split(l, x)
        (ll, Branch(k, p, rr, r))
```

### Вставка

Чтобы вставить ключ `x`, достаточно разделить дерево по `x` на `l` и `r`, 
создать узел с ключом `x` и случайным приоритетом и склеить три дерева через `merge`.

**Код:**

```dotty
def insert[K: Ordering, P: Ordering](
    t: Treap[K, P],
    key: K,
    priority: P
): Treap[K, P] =
  val (l, r) = split(t, key)
  merge(merge(l, Branch(key, priority, Leaf, Leaf)), r)
```

### Поиск

Поиск по ключу аналогичен поиску в обычном [двоичном дереве поиска](binary-search-tree.md) 
и не использует приоритеты: на каждом шаге сравниваем ключ с ключом корня 
и спускаемся в левое либо правое поддерево.

**Код:**

```dotty
@tailrec
def search[K: Ordering as ord, A](t: Treap[K, A], key: K): Option[A] =
  t match
    case Leaf                => None
    case Branch(k, pr, l, r) =>
      if ord.lt(key, k) then search(l, key)
      else if ord.gt(key, k) then search(r, key)
      else Some(pr)
```

### Удаление

Удаление ключа `x` можно выразить через пару вызовов `split`, однако более 
наглядно (и без привязки к конкретному способу поиска предшественника) 
определить его напрямую рекурсивно: спускаемся к нужной вершине по ключу, 
а когда она найдена, заменяем её слиянием её левого и правого поддеревьев.

**Код:**

```dotty
def remove[K: Ordering as ord, P: Ordering](
    t: Treap[K, P],
    key: K
): Treap[K, P] =
  t match
    case Leaf               => Leaf
    case Branch(k, p, l, r) =>
      if ord.lt(key, k) then Branch(k, p, remove(l, key), r)
      else if ord.gt(key, k) then Branch(k, p, l, remove(r, key))
      else merge(l, r)
```

Если ключ не найден — дерево остаётся неизменным. Если же вершина найдена, 
она «выбрасывается», а её левое и правое поддеревья, которые и так удовлетворяют 
условию корректного `merge` (все ключи слева меньше всех ключей справа), 
склеиваются в одно дерево.

## Пример использования

Продемонстрируем базовые операции на простом примере. 
Поскольку приоритеты в примере заданы явно (не случайно), гарантия логарифмической 
высоты здесь не действует — это лишь иллюстрация алгоритма.

```dotty
val t0: Treap[Int, Int] = Leaf

val t1 = insert(t0, 5, 10)
val t2 = insert(t1, 3, 20)
val t3 = insert(t2, 8, 5)
val t4 = insert(t3, 1, 15)

t4.keys        // List(1, 3, 5, 8)  (inorder-обход, ключи отсортированы)
search(t4, 3)  // Some(20)          (приоритет вершины с ключом 3)
search(t4, 9)  // None

val (l, r) = split(t4, 4)
l.keys         // List(1, 3)        (ключи <= 4)
r.keys         // List(5, 8)        (ключи > 4)
```

Несмотря на то что `keys` возвращает отсортированную последовательность 
(это свойство бинарного дерева поиска по ключу), внутренняя форма дерева зависит 
от приоритетов: в примере выше корнем является вершина `(3, 20)` — у неё наибольший 
приоритет среди всех вершин.

## Применение

Декартово дерево сочетает простоту реализации с логарифмическими гарантиями, 
поэтому часто применяется там, где нужно динамическое упорядоченное множество:

- Реализация упорядоченных ассоциативных контейнеров (словарей и множеств) 
  с ожидаемой сложностью O(log n) на операцию.
- Операции `lower_bound` — поиск первого элемента, не меньшего заданного.
- Подсчёт количества элементов на отрезке `[l, r]` с помощью пары вызовов `split`.
- **Неявное декартово дерево** (implicit treap): когда приоритетом выступает позиция, 
  структура позволяет работать с последовательностью как с массивом с поддержкой 
  вставки, удаления, разворота и слияния подстрок за O(log n).
- **Персистентные** структуры данных: так как операции не разрушают исходные поддеревья, 
  версии дерева легко переиспользуют узлы, обеспечивая эффективные персистентные структуры.
