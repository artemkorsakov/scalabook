# Env — Чтение переменных окружения

`Env[F[_]]` — это **типовой класс**, предоставляющий функциональный 
и безопасный способ чтения **переменных окружения** процесса. 
Он абстрагирует доступ к переменным окружения, скрывая платформозависимые детали и потенциальные ошибки.

```dotty
trait Env[F[_]]:
  /** Возвращает значение переменной окружения, если она определена. */
  def get(name: String): F[Option[String]]

  /** Возвращает все переменные окружения как итерируемую коллекцию пар (имя,
    * значение).
    */
  def entries: F[Iterable[(String, String)]]
```

## Почему `F[Option[String]]`, а не просто `Option[String]`?

На первый взгляд может показаться, что чтение переменной окружения — это чистая операция, 
которая не должна требовать обёртки `F`. 
Однако есть несколько причин, почему Cats Effect помещает её в эффект:

### 1. Переменные окружения могут быть изменены в рантайме (POSIX)

В POSIX-совместимых системах (Linux, macOS) процесс может изменить 
свои собственные переменные окружения через `setenv` и `unsetenv`. 
Даже если процесс этого не делает, **другой поток** может изменить окружение (хотя это очень плохая практика).

```c
// C-код, который может выполняться параллельно с вашим Scala-кодом
setenv("MY_VAR", "new_value", 1);
```

Cats Effect не может гарантировать, что значение переменной окружения останется неизменным 
между последовательными вызовами `get`. 
Поскольку `F` может последовательно выполнять эффекты, помещение `get` в эффект явно указывает на то, 
что операция **может давать разные результаты при каждом вызове**.

### 2. Чтение окружения может завершиться ошибкой

В некоторых средах (например, Windows при недостаточных правах доступа) 
чтение переменной окружения может выбросить `SecurityException`. 
Обёртка `F` позволяет корректно поднять эту ошибку в контексте эффекта:

```dotty
env.get("PATH").handleErrorWith { case _: SecurityException =>
  Console[F].errorln("Нет прав для чтения переменной PATH")
}
```

### 3. Кроссплатформенность (JVM, Scala.js, Scala Native)

Реализация чтения окружения отличается на разных платформах:

| Платформа         | Особенности                                                                                    |
|:------------------|:-----------------------------------------------------------------------------------------------|
| **JVM**           | Использует `System.getenv()`, который может вернуть `null` или выбросить `SecurityException`.  |
| **Scala Native**  | Обращается к libc (`getenv`), что требует взаимодействия с нативным кодом.                     |
| **Scala.js**      | В браузере переменных окружения нет (доступны только через Node.js API).                       |

Обёртка `F` скрывает эти различия и предоставляет единый интерфейс.

### 4. Переменные окружения не являются чистыми

С точки зрения ссылочной прозрачности, `Env.get("PATH")` не обязан возвращать одно и то же значение при каждом вызове. 
Помещение операции в `F` явно сигнализирует о её **недетерминированности** и **зависимости от внешнего мира**.

## Примеры использования

### Базовое чтение одной переменной

```dotty
import cats.effect.{IO, IOApp}
import cats.effect.std.Env

object ReadEnv extends IOApp.Simple:
  val run: IO[Unit] =
    for
      maybeHome <- Env[IO].get("HOME")
      _         <- maybeHome match
        case Some(home) => IO.println(s"Домашняя директория: $home")
        case None       => IO.println("Переменная HOME не установлена")
    yield ()
```

### Чтение всех переменных

```dotty
val program = Env[IO].entries.flatMap { vars =>
  vars.toList.traverse_ { case (k, v) =>
    IO.println(s"$k = $v")
  }
}
```

### Обработка ошибок

```dotty
import cats.effect.IO
import cats.effect.std.Env

val safeGet = Env[IO].get("SECRET_KEY").attempt.flatMap {
  case Right(Some(value)) => IO.println(s"Ключ найден: ${value.take(3)}...")
  case Right(None)        => IO.println("Ключ не установлен")
  case Left(e)            => IO.println(s"Ошибка доступа: ${e.getMessage}")
}
```

### Валидация обязательных переменных

```dotty
def requireEnv(name: String): IO[String] =
  Env[IO].get(name).flatMap {
    case Some(value) => IO.pure(value)
    case None        => IO.raiseError(
        new Exception(s"Отсутствует обязательная переменная: $name")
      )
  }

val config =
  for
    dbUrl  <- requireEnv("DATABASE_URL")
    apiKey <- requireEnv("API_KEY")
    mode   <- requireEnv("MODE").map(_.toLowerCase)
  yield AppConfig(dbUrl, apiKey, mode)
```

## Платформенные особенности

| Платформа               | Доступность     | Особенности `get`                                                                                              |
|:------------------------|:----------------|:---------------------------------------------------------------------------------------------------------------|
| **JVM**                 | ✅ Полностью     | Может выбросить `SecurityException`. Возвращает `null` для отсутствующих переменных (преобразуется в `None`).  |
| **Scala Native**        | ✅ Полностью     | Использует `getenv` из libc. Работает аналогично JVM.                                                          |
| **Scala.js (Node.js)**  | ⚠️ Частично     | Доступ через `process.env`. Метод `entries` поддерживается.                                                    |
| **Scala.js (браузер)**  | ❌ Отсутствует   | Нет доступа к переменным окружения. `get` всегда возвращает `None`, `entries` — пустой `Iterable`.             |

## Сравнение с другими подходами

| Подход                                   | Тип результата                | Обработка ошибок                     | Кроссплатформенный  |
|:-----------------------------------------|:------------------------------|:-------------------------------------|:--------------------|
| **`Env[F].get`**                         | `F[Option[String]]`           | ✅ Через механизм ошибок `F`          | ✅ Да                |
| `System.getenv` (JVM)                    | `String` (может быть `null`)  | ❌ `SecurityException` (синхронный)   | ❌ Только JVM        |
| `scala.scalanative.posix.stdlib.getenv`  | `CString`                     | ❌ Зависит от платформы               | ❌ Только Native     |
| `process.env` (Node.js)                  | `string \| undefined`         | ❌ Синхронный                         | ❌ Только JS         |

## Типичные сценарии использования

| Сценарий                          | Пример                                         |
|:----------------------------------|:-----------------------------------------------|
| **Чтение конфигурации**           | `DATABASE_URL`, `REDIS_HOST`, `LOG_LEVEL`      |
| **Feature toggles**               | `ENABLE_FEATURE_X=true`                        |
| **Окружение (dev/staging/prod)**  | `APP_ENV=production`                           |
| **Ключи API**                     | `SERVICE_API_KEY=abc123` (хранить в секрете!)  |
| **Параметры деплоя**              | `KUBERNETES_NAMESPACE=default`                 |

## Итог

✅ **Используйте `Env`, когда нужно:**

- Прочитать несколько переменных окружения в кроссплатформенном приложении.
- Элегантно обработать отсутствие переменной или ошибку доступа.
- Сохранить ссылочную прозрачность и единообразие кода.

❌ **Не используйте `Env`, если:**

- Вам нужна сложная конфигурация с типами и валидацией (возьмите `pureconfig`).
- Вы пишете приложение только для JVM и предпочитаете `System.getenv` (но `Env` всё равно удобнее в тестах).

**Ключевая идея:** `Env` — это функциональная, безопасная и кроссплатформенная обёртка над нечистым миром переменных окружения. 
Она превращает потенциальные глобальные мутации и исключения в честные эффекты `F[Option[String]]`.
