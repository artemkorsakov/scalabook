# Эффекты

## Введение

Понятие **эффекта** является центральным в Cats Effect и во всей экосистеме функционального программирования с эффектами. 
Понимание того, что такое эффект, чем он отличается от побочного эффекта и как правильно работать с эффектами, — 
это ключ к написанию корректного, композиционного и предсказуемого кода.

## Что такое эффект?

### Определение

**Эффект** — это **описание действия (или последовательности действий)**, которое будет выполнено при вычислении. 
Важнейшее свойство эффекта: он **не выполняет действие немедленно**, а лишь описывает его.

Самый распространённый тип эффекта в Cats Effect — это `IO`:

```dotty
import cats.effect.IO

// printer — это эффект, описывающий печать строки
val printer: IO[Unit] = IO.println("Hello, World")

// printAndRead — эффект, описывающий последовательность действий
val printAndRead: IO[String] = IO.print("Enter your name: ") *> IO.readLine
```

Обратите внимание на ключевое слово `val`. `printer` — это **значение**. 
Оно существует в программе как объект, но само по себе **ничего не печатает**. 
Печать произойдёт только тогда, когда эффект будет **выполнен** (обычно внутри `IOApp.run` или через `unsafe`-методы).

### Эффект-функции

Функция, которая возвращает эффект, называется **функцией с эффектом** (_effectful function_):

```dotty
def foo(str: String): IO[String] = IO.pure(str.toUpperCase)
```

В сокращённой речи говорят: «`foo` — это функция с эффектом». Важно понимать разницу между:

- **Функция с эффектом** — возвращает описание действия (`IO[String]`)
- **Функция, выполняющая эффект** — непосредственно производит побочные эффекты

Эту разницу часто упускают из виду, но она критически важна для понимания функционального программирования с эффектами.

## Эффект vs Побочный эффект: ключевое различие

### Побочный эффект (Side Effect)

**Побочный эффект** — это изменение, выходящее за рамки простого возврата значения. Признаки побочного эффекта:

- **Важно, сколько раз выполняется код** (один раз, два раза, ни разу)
- **Важно, когда выполняется код** (сейчас, через секунду, после другого действия)
- Код взаимодействует с внешним миром (консоль, файлы, сеть)
- Код изменяет состояние (переменные, коллекции)

Классический пример — `System.out.println`:

```dotty
def double(x: Int): Int =
  System.out.println("Hello, World")  // ← Побочный эффект!
  x + x
```

При вызове `double(5)`:

1. Происходит печать в консоль (побочный эффект)
2. Вычисляется и возвращается `10`

Если вызвать `double` трижды, печать произойдёт трижды. 
Нельзя «отменить» или «изменить» этот побочный эффект — он происходит неизбежно в момент вызова.

**Проблемы побочных эффектов:**

- Невозможно легко тестировать (нужно перехватывать `stdout`)
- Нельзя выполнить параллельно без дополнительной синхронизации
- Нельзя повторить при ошибке
- Нельзя отложить выполнение
- Трудно рассуждать о поведении программы

### Эффект как описание

В Cats Effect код с побочными эффектами **всегда оборачивается** в специальные конструкторы, 
превращая его в **эффект** — описание действия:

```dotty
// Побочный эффект (выполняется немедленно)
System.out.println("Hello, World")

// Эффект (описание, ничего не печатает)
val wrapped: IO[Unit] = IO(System.out.println("Hello, World"))
```

Теперь `wrapped` — это значение, которое можно:

- Передавать в функции
- Комбинировать с другими эффектами
- Трансформировать (`map`, `flatMap`)
- Выполнять параллельно
- Повторять при ошибке
- Отменять

**Важнейшее следствие:** Сам код с побочными эффектами по-прежнему содержит побочные эффекты, 
но **вне лексической области видимости конструктора** мы работаем только с эффектом, а не с побочным эффектом.

## Сравнение с Future: почему IO лучше

Многие разработчики Scala знакомы с `Future`. На первый взгляд `Future` и `IO` похожи — оба представляют асинхронные вычисления. 
Но есть фундаментальное различие:

### Future: результат, а не описание

```dotty
import scala.concurrent.Future
import scala.concurrent.ExecutionContext.Implicits.global

val printer: Future[Unit] = Future(println("Hello, World"))

printer  // ← ничего не делает? НЕТ! Уже напечатало "Hello, World"!
printer  // ← не печатает снова
printer  // ← не печатает снова
```

**Что здесь произошло?**

1. `Future(println("Hello, World"))` **немедленно начинает выполнение** в пуле потоков
2. Переменная `printer` хранит не описание, а **результат** уже запущенного вычисления
3. Последующие обращения к `printer` просто возвращают уже завершённый (или ещё выполняющийся) результат

Это приводит к проблемам:

- Непредсказуемое поведение: сколько раз напечатается?
- Нельзя отложить выполнение
- Нельзя легко повторить
- Замыкания захватывают состояние сложным образом

### Попытка исправить Future через def

```dotty
def printer: Future[Unit] = Future(println("Hello, World"))

printer  // печатает
printer  // печатает снова
printer  // печатает снова
```

Теперь печатается три раза — но это тоже не описание действия, а **каждый раз новый запуск** вычисления. При этом:

- Нет контроля над тем, когда начинается выполнение
- Нет единого описания, которое можно скомпоновать
- Легко случайно запустить вычисление много раз, когда нужно один

### IO: истинное описание

```dotty
import cats.effect.IO

val printer: IO[Unit] = IO.println("Hello, World")

printer  // ничего не делает
printer  // ничего не делает
printer  // ничего не делает

// Только когда мы явно запускаем эффект — происходит печать
printer.unsafeRunSync()  // печатает один раз
```

**Преимущества `IO`:**

- Полный контроль над временем выполнения
- Предсказуемое поведение при многократном использовании
- Легкость композиции
- Возможность трансформации до выполнения

## Конструкторы эффектов: как оборачивать побочные эффекты

Cats Effect предоставляет несколько конструкторов для оборачивания кода с побочными эффектами в зависимости от характера операции.

### Синхронные конструкторы

Синхронные конструкторы используются для кода, который выполняется на текущем потоке и либо возвращает значение, либо бросает исключение.

#### `IO.apply / IO.delay` — базовый синхронный конструктор

```dotty
import cats.effect.IO

// Базовый способ
val effect: IO[Int] = IO(42)

// С побочным эффектом
val printing: IO[Unit] = IO(System.out.println("Hello"))

// С возможным исключением
val risky: IO[Int] = IO(10 / 0)  // Опишет ошибку, не бросит её сейчас
```

**Когда использовать:** Для быстрых операций без блокировок (вычисления, лёгкие побочные эффекты).

#### `IO.blocking` — для блокирующих операций

```dotty
import cats.effect.IO

// Чтение из файла с блокировкой
val readFile: IO[String] = IO.blocking {
  val src = scala.io.Source.fromFile("data.txt")
  val res = src.mkString
  src.close()
  res
}

// JDBC запрос
val dbQuery: IO[ResultSet] = IO.blocking {
  statement.executeQuery()
}
```

**Когда использовать:** Для операций, которые блокируют поток ОС (дисковый I/O, JDBC, старые сетевые библиотеки). 
Cats Effect выделяет для таких операций отдельный пул потоков.

#### `IO.interruptible / IO.interruptibleMany` — блокирующие, но прерываемые

```dotty
import cats.effect.IO

// Прерываемая блокирующая операция
val interruptibleSleep: IO[Unit] = IO.interruptible {
  Thread.sleep(10000) // Можно прервать через cancel
}
```

**Разница между interruptible и interruptibleMany:**

- `interruptible` — проверяет прерывание один раз перед выполнением
- `interruptibleMany` — периодически проверяет прерывание во время выполнения

**Когда использовать:** Для долгих блокирующих операций, которые должны реагировать на отмену.

### Асинхронные конструкторы

Асинхронные конструкторы используются для кода, который использует callback-механизмы (например, Netty, NIO, JavaScript setTimeout).

#### `IO.async / IO.async_` — для callback-based API

```dotty
import cats.effect.IO
import java.util.concurrent.ScheduledExecutorService

def delayedEffect(scheduler: ScheduledExecutorService, delayMs: Long): IO[Unit] =
  IO.async_ { callback =>
    scheduler.schedule(
      new Runnable {
        def run(): Unit = callback(Right(()))
      },
      delayMs,
      java.util.concurrent.TimeUnit.MILLISECONDS
    )
    ()
  }
```

**Структура `async_`:**

1. Принимает обратный вызов: `Either[Throwable, A] => Unit`
2. Регистрирует этот обратный вызов в асинхронном API
3. Возвращает `Unit` (нет финализатора)

**IO.async** — более мощная версия, возвращающая `IO[Option[IO[Unit]]]` для возможности отмены.

**Когда использовать:** Для интеграции с callback-based библиотеками, сетевыми фреймворками, таймерами.

### Сравнительная таблица конструкторов

| Конструктор            | Тип выполнения           | Прерываемость           | Использование потока  | Пример использования                   |
|------------------------|--------------------------|-------------------------|-----------------------|----------------------------------------|
| `IO.apply`             | Синхронный               | N/A (быстро)            | Текущий               | Вычисления, лёгкие операции            |
| `IO.blocking`          | Синхронный, блокирующий  | Нет                     | Выделенный пул        | Дисковый I/O, JDBC                     |
| `IO.interruptible`     | Синхронный, блокирующий  | Да (одна проверка)      | Выделенный пул        | Долгие операции с возможностью отмены  |
| `IO.interruptibleMany` | Синхронный, блокирующий  | Да (периодически)       | Выделенный пул        | Очень долгие циклы                     |
| `IO.async`             | Асинхронный, callback    | Да (через финализатор)  | Не блокирует          | Сетевые вызовы, таймеры                |

## Полиморфные эффекты (`F[_]`)

В реальных проектах на Cats Effect код часто пишется не для конкретного типа `IO`, а для **абстрактного типа эффекта** `F[_]`. Это позволяет:

- Легко тестировать (используя `IO` или специальные тестовые эффекты)
- Переиспользовать код с разными эффектами
- Комбинировать с другими библиотеками (fs2, http4s, doobie)

### Пример полиморфной функции

```dotty
import cats.Monad
import cats.effect.std.Console
import cats.syntax.all.*

def example[F[_]: {Monad, Console}](str: String): F[String] =
  val printer: F[Unit] = Console[F].println(str)
  (printer *> printer).as(str)
```

**Разбор примера:**

- `F[_]` — абстрактный тип эффекта
- `Monad[F]` — возможность использовать `flatMap`, `map`, `*>`
- `Console[F]` — возможность выводить в консоль (абстракция над `IO.println`)
- `printer` — эффект печати в абстрактном контексте
- `printer *> printer` — два последовательных эффекта печати
- `.as(str)` — замена результата на исходную строку

### Использование полиморфной функции

```dotty
// С конкретным IO
val ioResult: IO[String] = example[IO]("Hello, World")

// С тестовым эффектом (например, для проверки)
val testResult: TestEffect[String] = example[TestEffect]("Test")
```

### Почему это мощно?

1. **Композиция библиотек** — разные библиотеки (fs2, http4s, doobie) работают с одним абстрактным `F`
2. **Тестируемость** — можно подставить `IO` или специальный тестовый эффект
3. **Гибкость** — можно менять стратегию выполнения без изменения кода

## Лучшие практики работы с эффектами

### Правило 1: Всегда оборачивайте побочные эффекты

```dotty
// ПЛОХО: прямой побочный эффект
def readConfig(): String =
  println("Reading config...") // Побочный эффект!
  ...

// ХОРОШО: эффект-функция
def readConfig: IO[String] =
  for
    _      <- IO.println("Reading config...")
    config <- IO.blocking(...)
  yield config
```

### Правило 2: Используйте правильный конструктор

```dotty
// Быстрые вычисления
val fast: IO[Int] = IO(2 + 2)

// Дисковый I/O
val diskIO: IO[String] = IO.blocking(readFile())

// Сетевые вызовы (асинхронные библиотеки)
val network: IO[Response] = IO.async_ { cb => httpClient.get(url, cb) }
```

### Правило 3: Не смешивайте эффекты и побочные эффекты

```dotty
// ПЛОХО: побочный эффект внутри map
val bad: IO[Int] =
  IO(42).map: x =>
    println(x) // Побочный эффект в map!
    x + 1

// ХОРОШО: оборачиваем в IO
val good: IO[Int] =
  for
    x <- IO(42)
    _ <- IO.println(x)
  yield x + 1
```

### Правило 4: Помните о разнице между val и def

```dotty
// Одно и то же описание, переиспользуемое многократно
val sharedEffect: IO[Unit] = IO.println("Shared")

// При каждом вызове — новое описание
def freshEffect: IO[Unit] = IO.println("Fresh")

// sharedEffect можно использовать много раз — описание одно и то же
val program1 = sharedEffect *> sharedEffect // Напечатает дважды

// freshEffect создаёт новое описание при каждом использовании
val program2 = freshEffect *> freshEffect // Тоже напечатает дважды
```

**Когда использовать `val`, а когда `def`:**

- `val` — когда эффект всегда должен делать одно и то же
- `def` — когда эффект параметризован или должен создаваться заново

## Резюме

| Понятие                  | Определение                                  | Пример                                |
|--------------------------|----------------------------------------------|---------------------------------------|
| **Эффект**               | Описание действия                            | `val print = IO.println("Hi")`        |
| **Побочный эффект**      | Действие, изменяющее состояние вне возврата  | `println("Hi")` напрямую              |
| **Функция с эффектом**   | Функция, возвращающая эффект                 | `def foo: IO[String]`                 |
| **Конструктор эффекта**  | Способ обернуть побочный эффект              | `IO(...)`, `IO.blocking`, `IO.async`  |

**Ключевые выводы:**

1. Эффекты — это **описания**, а не выполнения
2. Побочные эффекты всегда должны быть **обёрнуты** в конструкторы эффектов
3. `IO` — это не `Future`: `IO` описывает, `Future` запускает
4. Используйте **правильный конструктор** в зависимости от характера операции
5. Полиморфные эффекты (`F[_]`) дают максимальную гибкость и переиспользование

Следование этим принципам позволяет писать предсказуемый, тестируемый и композиционный код, 
полностью контролируя время и способ выполнения эффектов.
