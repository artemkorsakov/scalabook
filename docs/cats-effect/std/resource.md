# Resource — безопасное управление ресурсами

## Мотивация: проблема управления ресурсами

В любом приложении часто возникает один и тот же шаблон:

1. **Получить** ресурс (открыть файл, установить сетевое соединение, запустить поток).
2. **Использовать** ресурс для выполнения полезной работы.
3. **Освободить** ресурс (закрыть файл, разорвать соединение, остановить поток), 
   **независимо от того**, завершилась работа успешно, с ошибкой или была отменена.

### Традиционный подход: `bracket`

Cats Effect предоставляет метод `bracket` (из `MonadCancel`) специально для этой цели:

```dotty
def bracket[A, B](acquire: F[A])(use: A => F[B])(release: A => F[Unit]): F[B]
```

**Как это работает:**

1.  `acquire` — получаем ресурс (например, открываем файл).
2.  `use` — используем ресурс для вычислений.
3.  `release` — **гарантированно** освобождаем ресурс после `use`, даже если `use` упал с ошибкой или был отменён.

### Проблема: вложенный "ад" при множественных ресурсах

Пока ресурс один, код выглядит неплохо. Но что, если нам нужно открыть **три файла** одновременно? 
Код становится глубоко вложенным и трудным для чтения:

```dotty
val concat: IO[Unit] =
  IO.bracket(openFile("file1")) { file1 =>
    IO.bracket(openFile("file2")) { file2 =>
      IO.bracket(openFile("file3")) { file3 =>
        for
          bytes1 <- read(file1)
          bytes2 <- read(file2)
          _      <- write(file3, bytes1 ++ bytes2)
        yield ()
      }(file3 => close(file3))
    }(file2 => close(file2))
  }(file1 => close(file1))
```

**Недостатки такого подхода:**

| Проблема                            | Описание                                                                            |
|:------------------------------------|:------------------------------------------------------------------------------------|
| **Глубокая вложенность**            | Каждый новый ресурс добавляет уровень отступов (так называемый "пирамида смерти").  |
| **Смешение ответственности**        | Логика получения ресурса тесно связана с логикой его использования.                 |
| **Ошибкоопасность при композиции**  | Легко перепутать порядок закрытия или пропустить освобождение.                      |
| **Низкая переиспользуемость**       | Нельзя легко создать "ресурс", который потом будет использован в разных местах.     |

## Что такое `Resource`?

`Resource[F[_], A]` — это **абстракция**, которая инкапсулирует в себе **две вещи**:

1. Как **получить** (`acquire`) значение типа `A`.
2. Как **освободить** (`release`) это значение.

`Resource` формирует **монаду** (имеет `map` и `flatMap`), 
что позволяет нам **комбинировать несколько ресурсов** в один составной ресурс, **избегая вложенности**.

### Создание и использование

```dotty
object Resource:
  // Создаёт Resource из эффекта получения и функции освобождения
  def make[F[_], A](acquire: F[A])(release: A => F[Unit]): Resource[F, A]

  // Превращает любой эффект в Resource (пустой освободитель)
  def eval[F[_], A](fa: F[A]): Resource[F, A]

abstract class Resource[F[_], A]:
  // Использует ресурс: получает его, передаёт в функцию и гарантированно освобождает
  def use[B](f: A => F[B]): F[B]
```

### Как это работает?

- **`Resource.make(acquire)(release)`** создаёт "рецепт" получения и освобождения ресурса.
- **`res.flatMap`** или **for-comprehension** комбинируют несколько таких рецептов в один.
- **`res.use(f)`** — единственный момент, когда ресурс **реально получается**, передаётся в `f`, 
  а **после её завершения (или ошибки) — немедленно освобождается** в обратном порядке.

**Важнейшее правило:** `Resource` **не управляет ресурсом постоянно**. 
Ресурс живёт только внутри `use`. Как только `use` завершается — ресурс уничтожается.

## Пример №1: Безопасная работа с файлами

Вернёмся к нашему примеру с тремя файлами. Вот как `Resource` решает проблему вложенности:

```dotty
def file(name: String): Resource[IO, File] =
  Resource.make(openFile(name))(file => close(file))

val concat: IO[Unit] = (
  for
    in1 <- file("file1") // Эти строки не открывают файлы!
    in2 <- file("file2") // Они просто создают "рецепт"
    out <- file("file3") // Составной Resource[IO, (File, File, File)]
  yield (in1, in2, out)
).use {
  case (f1, f2, f3) => // А вот здесь файлы открываются
    for
      bytes1 <- read(f1)
      bytes2 <- read(f2)
      _      <- write(f3, bytes1 ++ bytes2)
    yield ()
} // И здесь (после use) гарантированно закрываются (в обратном порядке)
```

**Что здесь произошло?**

1.  **`file("file1")`** не открывает файл. Он создаёт значение `Resource[IO, File]` — "обещание" открыть файл в будущем и закрыть его после использования.
2.  **for-comprehension** комбинирует три таких обещания в одно: `Resource[IO, (File, File, File)]`.
3.  **`.use`** — это точка входа. Он:
    - Получает **все три** файла (если один не откроется, остальные даже не начнут открываться!).
    - Передаёт их в функцию использования.
    - После завершения функции (успех, ошибка, отмена) **закрывает файлы в обратном порядке**: сначала `f3`, потом `f2`, потом `f1`.

**Ключевые преимущества:**

- **Нет вложенности:** код линейный и читаемый.
- **Композиция:** `file` — это переиспользуемый строительный блок.
- **Безопасность:** порядок закрытия гарантирован, даже при отмене или ошибке.

## Пример №2: Комбинация с `eval` и работа с соединениями

`Resource.eval` полезен, когда у вас есть эффект, который не нужно освобождать, но он является частью "ресурсной" логики.

```dotty
def openConnection(host: String, port: Int): Resource[IO, Socket] =
  Resource.make(IO.println(s"Connecting to $host:$port") >> Socket(host, port))(
    s =>
      IO.println(s"Closing connection to $host:$port") >> s.close
  )

def getConfig(conn: Socket): IO[String] =
  conn.send("GET /config") >> conn.receive

val program: IO[Unit] = (
  for
    _    <- Resource.eval(IO.println("Начинаем работу"))    // Просто эффект
    conn <- openConnection("localhost", 8080)               // Ресурс
    _    <- Resource.eval(IO.println("Соединение открыто")) // Ещё эффект
  yield conn
).use { conn => // Здесь соединение уже открыто и готово к работе
  for
    config <- getConfig(conn)
    _      <- IO.println(s"Получена конфигурация: $config")
  yield ()
} // Здесь соединение будет закрыто автоматически
```

## Важные гарантии и детали поведения

### 1. Гарантированный обратный порядок освобождения

```dotty
val res =
  for
    a <- Resource.make(acquireA)(releaseA)
    b <- Resource.make(acquireB)(releaseB)
    c <- Resource.make(acquireC)(releaseC)
  yield (a, b, c)

res.use(???)
// Порядок вызовов:
// 1. acquireA
// 2. acquireB
// 3. acquireC
// 4. use(...)
// 5. releaseC
// 6. releaseB
// 7. releaseA
```

Это критически важно, так как ресурсы часто зависят друг от друга (например, `b` может зависеть от `a`).

### 2. Непрерываемость `acquire` и `release`

**`acquire` и `release` являются `uncancelable`** (непрерываемыми). Это означает, что:

- **Во время `acquire`**: ресурс будет получен полностью, даже если произошла отмена. Это предотвращает состояние "наполовину полученного" ресурса.
- **Во время `release`**: освобождение будет выполнено полностью, без прерываний. Это гарантирует, что ресурс не "утечёт".
- **Прерывание возможно только во время `use`** (между `acquire` и `release`).

```dotty
Resource.make(IO.println("Не могу быть прерван!"))( _ => IO.println("Тоже не могу!"))
```

### 3. `Resource` — это "одноразовое" использование

Каждый вызов `use` приводит к **новому получению** ресурса.

```dotty
val fileResource: Resource[IO, File] = Resource.make(openFile("a.txt"))(close)

// ❌ НЕПРАВИЛЬНО: файл откроется и закроется дважды, но для разных операций!
val program = fileResource.use(read) >> fileResource.use(read)

// ✅ ПРАВИЛЬНО: файл откроется один раз, и обе операции чтения будут выполнены с ним
val program = fileResource.use { file => read(file) >> read(file) }
```

**Следствие:** Не храните `Resource` как долгоживущий объект, из которого вы планируете много раз читать. 
Вместо этого создавайте его один раз для одного "сеанса" работы.

## Продвинутые возможности и паттерны

### `allocated` — "забрать" ресурс из `Resource`

```dotty
def allocated: F[(A, F[Unit])]
```

Выполняет `acquire`, но **не освобождает** ресурс автоматически. Возвращает кортеж: (значение, финализатор). 
**Эту функцию следует использовать с осторожностью**, так как она нарушает гарантии безопасности `Resource`.

```dotty
val (socket, finalize) =
  Resource.make(openSocket)(close).allocated.unsafeRunSync()
try
  socket.send("hello")
finally
  finalize.unsafeRunSync() // не забыть вызвать!
```

### `onFinalize` — добавить действие к освобождению

```dotty
def onFinalize(f: F[Unit]): Resource[F, A]
```

Добавляет дополнительный эффект к освобождению.

```dotty
val res = Resource.make(openFile)(close).onFinalize(IO.println("Файл будет закрыт"))
```

### `Resource.fromAutoCloseable` — для Java-ресурсов

Утилита для `AutoCloseable` ресурсов (файлы, сокеты, JDBC соединения).

```dotty
val file = Resource.fromAutoCloseable(IO(new FileInputStream("data.bin")))
```

## Итог: когда использовать `Resource`?

| Задача                                                                | Решение                                                                  |
|:----------------------------------------------------------------------|:-------------------------------------------------------------------------|
| **Работа с одним файлом/сокетом/соединением**                         | `Resource.make` + `use`                                                  |
| **Комбинация нескольких зависимых ресурсов**                          | `for` внутри `Resource` (как в примере с файлами)                        |
| **Безопасная работа с Java-ресурсами (AutoCloseable)**                | `Resource.fromAutoCloseable`                                             |
| **Простой эффект без освобождения (часть цепочки)**                   | `Resource.eval`                                                          |
| **Нужен доступ к ресурсу из долгоживущего сервера (не закрывается)**  | Рассмотрите `Resource` внутри цикла, пересоздавая его при необходимости  |

`Resource` — это стандартный, идиоматический путь работы с ресурсами в Cats Effect. 
Он заменяет цепочки вложенных `bracket` на чистый, композируемый и безопасный код.
