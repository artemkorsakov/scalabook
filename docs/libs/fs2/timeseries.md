# Временные ряды

Пакет `fs2.timeseries` предоставляет различные утилиты для работы со значениями, имеющими временные метки. 
Это особенно полезно в таких областях, как мониторинг сетевого трафика, телеметрия, логирование с временными метками, 
анализ производительности и любые другие сценарии, где важно отслеживать изменения значений во времени.

## Тип TimeStamped

Тип `TimeStamped` связывает временную метку, представленную как эпоха Unix (количество времени от начала эпохи), со значением:

```dotty
case class TimeStamped[+A](time: FiniteDuration, value: A)
```

Здесь:

- `time: FiniteDuration` — временная метка, обычно измеряемая в наносекундах или миллисекундах от начала эпохи (Unix epoch).
- `value: A` — само значение, которое может быть любого типа.

Этот простой, но мощный тип данных служит фундаментом для всех операций с временными рядами в FS2.

## Вычисление битрейта (Bitrate)

С потоками значений с временными метками можно выполнять множество интересных операций. 
Например, мы можем вычислять битрейт (скорость передачи данных в битах в секунду) для бинарных потоков:

```dotty
import fs2.Stream
import fs2.timeseries.TimeStamped
import scodec.bits.ByteVector

def withBitrate[F[_]](input: Stream[F, TimeStamped[ByteVector]]): Stream[F, TimeStamped[Either[Long, ByteVector]]] =
  TimeStamped.withPerSecondRate[ByteVector, Long](_.size * 8).toPipe(input)
```

**Детальное объяснение:**

Функция `TimeStamped.withPerSecondRate` позволяет нам агрегировать некоторую «характеристику» (feature) 
последовательности значений, полученных в каждом односекундном интервале. 
В данном случае нашей характеристикой является количество битов (размер данных в байтах, умноженный на 8), что даёт нам битрейт.

- Параметр `_.size * 8` — это функция, которая извлекает характеристику из каждого элемента `ByteVector`. 
  Здесь мы берём размер в байтах и умножаем на 8, чтобы получить количество бит.
- `withPerSecondRate` группирует входящие значения по временным меткам, соответствующим каждой секунде, 
  суммирует характеристику для каждой группы и выдаёт результат.
- Вычисленные битрейты передаются в выходной поток.
- Результат имеет тип `TimeStamped[Either[Long, ByteVector]]`:
    - `Left(bitrate)` — вычисленный битрейт (в битах в секунду) для текущего интервала.
    - `Right(ByteVector)` — исходные данные, пропущенные через поток без изменений (позволяет сохранить исходный поток для дальнейшей обработки).

## Добавление временных меток к потоку байт

Наш комбинатор `withBitrate` требует аргумент типа `Stream[F, TimeStamped[ByteVector]]`,
тогда как обычно при работе с бинарными данными (например, при чтении из сетевых сокетов) мы имеем `Stream[F, Byte]`. 
Нам нужно преобразовать поток байт в поток байт с временными метками:

```dotty
def withReceivedBitrate[F[_]](input: Stream[F, Byte]): Stream[F, TimeStamped[Either[Long, ByteVector]]] =
  input.chunks.map(c => TimeStamped.unsafeMonotonic(c.toByteVector)).through(withBitrate)
```

**Объяснение:**

1. `input.chunks` — разбивает поток байт на чанки (фрагменты). Чанки — это [внутренние единицы хранения данных в FS2](guide.md), 
   работа с ними эффективнее, чем с отдельными байтами.
2. `.map(c => TimeStamped.unsafeMonotonic(c.toByteVector))` — для каждого чанка:
    - Преобразуем его в `ByteVector` (эффективная структура данных для работы с байтами из библиотеки scodec).
    - Добавляем временную метку с помощью `TimeStamped.unsafeMonotonic`. 
      Эта функция использует монотонные часы для получения текущего времени. 
      Название содержит `unsafe`, потому что она выполняет побочный эффект (чтение системного времени) вне контекста эффекта `F`. 
      Это допустимо, поскольку чтение времени — относительно безопасная операция, 
      но в строго функциональном коде предпочтительнее использовать альтернативы с эффектами.
3. `.through(withBitrate)` — применяет ранее определённый комбинатор вычисления битрейта.

## Вычисление скользящего среднего

Каждый выдаваемый сэмпл представляет собой сумму битов, полученных в течение каждой односекундной пары. 
Теперь давайте вычислим среднее значение битрейта за последние 10 секунд. 
Это можно сделать с помощью `mapAccumulate` вместе с `scala.collection.immutable.Queue` 
(очередь — структура данных, поддерживающая операции добавления в начало и удаления с конца за O(1)):

```dotty
import scala.collection.immutable.Queue

def withAverageBitrate[F[_]](input: Stream[F, Byte])
    : Stream[F, TimeStamped[Either[Long, ByteVector]]] =
  withReceivedBitrate(input).mapAccumulate(Queue.empty[Long]) {
    case (q, tsv @ TimeStamped(_, Right(_))) => (q, tsv)
    case (q, TimeStamped(t, Left(sample)))   =>
      val q2      = (sample +: q).take(10)
      val average = q2.sum / q2.size
      (q, TimeStamped(t, Left(average)))
  }.map(_._2)
```

**Пошаговое объяснение:**

1. `withReceivedBitrate(input)` — сначала вычисляем битрейт для каждого односекундного интервала.
2. `.mapAccumulate(Queue.empty[Long])` — выполняет аккумуляцию с состоянием. Начальное состояние — пустая очередь.
3. Обработка каждого элемента:
    - Если элемент является исходными данными (`Right(_)`), мы просто пропускаем его без изменений, сохраняя очередь неизменной. 
      Это важно, потому что мы не хотим, чтобы данные влияли на вычисление среднего — среднее вычисляется только на основе битрейтов.
    - Если элемент является вычисленным битрейтом (`Left(sample)`):
        - `val q2 = (sample +: q).take(10)` — добавляем новый сэмпл в начало очереди и берём только последние 10 элементов. 
          Если в очереди было 10 элементов, старейший (последний в очереди) будет отброшен.
        - `val average = q2.sum / q2.size` — вычисляем среднее арифметическое по 10 последним значениям.
        - Возвращаем обновлённую очередь и новый элемент с вычисленным средним битрейтом.
4. `.map(_._2)` — извлекаем только вторую часть кортежа (обновлённые элементы), отбрасывая состояние очереди, так как она нам больше не нужна.

## Хранение результатов в Ref

Затем мы можем сохранить вычисленные битрейты в `Ref` для последующего просмотра, логирования и т.д. 
`Ref` — это [потокобезопасная ссылка](../../cats-effect/typeclasses/concurrent/ref.md) из библиотеки cats-effect, 
которая позволяет атомарно читать и изменять значение:

```dotty
import cats.effect.Ref
import fs2.Chunk

def measureAverageBitrate[F[_]](
    store: Ref[F, Long],
    input: Stream[F, Byte]
): Stream[F, Byte] =
  withAverageBitrate(input).flatMap {
    case TimeStamped(_, Left(bitrate)) => Stream.exec(store.set(bitrate))
    case TimeStamped(_, Right(bytes))  => Stream.chunk(Chunk.byteVector(bytes))
  }
```

**Объяснение:**

1. `withAverageBitrate(input)` — применяем вычисление среднего битрейта.
2. `.flatMap` — для каждого элемента потока:
    - Если это средний битрейт (`Left(bitrate)`): выполняем эффект сохранения в `Ref` с помощью `Stream.exec(store.set(bitrate))`. 
      `Stream.exec` создаёт поток, который выполняет эффект и ничего не выдаёт.
    - Если это исходные данные (`Right(bytes)`): пропускаем их дальше с помощью `Stream.chunk(Chunk.byteVector(bytes))`. 
      Это позволяет сохранить исходный поток байт для дальнейшей обработки (например, передачи в другой компонент системы).

## Проблема: замороженное состояние при отсутствии данных

Всё хорошо, но что происходит, если мы перестаём получать данные на некоторое время? 
В этом случае на вход `TimeStamped.withPerSecondRate` не поступает никаких данных, а значит, и выходных данных тоже нет. 
Это означает, что наш `Ref` не будет обновляться — он останется замороженным с последним значением! 
Нам нужно, чтобы `Ref` точно отражал потерю данных, то есть нам нужен способ позволить `withPerSecondRate` 
выдавать нулевые значения по мере течения времени, даже когда данные не поступают.

**Пример проблемы:**

- В секунду 1 мы получили 8000 бит. Битрейт = 8000 бит/с, сохраняем в `Ref`.
- В секунду 2 мы получили 6000 бит. Битрейт = 6000 бит/с, сохраняем в `Ref`.
- В секунду 3-10 мы не получили ни одного байта. Выходных данных от `withPerSecondRate` нет, `Ref` остаётся равным 6000, хотя реальный битрейт равен 0.
- Это вводит в заблуждение системы мониторинга и может привести к неверным решениям.

## Решение: временные ряды (Time Series)

Чтобы решить эту проблему, мы можем изменить вычисление битрейта так, 
чтобы оно работало со значениями типа `TimeStamped[Option[ByteVector]]`, 
где `TimeStamped(None)` представляет собой «тик» часов — сигнал о том, 
что прошёл один интервал времени, даже если данные не поступали.

Поток значений с типом `Option`, где `None` используется как маркер времени, называется **временным рядом (time series)**. 
Объект `fs2.timeseries.TimeSeries` определяет различные способы построения таких потоков.

### Шаг 1: Адаптация withBitrate для Option

Сначала адаптируем `withBitrate` так, чтобы он работал со значениями `TimeStamped[Option[ByteVector]]`:

```dotty
import fs2.Stream
import fs2.timeseries.{TimeStamped, TimeSeries}
import scodec.bits.ByteVector

def withBitrate[F[_]](input: Stream[F, TimeStamped[Option[ByteVector]]])
    : Stream[F, TimeStamped[Either[Long, Option[ByteVector]]]] =
  TimeStamped.withPerSecondRate[
    Option[ByteVector],
    Long
  ](_.map(_.size).getOrElse(0L) * 8).toPipe(input)
```

**Изменения:**

- Входной тип теперь `TimeStamped[Option[ByteVector]]`.
- Функция извлечения характеристики теперь обрабатывает `Option`:
    - Если есть данные (`Some(bytes)`), берём их размер и умножаем на 8.
    - Если данных нет (`None`), характеристика равна 0.
- Выходной тип теперь `TimeStamped[Either[Long, Option[ByteVector]]]`:
    - `Left(bitrate)` — битрейт (может быть 0, если данных не было).
    - `Right(Some(bytes))` — данные.
    - `Right(None)` — «тик» времени, когда данных не было.

### Шаг 2: Преобразование во временной ряд

Теперь нам нужно адаптировать `withReceivedBitrate` для преобразования нашего исходного потока во временной ряд:

```dotty
import scala.concurrent.duration.*
import cats.effect.Temporal

def withReceivedBitrate[F[_]: Temporal](input: Stream[F, Byte])
    : Stream[F, TimeStamped[Either[Long, Option[ByteVector]]]] =
  TimeSeries.timePulled(
    input.chunks.map(_.toByteVector),
    1.second,
    1.second
  ).through(withBitrate)
```

**Что здесь происходит:**

- Мы использовали операцию `timePulled` для построения временного ряда из обычного потока.
- Как следует из названия, `timePulled` добавляет временную метку к каждому полученному значению, 
  используя время системных часов (wall clock time) в момент, когда значение было извлечено из исходного потока (`pulled`).
- Параметры `timePulled`:
    - Первый `1.second` — период тиков. Каждую секунду, даже если данные не поступают, генерируется `TimeStamped(None)`. 
      Это гарантирует, что `withPerSecondRate` получает входные данные даже в периоды отсутствия трафика.
    - Второй `1.second` — период сэмплирования (или «ведро» агрегации). 
      Данные, полученные в течение каждой секунды, группируются вместе.
- Эти два параметра могут различаться. Например, мы можем получать тики каждые 100 мс, но агрегировать данные посекундно. 
  Это даёт более высокую точность временных меток.
- Результат передаётся в `withBitrate`, который теперь корректно обрабатывает как данные, так и пустые интервалы.

### Шаг 3: Остальные части вычисления

Остальные части вычисления битрейта практически не зависят от этого преобразования во временной ряд 
(кроме небольших изменений в сигнатурах типов). 
Теперь `Ref` будет обновляться даже в периоды отсутствия данных — в эти моменты битрейт будет равен 0, 
что соответствует реальности.

## Сканы (Scans)

Выше было написано несколько преобразований потоков, 
которые постепенно строили конвейер (pipe) для мониторинга битрейта, проходящего через поток. 
Каждое из этих преобразований, вплоть до финального сохранения вычисленного битрейта в `Ref`, 
было **чистым преобразованием (pure transformation)** — не вычислялось никаких эффектов и не открывалось никаких ресурсов. 
Такой тип обработки очень распространён при работе с временными рядами.

Тип `fs2.Scan` позволяет нам выражать такие чистые, сохраняющие состояние вычисления способом, 
который даёт значительно большую композиционность, чем `Pipe`. Перепишем наш пример выше с использованием `Scan`:

```dotty
import fs2.{Stream, Chunk, Scan}
import fs2.timeseries.{TimeStamped, TimeSeries}
import cats.effect.{Ref, Temporal}
import scodec.bits.ByteVector
import scala.collection.immutable.Queue
import scala.concurrent.duration.*

// Определяем Scan для вычисления битрейта
def bitrate =
  TimeStamped.withPerSecondRate[
    Option[ByteVector],
    Long
  ](_.map(_.size).getOrElse(0L) * 8)

// Определяем Scan для вычисления скользящего среднего битрейта
def averageBitrate =
  bitrate.andThen(Scan.stateful1(Queue.empty[Long]) {
    case (q, tsv @ TimeStamped(_, Right(_))) => (q, tsv)
    case (q, TimeStamped(t, Left(sample)))   =>
      val q2      = (sample +: q).take(10)
      val average = q2.sum / q2.size
      (q, TimeStamped(t, Left(average)))
  })

// Функция измерения среднего битрейта с использованием Scan
def measureAverageBitrate[F[_]: Temporal](
    store: Ref[F, Long],
    input: Stream[F, Byte]
): Stream[F, Byte] =
  TimeSeries.timePulled(input.chunks.map(_.toByteVector), 1.second, 1.second)
    .through(averageBitrate.toPipe)
    .flatMap {
      case TimeStamped(_, Left(bitrate))      => Stream.exec(store.set(bitrate))
      case TimeStamped(_, Right(Some(bytes))) =>
        Stream.chunk(Chunk.byteVector(bytes))
      case TimeStamped(_, Right(None)) => Stream.empty
    }
```

**Что изменилось и почему это лучше:**

1. **Композиция через `andThen`**:
    - В этом примере и `bitrate`, и `averageBitrate` являются экземплярами `Scan`.
    - Функция `averageBitrate` напрямую использует `bitrate` с помощью `andThen` для построения «большего» скана. 
      Это напоминает композицию функций: мы говорим «сначала примени битрейт, затем примени скользящее среднее».
    - Такая композиция намного читаемее и легче для понимания, чем вложенные вызовы `through`.

2. **Отделение логики от выполнения**:
    - `Scan` — это чистое описание преобразования. Оно не содержит эффектов и не зависит от конкретного типа эффекта `F`.
    - После того как мы закончили композицию сканов, мы преобразуем скан в `Pipe` с помощью `.toPipe` 
      и применяем его к входному потоку. Это разделение позволяет легко тестировать логику скана независимо от эффектов.

3. **Повторное использование**:
    - Сканы можно легко комбинировать, переиспользовать и тестировать по отдельности.
    - Например, мы могли бы определить другие сканы (например, для вычисления максимального битрейта, медианы и т.д.) 
      и скомбинировать их вместе.

4. **Обработка `None`**:
    - В финальной обработке мы явно обрабатываем случай `Right(None)` (пустой тик), пропуская его. 
      Это позволяет избежать записи пустых значений в результирующий поток.

## Обзор комбинаторов TimeStamped и TimeSeries

В пакете `fs2.timeseries` существует множество комбинаторов на `TimeStamped` и `TimeSeries`, 
которые предоставляют различные сканы (scans). Вот некоторые из них:

### Комбинаторы TimeStamped:

- `withPerSecondRate` — вычисляет скорость изменения характеристики в секунду. Используется в примерах выше для битрейта.
- `withRate` — более общая версия, позволяющая задать произвольный интервал.
- `withCountPerSecond` — подсчитывает количество элементов в секунду.
- `map`, `filter`, `flatMap` — стандартные операции над значениями с сохранением временных меток.

### Комбинаторы TimeSeries:

- `timePulled` — создаёт временной ряд из обычного потока, добавляя временные метки в момент извлечения.
- `timeArrival` — создаёт временной ряд, используя время получения элемента (может отличаться от времени извлечения в асинхронных системах).
- `tick` — генерирует периодические тики (значения `None`) с заданным интервалом.
- `sample` — сэмплирует поток с заданной частотой.
- `filter` / `collect` — фильтруют значения во временном ряду.
- `map` — преобразует значения с сохранением временных меток.

### Комбинаторы Scan:

- `stateful1` — создаёт скан с одним состоянием (как в примере с очередью).
- `stateful` — создаёт скан с произвольным состоянием и возможностью возвращать несколько выходных значений.
- `andThen` — композиция сканов (последовательное применение).
- `zipWith` — комбинирует два скана параллельно.
- `toPipe` — преобразует скан в `Pipe` для использования в потоке.

## Преимущества подхода со сканами

Использование `Scan` вместо прямого манипулирования потоками даёт несколько важных преимуществ:

1. **Чистота** — сканы являются чистыми функциями, не содержащими эффектов. Это упрощает рассуждение о программе и её тестирование.
2. **Композиционность** — сканы легко комбинируются с помощью `andThen`, `zipWith` и других комбинаторов.
3. **Переиспользование** — один и тот же скан можно использовать в разных частях программы с разными входными потоками.
4. **Отделение логики от инфраструктуры** — логика обработки данных отделена от кода, 
   отвечающего за выполнение эффектов (например, чтение из сокета, запись в `Ref`).
5. **Производительность** — сканы работают на уровне чанков (chunks), 
   что минимизирует накладные расходы на обработку каждого отдельного элемента.
