# Общее состояние и области совместного использования

## Что такое общее состояние в функциональной конкурентности?

В конкурентном функциональном программировании **общее состояние** — 
это любые данные, которые одновременно используются несколькими волокнами (fibers). 
Примерами общего состояния являются:

- [Ref](../../typeclasses/concurrent/ref.md) — общая переменная
- [Semaphore](../semaphore.md) — счётчик разрешений
- [Deferred](../../typeclasses/concurrent/deferred.md) — сигнал для ожидания
- [Queue](../queue.md) — очередь сообщений
- [Mutex](../mutex.md) — блокировка

Однако в отличие от императивных языков, где общее состояние часто является **глобальным** (например, `static` переменная), 
в Cats Effect общее состояние создаётся **локально** и его область действия явно контролируется через `flatMap`.

## Ключевая идея: Области совместного использования

В Cats Effect **область совместного использования** определяется границами `flatMap` (или синтаксическим сахаром for-comprehension). 
Когда вы создаёте общее состояние внутри `flatMap`, вы чётко определяете, где оно будет доступно.

```dotty
for
  sem <- Semaphore[IO](1) // ← начало области совместного использования
  // sem доступен здесь
  _ <- something(sem)
// sem всё ещё доступен
yield ()
// sem больше НЕ доступен — область закончилась
```

Это похоже на **принцип наименьших привилегий** (least privilege): ресурс существует только там, где он нужен.

## Пример 1: Правильное совместное использование через `flatMap`

В этом примере два бесконечных процесса `p1` и `p2` делят один семафор, который ограничивает доступ к "дорогой" операции. 
Семафор создаётся в области `flatMap` и **явно передаётся** обеим функциям.

```dotty
import scala.concurrent.duration.*
import cats.effect.*
import cats.effect.std.{Semaphore, Supervisor}

object Regions extends IOApp.Simple:

  // Имитация случайной задержки (700–800 мс)
  val randomSleep: IO[Unit] =
    IO(scala.util.Random.nextInt(100)).flatMap { ms =>
      IO.sleep((ms + 700).millis)
    }.void

  // Процесс 1: захватывает разрешение, печатает, затем спит
  def p1(sem: Semaphore[IO]): IO[Unit] =
    sem.permit.surround(IO.println("Running P1")) >> randomSleep

  // Процесс 2: аналогично
  def p2(sem: Semaphore[IO]): IO[Unit] =
    sem.permit.surround(IO.println("Running P2")) >> randomSleep

  def run: IO[Unit] =
    Supervisor[IO].use { supervisor =>
      // Создаём семафор с 1 разрешением ВНУТРИ области Supervisor
      Semaphore[IO](1).flatMap { sem =>
        // Запускаем оба процесса под надзором супервизора
        supervisor.supervise(p1(sem).foreverM).void *>
          supervisor.supervise(p2(sem).foreverM).void *>
          // Даём поработать 5 секунд
          IO.sleep(5.seconds).void
      }
    }
end Regions
```

### Что здесь важно?

| Элемент               | Роль                                                                           |
|:----------------------|:-------------------------------------------------------------------------------|
| `Semaphore[IO](1)`    | Создаётся **внутри** `flatMap`, его область действия ограничена блоком.        |
| `p1(sem)`, `p2(sem)`  | Семафор **явно передаётся** как параметр. Нет глобального доступа.             |
| `Supervisor`          | Запускает долгоживущие процессы, но не влияет на область видимости состояния.  |

**Результат:** `p1` и `p2` конкурируют за одно разрешение. 
Порядок выполнения непредсказуем, но они никогда не работают одновременно. 
При этом семафор **не виден** за пределами `flatMap`.

## Почему структуры данных возвращают `F[Something]`?

Вы могли заметить: `Semaphore[IO](1)` возвращает не `Semaphore[IO]`, а `IO[Semaphore[IO]]`. Это сделано **намеренно**.

```dotty
// Создание семафора — эффект!
val create: IO[Semaphore[IO]] = Semaphore[IO](1)

// Использование
create.flatMap { sem => // только здесь sem доступен
  // ...
}
```

**Причины:**

1. **Атомарность инициализации:** Создание семафора может включать внутреннее состояние (`Ref`), которое должно быть создано атомарно.
2. **Явная область видимости:** Вы не можете "случайно" сделать семафор глобальным, не выполнив эффект.
3. **Безопасность ресурсов:** Если создание ресурса — это эффект, его можно вписать в `Resource` или `bracket`.
4. **Referential transparency:** Всё остаётся чистой функцией.

> **Аналогия из ООП:** Это как если бы конструктор класса мог быть вызван только внутри `try-with-resources` 
> или `using` — вы не можете создать объект вне контекста.

## Пример 2: Утечка состояния (Leaky State) — ЧТО НЕЛЬЗЯ ДЕЛАТЬ

Теперь рассмотрим **плохой** пример, где общее состояние становится глобальным и неконтролируемым.

```dotty
import scala.concurrent.duration.*
import cats.effect.*
import cats.effect.std.{Semaphore, Supervisor}
import cats.effect.unsafe.implicits.global

object LeakyState extends IOApp.Simple:

  // ❌ ГЛОБАЛЬНЫЙ СЕМАФОР — создаётся один раз вне контроля
  lazy val sem: Semaphore[IO] =
    Semaphore[IO](1).unsafeRunSync() // анти-паттерн!

  def launchMissiles: IO[Unit] =
    sem.permit.surround {
      IO.println("Запуск ракет") >>
        IO.sleep(3.seconds) >>
        IO.println("Ракеты запущены, блокировка снята")
    }

  def randomSleep: IO[Unit] =
    IO(scala.util.Random.nextInt(100)).flatMap { ms =>
      IO.sleep((ms + 700).millis)
    }.void

  def p1: IO[Unit] =
    sem.permit.surround(IO.println("Running P1")) >> randomSleep

  def p2: IO[Unit] =
    sem.permit.surround(IO.println("Running P2")) >> randomSleep

  def run: IO[Unit] =
    Supervisor[IO].use { supervisor =>
      supervisor.supervise(launchMissiles) *>
        supervisor.supervise(p1.foreverM).void *>
        supervisor.supervise(p2.foreverM).void *>
        IO.sleep(5.seconds).void
    }
end LeakyState

// Running P1
// Запуск ракет
// Ракеты запущены, блокировка снята
// Running P2
// Running P1
// Running P2
// Running P1
// Running P2
// Running P1
```

### Почему это опасно?

1. **Глобальный доступ:** `sem` доступен из любой точки программы, включая `launchMissiles`, `p1`, `p2`.
2. **Неявное разделение:** Вы не видите, где и как используется семафор, просто взглянув на сигнатуру функции.
3. **Риск блокировки:** Если `launchMissiles` захватит разрешение и никогда его не отпустит 
   (например, из-за ошибки или бесконечного цикла), `p1` и `p2` заблокируются навсегда.
4. **Тестирование:** Нельзя легко подменить семафор в тестах — он жёстко зашит.
5. **Неопределённое поведение:** `unsafeRunSync()` вне `IOApp` может привести к зависаниям, особенно на платформах типа Scala.js.

### Что произойдёт при запуске `LeakyState`?

Возможен сценарий:

- `launchMissiles` захватывает разрешение.
- `p1` и `p2` пытаются захватить разрешение → блокируются.
- Через 3 секунды `launchMissiles` завершается и освобождает разрешение.
- `p1` или `p2` захватывает его, но процесс уже потерял 3 секунды.
- В большой программе трудно предсказать, кто и когда захватит разрешение, и не приведёт ли один "жадный" процесс к голоданию других.

## Сравнение: Правильное состояние vs Утечка

| Аспект                        | ✅ Правильное (Regions)          | ❌ Утечка (LeakyState)          |
|:------------------------------|:--------------------------------|:-------------------------------|
| **Создание**                  | Внутри `flatMap`, явный эффект  | Глобально, `unsafeRunSync()`   |
| **Область видимости**         | Локальная, ограничена блоком    | Глобальная, доступна отовсюду  |
| **Передача в функции**        | Явный параметр                  | Неявная (через замыкание)      |
| **Тестируемость**             | Легко подменить семафор         | Невозможно без переписывания   |
| **Риск блокировки**           | Низкий (видно, кто использует)  | Высокий (скрытые зависимости)  |
| **Referential transparency**  | Да                              | Нет (из-за `unsafeRunSync`)    |

## Главная идея: Область совместного использования = `flatMap`

В Cats Effect **область совместного использования** — это **блок кода**, где общее состояние создаётся и используется.

```dotty
// Область совместного использования начинается здесь
Semaphore[IO](1).flatMap { sem =>
  // Всё, что здесь — видит sem
  p1(sem) *> p2(sem)
}
// Здесь sem уже недоступен
```

**Как это помогает?**

- Вы можете видеть **всех пользователей** общего состояния, просто посмотрев на блок.
- Нет скрытых зависимостей через глобальные переменные.
- Легко рефакторить и тестировать.

## Практические выводы

### ✅ Что нужно делать:

1. Всегда создавайте общее состояние внутри `flatMap` или `for`.
2. Передавайте его **явно** как параметр туда, где оно нужно.
3. Используйте `Resource` для долгоживущих состояний (например, пул соединений).
4. Тестируйте, создавая состояние локально внутри теста.

```dotty
test("semaphore works") {
  Semaphore[IO](1).flatMap { sem =>
    // тестируем sem
  }
}
```

### ❌ Чего нужно избегать:

1.  **Глобальных переменных** с общим состоянием (`lazy val` + `unsafeRunSync`).
2.  **`unsafeRunSync()`** вне `IOApp` (это "лазейка" только для REPL и тестовых примеров).
3.  Создания состояния без явной области видимости (например, внутри объекта `object`).
4.  Передачи состояния **неявно** через замыкания (затрудняет понимание зависимостей).

## Итог

- **Общее состояние в Cats Effect** — это не магия, а обычные значения (`Ref`, `Semaphore` и др.), 
  которые **создаются в эффекте** и **обладают явной областью видимости** через `flatMap`.
- **Область совместного использования** — это блок кода, ограниченный `flatMap`, внутри которого состояние доступно.
- **Утечка состояния** происходит, когда вы создаёте общее состояние **глобально**, вне `flatMap`, 
  и оно становится доступным неконтролируемо.
- Следуя принципу "создавай внутри `flatMap`, передавай явно", 
  вы получите **предсказуемый, тестируемый и безопасный** конкурентный код.

Это одна из фундаментальных причин, почему Cats Effect (и другие функциональные системы эффектов) 
проектируют свои структуры данных, возвращая `F[Thing]`, а не просто `Thing`. 
Они заставляют вас **думать об области совместного использования**.
