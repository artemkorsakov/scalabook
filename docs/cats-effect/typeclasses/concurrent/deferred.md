# `Deferred` — Однократный контейнер для синхронизации волокон

`Deferred[F[_], A]` — это **чисто функциональный примитив синхронизации**, 
который представляет собой **однократный контейнер** для значения типа `A`. 
В момент создания контейнер **пуст**. 
В него можно **ровно один раз** положить значение, после чего контейнер становится **заполненным** навсегда.

Представьте себе "комнату ожидания" с одной дверью:

- Сначала комната пуста.
- Волокна могут **ждать снаружи** (`get`), пока кто-то не откроет дверь.
- **Первый**, кто придёт с ключом (`complete(a)`), открывает дверь и кладёт значение.
- Все ожидающие немедленно получают это значение и "заходят".
- Все последующие попытки принести ключ (`complete`) игнорируются.

### Базовый интерфейс

В своей простейшей форме `Deferred` выглядит так:

```dotty
abstract class Deferred[F[_], A]:
  /** Ожидает появления значения. */
  def get: F[A]

  /** Пытается установить значение (только если контейнер пуст). */
  def complete(a: A): F[Boolean]
  
  /** Возращает значение, если оно есть. */
  def tryGet: F[Option[A]]
```

## Подробное поведение операций

### `get` — Ожидание значения

Поведение метода `get` строго определено и предсказуемо:

| Состояние `Deferred`          | Поведение `get`                                                                                                                                                                            |
|-------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Пуст**                      | Волокно **семантически блокируется** до тех пор, пока другой вызов не выполнит `complete`. Блокировка **не блокирует поток ОС** (используется асинхронное ожидание).                       |
| **Заполнен**                  | Значение возвращается **немедленно**.                                                                                                                                                      |
| **Отмена во время ожидания**  | Если волокно, вызвавшее `get`, было отменено, оно **автоматически отписывается** от уведомления и не будет разбужено при `complete`. Это предотвращает утечки памяти и "висящие" волокна.  |

> **Важно:** Блокировка в `get` — **семантическая**. Под капотом Cats Effect не блокирует системные потоки, 
> а переключает волокно в режим ожидания, позволяя другим волокнам использовать вычислительные ресурсы.

### `complete` — Установка значения

Поведение метода `complete` также строго определено:

| Состояние `Deferred`  | Поведение `complete(a)`                                                                | Возвращаемое значение  |
|-----------------------|----------------------------------------------------------------------------------------|------------------------|
| **Пуст**              | Устанавливает значение `a`, **немедленно пробуждает** все волокна, ожидающие в `get`.  | `true`                 |
| **Заполнен**          | **Ничего не меняет**. Значение остаётся первоначальным.                                | `false`                |

Возвращаемый `Boolean` позволяет определить, был ли ваш `complete` первым (или единственным успешным).

### `tryGet` — неблокирующая проверка

Возвращает `Some(a)`, если `Deferred` заполнен, и `None` — если пуст. **Никогда не блокируется.**

```dotty
for
  d     <- Deferred[IO, String]
  empty <- d.tryGet // None
  _     <- d.complete("done")
  full  <- d.tryGet // Some("done")
yield ()
```

## Простой пример: координация двух волокон

Этот пример показывает, как одно волокно ожидает сигнала от другого.

```dotty
object DeferredExample extends IOApp.Simple:
  val run: IO[Unit] =
    for
      // Создаём пустой Deferred для сигнала (значение Unit)
      signal <- Deferred[IO, Unit]

      // Волокно-ожидатель: запускаем первым, оно заблокируется
      waiter <-
      (IO.println("Ожидаю сигнала...") >> signal.get >>
        IO.println("Сигнал получен! Продолжаю работу.")).start

      // Волокно-сигнальщик: спим 2 секунды, затем даём сигнал
      _ <-
      (IO.sleep(2.seconds) >>
        IO.println("Посылаю сигнал!") >>
        signal.complete(())).start

      // Даём волокнам время завершиться
      _ <- waiter.join
    yield ()
end DeferredExample
```

**Вывод:**

```
Ожидаю сигнала...
(через 2 секунды)
Посылаю сигнал!
Сигнал получен! Продолжаю работу.
```

## Паттерн: "Только один раз" (первый победитель)

Классический сценарий: множество конкурентных процессов пытаются выполнить действие, 
но **результат нужен только от первого успешного**.

```dotty
def firstSuccessful[F[_]: Concurrent, A](tasks: List[F[A]]): F[A] =
  for
    deferred <- Deferred[F, A] // Создаём пустой контейнер
    // Запускаем все задачи в режиме гонки
    fibers <- tasks.traverse { task =>
      task.flatMap(a => deferred.complete(a).void).start
    }
    // Ждём первого, кто завершит deferred
    result <- deferred.get
    // Отменяем остальные (опционально, для экономии ресурсов)
    _ <- fibers.traverse_(_.cancel)
  yield result

// Использование
val program = firstSuccessful(List(
  IO.sleep(3.seconds) >> IO.pure("Медленный"),
  IO.sleep(1.second) >> IO.pure("Быстрый"),
  IO.sleep(2.seconds) >> IO.raiseError(new Exception("Ошибка"))
)).flatMap(IO.println) // Выведет "Быстрый"
```

**Как это работает:**

1. Все три задачи стартуют одновременно.
2. Каждая задача, завершаясь успешно, пытается вызвать `deferred.complete`.
3. Первая успешная задача устанавливает значение — остальные вызовы `complete` получат `false` и будут проигнорированы.
4. `deferred.get` дожидается первого значения и возвращает его.
5. Оставшиеся задачи могут быть отменены (по желанию).

## Сравнение с другими примитивами

| Примитив           | Назначение             | Ключевая особенность                                                 |
|--------------------|------------------------|----------------------------------------------------------------------|
| **`Ref[A]`**       | Атомарная переменная   | Может обновляться бесконечно, хранит всегда доступное значение       |
| **`Deferred[A]`**  | Однократный контейнер  | Заполняется ровно один раз, позволяет блокироваться до заполнения    |
| **`Semaphore`**    | Счётный семафор        | Позволяет ограничивать параллелизм, многократно `acquire`/`release`  |
| **`Queue`**        | Конкурентная очередь   | Хранит множество значений, Producer-Consumer паттерн                 |
| **`Mutex`**        | Взаимное исключение    | Блокировка, которую может захватить только одно волокно за раз       |

## Типичные сценарии использования `Deferred`

| Сценарий                                            | Почему подходит                                                                         |
|-----------------------------------------------------|-----------------------------------------------------------------------------------------|
| **Ожидание завершения инициализации ресурса**       | Нужно убедиться, что все потребители ждут, пока один создатель подготовит ресурс.       |
| **Реализация "гонки" между операциями**             | Первая успешная операция заполняет `Deferred`, остальные отменяются или игнорируются.   |
| **Координация старта нескольких волокон**           | Все волокна вызывают `get` и стартуют одновременно после одного `complete`.             |
| **Сигнализация об ошибке в конкурентном процессе**  | Одно волокно использует `complete(error)` как канал для уведомления других о проблеме.  |
| **Однократный кеш для дорогого вычисления**         | Значение вычисляется один раз, затем сохраняется навсегда.                              |

`Deferred` — это простой, но невероятно мощный инструмент. 
В сочетании с `Ref` он позволяет строить практически любые конкурентные структуры: 
семафоры, барьеры, каналы, пулы потоков и даже транзакционную память (STM).
