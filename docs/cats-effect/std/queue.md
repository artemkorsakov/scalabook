# Queue — Асинхронная очередь для обмена данными

`Queue[F[_], A]` — это **чисто функциональная, конкурентная очередь**, 
предназначенная для безопасного обмена данными между волокнами. 
Она является аналогом `java.util.concurrent.BlockingQueue`, но полностью интегрирована с эффектами Cats Effect 
и использует **семантическую блокировку**, не останавливая системные потоки.

Волокна могут:

- **Класть** элементы в очередь (`offer`).
- **Забирать** элементы из очереди (`take`).

Основное преимущество — **безопасная коммуникация** между производителями (producers) и потребителями (consumers) в конкурентной среде.

### Базовый интерфейс

```dotty
trait Queue[F[_], A]:
  /** Извлекает элемент из очереди. Блокирует волокно, если очередь пуста. */
  def take: F[A]

  /** Пытается извлечь элемент без блокировки. */
  def tryTake: F[Option[A]]

  /** Добавляет элемент в очередь. Блокирует волокно, если очередь заполнена
    * (для bounded очередей).
    */
  def offer(a: A): F[Unit]

  /** Пытается добавить элемент без блокировки. Возвращает `true`, если элемент
    * был добавлен.
    */
  def tryOffer(a: A): F[Boolean]
```

## Виды очередей и их политики

`Queue` может быть создана с разной поведенческой политикой, которая определяет, 
как ведут себя операции `offer` и `take` при достижении предельной вместимости.

| Тип очереди                              | Поведение `offer` при заполнении                                                            | Поведение `take` при пустоте                                    | Создание                                       |
|:-----------------------------------------|:--------------------------------------------------------------------------------------------|:----------------------------------------------------------------|:-----------------------------------------------|
| **Ограниченная (bounded)**               | **Блокируется**, пока не освободится место.                                                 | **Блокируется**, пока не появится элемент.                      | `Queue.bounded(capacity)`                      |
| **Неограниченная (unbounded)**           | Никогда не блокируется. Всегда успешна.                                                     | **Блокируется**, пока не появится элемент.                      | `Queue.unbounded`                              |
| **Синхронная (synchronous)**             | Блокируется, пока другой вызов `take` не заберёт элемент.                                   | Блокируется, пока другой вызов `offer` не предоставит элемент.  | `Queue.synchronous` (эквивалент `bounded(0)`)  |
| **Отбрасывающая (dropping)**             | Никогда не блокируется. **Новый элемент отбрасывается**, если очередь заполнена.            | Блокируется, пока не появится элемент.                          | `Queue.dropping(capacity)`                     |
| **Циркулярный буфер (circular buffer)**  | Никогда не блокируется. **Самый старый элемент перезаписывается**, если очередь заполнена.  | Блокируется, пока не появится элемент.                          | `Queue.circularBuffer(capacity)`               |

### Выбор правильной очереди: примеры

- **`bounded`**: Классический producer-consumer. Идеально, когда нужно ограничить потребление ресурсов 
  или выровнять нагрузку между быстрым продюсером и медленным консьюмером.
- **`unbounded`**: Удобна, когда продюсер всегда успевает, или потеря данных недопустима. 
  **Осторожно**: может привести к переполнению памяти при постоянно растущей очереди.
- **`synchronous`**: Для прямого обмена сообщениями "рука-об-руку" (handoff). Каждый `offer` ждёт свой `take`.
- **`dropping`**: Для телеметрии или логов, где важны только самые свежие данные, и можно пожертвовать старыми.
- **`circularBuffer`**: Для кэша или скользящего окна событий, где всегда нужны последние `N` элементов.

## Глубокое погружение: Операции с очередью

### `take` — Ожидание элемента

- **Если очередь не пуста**: элемент извлекается и возвращается **немедленно**.
- **Если очередь пуста**: волокно **семантически блокируется**, то есть оно приостанавливается и перестаёт занимать поток ОС. 
  Как только другой поток вызовет `offer`, ожидающее волокно будет разбужено и получит элемент.
- **Отменяемость**: ожидание в `take` полностью отменяемо. Если волокно отменить, оно корректно удалится из очереди ожидания.

### `offer` — Добавление элемента

- **В `unbounded`**: элемент всегда добавляется мгновенно. Блокировки нет.
- **В `bounded` и `synchronous`**:
  - Если очередь **не заполнена**, элемент добавляется, а если есть ожидающие `take` — они мгновенно получают элемент. Операция успешна.
  - Если очередь **заполнена**, волокно блокируется и встаёт в очередь ожидания `offer`, пока какой-нибудь `take` не освободит место.
- **В `dropping` и `circularBuffer`**: операция **никогда не блокируется**, 
  но элемент может быть отброшен (dropping) или перезаписать старый (circular buffer).

### `tryTake` / `tryOffer` — Неблокирующие версии

Полезны, когда нужно опросить очередь или попытаться добавить элемент, но не ждать.

- `tryTake`: возвращает `Some(a)`, если элемент был немедленно доступен, и `None`, если очередь пуста.
- `tryOffer`: возвращает `true`, если элемент был успешно добавлен (с учётом политики очереди!), 
  и `false` в противном случае (например, очередь заполнена в `dropping`).

## Пример 1: Producer-Consumer с `bounded` очередью

Это самый классический сценарий. Один или несколько продюсеров создают данные, один или несколько консьюмеров их обрабатывают.

```dotty
import cats.effect.{IO, IOApp}
import cats.effect.std.Queue
import cats.syntax.all.*

object ProducerConsumer extends IOApp.Simple:
  val run: IO[Unit] =
    for
      queue <- Queue.bounded[IO, String](5) // Очередь вместимостью 5 сообщений

      producer = (id: Int) =>
        (1 to 10).toList.traverse_ { i =>
          val msg = s"Producer_$id: Msg_$i"
          queue.offer(msg) >> IO.println(s"ОТПРАВЛЕНО: $msg")
        }

      consumer = (id: Int) =>
        queue.take.flatMap { msg =>
          IO.println(s"Consumer_$id: ПОЛУЧЕНО: $msg")
        }.foreverM // Бесконечно потребляем

      // Запускаем 2 продюсеров и 3 консьюмеров параллельно
      _ <- List(
        producer(1).start,
        producer(2).start,
        consumer(1).start,
        consumer(2).start,
        consumer(3).start
      ).parSequence
    yield ()
```

**Как это работает:**

1.  Продюсеры быстро шлют сообщения. Если очередь из 5 элементов заполняется, следующий `offer` **заблокирует** продюсера.
2.  Консьюмеры ждут (`take`) и обрабатывают сообщения.
3.  Как только консьюмер забирает сообщение, в очереди появляется место, и заблокированный продюсер просыпается и отправляет следующее сообщение.

```text
ОТПРАВЛЕНО: Producer_2: Msg_1
ОТПРАВЛЕНО: Producer_1: Msg_1
Consumer_1: ПОЛУЧЕНО: Producer_2: Msg_1
ОТПРАВЛЕНО: Producer_2: Msg_2
ОТПРАВЛЕНО: Producer_2: Msg_3
ОТПРАВЛЕНО: Producer_2: Msg_4
...
ОТПРАВЛЕНО: Producer_1: Msg_9
Consumer_2: ПОЛУЧЕНО: Producer_1: Msg_9
ОТПРАВЛЕНО: Producer_1: Msg_10
Consumer_3: ПОЛУЧЕНО: Producer_1: Msg_10
```

## Пример 2: Использование `dropping` для телеметрии

Представьте, что вы собираете метрики от миллионов сенсоров, но можете обрабатывать только 100 самых последних в секунду.

```dotty
import cats.effect.std.Queue
import cats.effect.{IO, IOApp}

object Telemetry extends IOApp.Simple:
  val run: IO[Unit] =
    for
      metricsQueue <-
        Queue.dropping[IO, Metric](100) // Очередь на 100, лишнее отбрасываем
      // Поток-обработчик: забирает и сохраняет метрики
      _ <- metricsQueue.take.flatMap(saveMetric).foreverM.start
      // Симуляция потока-сенсора
      _ <- (1 to 10000).toList.traverse_ { i =>
        metricsQueue.offer(Metric(i, System.currentTimeMillis()))
      }
    yield ()
```

**Преимущество:** Система не будет захлёбываться и не будет блокировать сенсоры, 
но мы рискуем потерять часть данных, если подача превысит пропускную способность.

## Функториальность: `QueueSource` и `QueueSink`

Это мощная и элегантная возможность, редко встречающаяся в других языках. `Queue` разделена на два интерфейса:

```dotty
trait QueueSource[F[_], A]:
  def take: F[A]
  def tryTake: F[Option[A]]

object QueueSource:
  implicit def catsFunctorForQueueSource[F[_]: Functor]
      : Functor[[A] =>> QueueSource[F, A]] =
    new Functor[[A] =>> QueueSource[F, A]]:
      def map[A, B](fa: QueueSource[F, A])(f: A => B): QueueSource[F, B] =
        ???
        
trait QueueSink[F[_], A]:
  def offer(a: A): F[Unit]
  def tryOffer(a: A): F[Boolean]

object QueueSink:
  implicit def catsContravariantForQueueSink[F[_]]
      : Contravariant[[A] =>> QueueSink[F, A]] =
    new Contravariant[[A] =>> QueueSink[F, A]]:
      def contramap[A, B](fa: QueueSink[F, A])(f: B => A)
          : QueueSink[F, B] = ???
```

Это позволяет вам:

1. **Преобразовывать очередь на чтение (`map`):** Например, иметь очередь байтов, но читать из неё как из очереди строк (`String`), 
   применяя функцию преобразования на лету.
2. **Преобразовывать очередь на запись (`contramap`):** Например, иметь очередь чисел, но отправлять в неё булевы значения (`Boolean`), 
   преобразуя `true` в `1`, а `false` в `0`.

### Пример: Ковариантность (`map`)

Допустим, у вас есть очередь `Int`, но вам нужен источник `Long`.

```dotty
import cats.Functor
import cats.effect.std.{Queue, QueueSource}

val intQueue: IO[Queue[IO, Int]] = Queue.bounded[IO, Int](10)

intQueue.flatMap: queue =>
  // Преобразуем очередь-источник Int'ов в очередь-источник Long'ов
  val longSource: QueueSource[IO, Long] =
    Functor[[A] =>> QueueSource[IO, A]].map(queue)(_.toLong) // Int -> Long

  // Теперь можно класть Int'ы, а забирать Long'и
  queue.offer(42) >> longSource.take.map(println) // Напечатает: 42L
```

### Пример: Контравариантность (`contramap`)

Допустим, у вас есть очередь `Int`, но вам нужен приёмник `Boolean`.

```dotty
import cats.Contravariant
import cats.effect.std.{Queue, QueueSink}

val intQueue: IO[Queue[IO, Int]] = Queue.bounded[IO, Int](10)

intQueue.flatMap: queue =>
  // Преобразуем очередь-приёмник Int'ов в очередь-приёмник Boolean'ов
  val boolSink: QueueSink[IO, Boolean] =
    Contravariant[[A] =>> QueueSink[IO, A]]
      .contramap(queue)(b => if b then 1 else 0)

  // Теперь можно отправлять Boolean'ы, а забирать Int'ы
  boolSink.offer(true) >> queue.take.map(println)  // Напечатает: 1
  boolSink.offer(false) >> queue.take.map(println) // Напечатает: 0
```

**Где это полезно?** Когда у вас есть сложная система из нескольких очередей, 
и вы хотите соединить их, не создавая промежуточных структур данных.

## Итог: какую очередь выбрать?

| Сценарий                                                                   | Рекомендуемый тип очереди         |
|:---------------------------------------------------------------------------|:----------------------------------|
| **Балансировка нагрузки между разными по скорости producer/consumer**      | `bounded`                         |
| **Нужно гарантированно обработать все сообщения, продюсер очень быстрый**  | `unbounded` (следить за памятью)  |
| **Прямой обмен сообщениями (handoff), буфер не нужен**                     | `synchronous`                     |
| **Важны только самые свежие данные (логи, метрики, показания сенсоров)**   | `dropping`                        |
| **Нужно хранить последние N элементов (история чата, скользящее окно)**    | `circularBuffer`                  |
| **Работа с разными типами данных в одном потоке**                          | `map` / `contramap`               |
