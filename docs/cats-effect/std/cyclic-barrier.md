# CyclicBarrier — Многократный барьер синхронизации

`CyclicBarrier[F[_]]` — это **многократно используемый примитив синхронизации**, 
который позволяет группе волокон **ожидать друг друга** в определённой точке выполнения. 
Барьер инициализируется положительным целым числом `n` (количество участников). 
Когда `n` волокон вызывают `await`, **все они одновременно разблокируются**, а барьер **сбрасывается** для следующего цикла.

**Метафора:** Представьте экскурсионную группу, которая ждёт у автобуса. 
Водитель не тронется в путь, пока **все** туристы не соберутся (`await`). 
Когда подошли все 10 человек, водитель открывает двери, все заходят, и барьер сбрасывается для следующей экскурсии.

```dotty
trait CyclicBarrier[F[_]]:
  /** Ожидает, пока все n участников не вызовут await.
    * Когда это произойдёт, все разблокируются, барьер сбрасывается. */
  def await: F[Unit]
```

**Ключевые характеристики:**

- **Многократный** — после того как барьер пройден, его можно использовать снова (в отличие от `CountDownLatch`).
- **Синхронный для всех** — все участники освобождаются одновременно.
- **Отменяемый** — если одно волокно отменяется во время ожидания, барьер "теряет" его и будет ждать полного набора снова.

## Создание `CyclicBarrier`

```dotty
import cats.effect.IO
import cats.effect.std.CyclicBarrier

val barrier: IO[CyclicBarrier[IO]] = CyclicBarrier[IO](3)  // барьер на 3 участника
```

Параметр `n` должен быть **положительным целым числом** (≥ 1).

## Как это работает под капотом?

```
Инициализация: барьер ждёт 3 участника
          │
          ▼
   Волокно 1 вызывает await ──► ждёт
   Волокно 2 вызывает await ──► ждёт
   Волокно 3 вызывает await ──► ждёт
          │
          ▼
   Все 3 собрались! ──► одновременная разблокировка
          │
          ▼
   Барьер сбрасывается ──► снова ждёт 3 участника
```

**Важное отличие от `CountDownLatch`:** В `CountDownLatch` неважно, кто вызывает `release`, важен общий счётчик. 
В `CyclicBarrier` же **каждый участник лично** должен вызвать `await`. Нельзя "заменить" одного участника другим.

## Подробный пример: три волокна с разной скоростью

Этот пример показывает, как барьер заставляет быстрое волокно ждать медленные.

```dotty
import cats.effect.{IO, IOApp}
import cats.effect.std.CyclicBarrier
import scala.concurrent.duration.*
import cats.syntax.all.*

object BarrierDemo extends IOApp.Simple:
  val run: IO[Unit] =
    for
      barrier <- CyclicBarrier[IO](2) // барьер на 2 участника

      // Быстрое волокно (доходит до барьера почти сразу)
      f1 <-
      (IO.println("⚡ FAST: дошёл до барьера") *>
        barrier.await *>
        IO.println("⚡ FAST: прошёл барьер!")).start

      // Медленное волокно (спит 2 секунды перед барьером)
      f2 <-
      (IO.sleep(2.seconds) *>
        IO.println("🐢 SLOW: дошёл до барьера") *>
        barrier.await *>
        IO.println("🐢 SLOW: прошёл барьер!")).start

      _ <- (f1.join, f2.join).tupled
    yield ()
end BarrierDemo
```

**Вывод:**

```
⚡ FAST: дошёл до барьера
(пауза ~2 секунды)
🐢 SLOW: дошёл до барьера
⚡ FAST: прошёл барьер!
🐢 SLOW: прошёл барьер!
```

**Что произошло:**

1. Быстрое волокно доходит до барьера и **блокируется**, ожидая второго участника.
2. Медленное волокно спит 2 секунды, затем доходит до барьера.
3. Когда оба волокна достигли барьера, они **одновременно** разблокируются и продолжают выполнение.

## Многократное использование (цикличность)

В отличие от `CountDownLatch`, `CyclicBarrier` можно использовать многократно. 
После того как все участники прошли барьер, он **автоматически сбрасывается** и готов к следующему раунду.

```dotty
import cats.effect.std.CyclicBarrier
import cats.effect.{IO, IOApp}
import cats.syntax.all.*

import scala.concurrent.duration.*

object ReusableBarrier extends IOApp.Simple:
  val run: IO[Unit] =
    for
      barrier <- CyclicBarrier[IO](3)
      fibers  <- (1 to 3).toList.traverse(i => worker(barrier, i).start)
      _       <- fibers.traverse_(_.join)
    yield ()

  def worker(barrier: CyclicBarrier[IO], id: Int): IO[Unit] =
    for
      _ <- IO.sleep((id * 500).millis)
      _ <- IO.println(s"Рабочий $id: раунд 1, жду...")
      _ <- barrier.await
      _ <- IO.println(s"Рабочий $id: раунд 1, завершён!")

      _ <- IO.sleep((id * 300).millis)
      _ <- IO.println(s"Рабочий $id: раунд 2, жду...")
      _ <- barrier.await
      _ <- IO.println(s"Рабочий $id: раунд 2, завершён!")
    yield ()
end ReusableBarrier
```

**Вывод:**

```
Рабочий 1: раунд 1, жду...
Рабочий 2: раунд 1, жду...
Рабочий 3: раунд 1, жду...
Рабочий 3: раунд 1, завершён!
Рабочий 2: раунд 1, завершён!
Рабочий 1: раунд 1, завершён!
Рабочий 1: раунд 2, жду...
Рабочий 2: раунд 2, жду...
Рабочий 3: раунд 2, жду...
Рабочий 3: раунд 2, завершён!
Рабочий 2: раунд 2, завершён!
Рабочий 1: раунд 2, завершён!
```

**Результат:** Все три рабочих проходят через барьер дважды, причём в каждом раунде они синхронизируются независимо.

## Отмена ожидания

Если волокно, ожидающее на `await`, **отменяется**, барьер теряет одного участника. 
Оставшиеся волокна будут ждать, пока не наберётся `n` активных вызывающих (или пока не будет отменено ещё одно волокно).

```dotty
import cats.effect.std.CyclicBarrier
import cats.effect.{IO, IOApp}
import cats.syntax.all.*

import scala.concurrent.duration.*

object BarrierCancel extends IOApp.Simple:
  val run: IO[Unit] =
    for
      barrier <- CyclicBarrier[IO](3)

      f1 <-
      (IO.println("1: жду...") *> barrier.await *>
        IO.println("1: прошёл!")).start
      f2 <-
      (IO.println("2: жду...") *> barrier.await *>
        IO.println("2: прошёл!")).start

      // Третий участник будет отменён
      f3 <-
      (IO.sleep(1.second) *> IO.println("3: жду...") *> barrier.await *>
        IO.println("3: прошёл!")).start

      _ <- IO.sleep(500.millis)
      _ <- IO.println("Отменяем третьего участника!")
      _ <- f3.cancel

      _ <-
      (IO.sleep(2.seconds) *>
        IO.println("Добавляем нового третьего участника")).start

      f4 <-
      (IO.println("4: жду...") *> barrier.await *>
        IO.println("4: прошёл!")).start

      _ <- List(f1, f2, f4).traverse_(_.join)
    yield ()
end BarrierCancel
```

**Вывод:**

```
1: жду...
2: жду...
Отменяем третьего участника!
4: жду...
1: прошёл!
4: прошёл!
2: прошёл!
```

**Поведение:**

- Волокна 1 и 2 ждут.
- Волокно 3 отменяется → барьер "теряет" его.
- Волокно 4 приходит и становится третьим участником → все трое (1, 2, 4) проходят барьер.

## `CyclicBarrier` vs `CountDownLatch`

| Характеристика                  | `CyclicBarrier`                            | `CountDownLatch`                          |
|:--------------------------------|:-------------------------------------------|:------------------------------------------|
| **Одноразовый / многоразовый**  | ✅ Многократный (циклический)               | ❌ Одноразовый                             |
| **Сброс состояния**             | Автоматический после достижения 0          | Нет (нельзя сбросить)                     |
| **Кто вызывает**                | Каждый участник лично (n вызовов `await`)  | Кто угодно (n вызовов `release`)          |
| **Ожидание**                    | Все участники ждут друг друга              | Ожидающие ждут, пока счётчик не станет 0  |
| **Отмена**                      | Уменьшает количество участников            | Не влияет на счётчик                      |
| **Типичный сценарий**           | Синхронизация фаз в многошаговом процессе  | Ожидание группы независимых событий       |

## Ограничения и подводные камни

### 1. `n` должно быть ≥ 1

Создание барьера с `n = 0` не имеет смысла.

### 2. Волокна, отменённые на `await`, не восстанавливаются

Если волокно отменяется во время ожидания, барьер теряет его навсегда для текущего цикла. 
Оставшимся волокнам потребуется `n` **других** волокон, чтобы пройти барьер.

### 3. Не для динамического набора участников

Набор участников фиксируется при создании барьера. Нельзя добавить нового участника "в середине" цикла.

### 4. Не для обмена данными

`CyclicBarrier` не передаёт данные между волокнами. Если вам нужно обменяться результатами, используйте `Queue` или `Ref`.

## Итог: когда использовать `CyclicBarrier`?

✅ **Используйте `CyclicBarrier`, если:**

- Несколько волокон должны синхронизироваться **многократно** на разных этапах.
- Все участники должны завершить текущий шаг, прежде чем перейти к следующему.
- Вы не хотите заново создавать барьер после каждого использования.
- Типичные сценарии: многофазные вычисления, алгоритмы с барьерной синхронизацией, тестирование параллельных систем.

❌ **Не используйте `CyclicBarrier`, если:**

- Вам нужно дождаться **группы независимых событий** (используйте `CountDownLatch`).
- Участники добавляются/удаляются динамически (барьер не подходит).
- Вам нужен **один раз** (проще взять `CountDownLatch`).
- Вам нужно передавать данные между волокнами (используйте `Queue`, `Deferred`).

**Ключевая идея:** `CyclicBarrier` — это идеальный выбор для **синхронизации повторяющихся (циклических) фаз** в группе волокон. 
Он незаменим в алгоритмах, где каждый раунд зависит от завершения всех участниками предыдущего раунда.
