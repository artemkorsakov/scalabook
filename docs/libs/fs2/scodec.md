# Scodec

Библиотека `fs2-scodec` предоставляет возможность потокового кодирования и декодирования бинарных данных, 
основанную на библиотеке [scodec](https://github.com/scodec/scodec). 
Изначально эта библиотека называлась [scodec-stream](https://github.com/scodec/scodec-stream) 
и долгое время развивалась независимо, прежде чем была интегрирована в состав FS2.

**Что такое Scodec?**

Scodec — это библиотека для работы с бинарными данными в Scala, 
позволяющая описывать бинарные протоколы и форматы данных в композиционном, типобезопасном и чисто функциональном стиле. 
Вместо того чтобы вручную управлять смещениями в буферах байтов, 
вы описываете структуру данных с помощью комбинаторов кодирования/декодирования, 
а библиотека берёт на себя всю низкоуровневую работу.

**Зачем использовать fs2-scodec?**

- **Потоковая обработка** — вы можете декодировать данные по мере их поступления, 
  не загружая весь файл или сетевое сообщение в память целиком. 
  Это критически важно для работы с большими объёмами данных или бесконечными потоками.
- **Безопасность ресурсов** — интеграция с FS2 гарантирует корректное управление ресурсами (закрытие файлов, сокетов и т.д.).
- **Композиционность** — вы можете строить сложные протоколы из простых, хорошо протестированных строительных блоков.
- **Производительность** — потоковая обработка с использованием чанков (chunks) 
  обеспечивает высокую производительность при низком потреблении памяти.

## Базовый пример декодирования

Рассмотрим пример программы, которая читает файл и декодирует из него поток кадров (frames). Каждый кадр имеет следующий формат:

1. Первые 4 байта — это 32-битное знаковое целое число, указывающее длину полезной нагрузки кадра.
2. За ним следует указанное количество байтов — сама полезная нагрузка кадра.

```dotty
import cats.effect.{IO, IOApp}
import scodec.bits.*
import scodec.codecs.*
import fs2.Stream
import fs2.interop.scodec.*
import fs2.io.file.{Files, Path}

object Decode extends IOApp.Simple:

  def run: IO[Unit] =
    // Создаём декодер, который читает поток кадров
    val frames: StreamDecoder[ByteVector] =
      StreamDecoder.many(int32).flatMap { numBytes =>
        // Для каждого кадра: читаем длину (int32), затем читаем numBytes байтов payload
        StreamDecoder.once(bytes(numBytes))
      }

    // Путь к файлу
    val filePath = Path("largefile.bin")

    // Читаем файл потоково и декодируем его с помощью нашего декодера
    val s: Stream[IO, ByteVector] =
      Files[IO].readAll(filePath).through(frames.toPipeByte)

    // Подсчитываем количество успешно декодированных кадров
    s.compile.count.flatMap(cnt => IO.println(s"Прочитано $cnt кадров."))
```

При выполнении эта программа будет инкрементально читать данные из файла "largefile.bin" 
и декодировать поток кадров в соответствии с описанным форматом.

## Детальный разбор примера

### Создание декодера

```dotty
val frames: StreamDecoder[ByteVector] =
  StreamDecoder.many(int32).flatMap { numBytes =>
    StreamDecoder.once(bytes(numBytes))
  }
```

Здесь используется декомпозиция на две части:

1. **`StreamDecoder.many(int32)`** — создаёт декодер, который многократно применяет кодек `int32` к входному потоку, 
   извлекая 32-битные целые числа одно за другим. Каждое извлечённое значение представляет собой длину следующего кадра.
2. **`.flatMap { numBytes => StreamDecoder.once(bytes(numBytes)) }`** — для каждого извлечённого числа `numBytes` 
   создаётся новый декодер, который ровно один раз применяет кодек `bytes(numBytes)`. 
   Этот кодек читает ровно `numBytes` байтов из входного потока и возвращает их как `ByteVector`. 
   Затем процесс повторяется: мы снова читаем `int32` (используя `StreamDecoder.many`), затем снова байты, 
   и так далее до исчерпания входного потока.

> `flatMap` на уровне `StreamDecoder` работает так, что каждый раз, когда декодер извлекает значение, 
> он может использовать это значение для динамического выбора следующего декодера. 
> Это позволяет описывать протоколы с переменной длиной полей, где размер следующего поля зависит от значения предыдущего.

Альтернативная запись того же декодера с использованием метода `decodeMany`:

```dotty
val frames: StreamDecoder[ByteVector] =
  StreamDecoder.decodeMany(int32.flatMap { numBytes =>
    bytes(numBytes)
  })
```

### Чтение файла и применение декодера

```dotty
val s: Stream[IO, ByteVector] =
  Files[IO].readAll(filePath).through(frames.toPipeByte)
```

- **`Files[IO].readAll(filePath)`** — создаёт поток байтов `Stream[IO, Byte]`, который читает файл инкрементально, 
  используя буфер фиксированного размера. Это гарантирует, что даже очень большие файлы не будут загружены в память целиком.
- **`.through(frames.toPipeByte)`** — применяет декодер к потоку байтов. 
  `frames.toPipeByte` преобразует `StreamDecoder[ByteVector]` в `Pipe[F, Byte, ByteVector]` — функцию, 
  которая принимает поток байтов и выдаёт поток декодированных `ByteVector`. 
  Результат: поток кадров, где каждый кадр — это последовательность байтов, прочитанная в соответствии с описанием протокола.

### Подсчёт результатов

```dotty
s.compile.count.flatMap(cnt => IO.println(s"Прочитано $cnt кадров."))
```

- **`s.compile.count`** — компилирует поток и подсчитывает количество элементов 
  (в нашем случае — количество успешно декодированных кадров). Это выполняется внутри эффекта `IO`.
- **`flatMap(cnt => IO.println(...))`** — после подсчёта выводим результат на консоль.

## Основные типы: StreamDecoder и StreamEncoder

Библиотека `fs2-scodec` предоставляет два основных типа:

### `StreamDecoder[A]`

`StreamDecoder[A]` представляет собой декодер, который преобразует поток байтов в поток значений типа `A`. 
Это чисто функциональное описание того, как извлекать структурированные данные из потока байтов.

**Конструкторы и комбинаторы StreamDecoder:**

- `StreamDecoder.once(decoder: Decoder[A])` — создаёт декодер, который применяет переданный `Decoder` 
  ровно один раз к началу потока. После декодирования одного значения декодер завершается 
  (даже если в потоке остались данные, они не будут прочитаны).
- `StreamDecoder.many(decoder: Decoder[A])` — создаёт декодер, который многократно применяет переданный `Decoder` к потоку, 
  извлекая последовательность значений типа `A`. Декодирование продолжается до тех пор, 
  пока не закончатся входные данные или не произойдёт ошибка.
- `StreamDecoder.decodeMany[A](decoder: Decoder[A])` — альтернативный синтаксис для `many`.
- `flatMap[B](f: A => StreamDecoder[B])` — позволяет динамически выбирать следующий декодер 
  на основе только что декодированного значения. Это мощный механизм для описания протоколов с переменной структурой.
- `map[B](f: A => B)` — преобразует выходные значения декодера.
- `filter(p: A => Boolean)` — отфильтровывает значения, не удовлетворяющие предикату.
- `evalMap[F[_], B](f: A => F[B])` — позволяет выполнять эффекты над каждым декодированным значением 
  (например, логирование, валидация с обращением к внешним системам).
- `handleErrorWith(f: Throwable => StreamDecoder[A])` — обрабатывает ошибки декодирования, 
  позволяя восстановиться или пропустить повреждённые данные.
- `repeat` — повторяет декодер бесконечно (или до ошибки/конца данных).
- `stop` — принудительно завершает декодирование.
- `toPipeByte` — преобразует `StreamDecoder[A]` в `Pipe[F, Byte, A]` для использования в конвейерах FS2.

### `StreamEncoder[A]`

`StreamEncoder[A]` представляет собой кодер, который преобразует поток значений типа `A` в поток байтов. 
Это зеркальное отражение `StreamDecoder`.

**Основные конструкторы:**

- `StreamEncoder.once(encoder: Encoder[A])` — кодирует одно значение.
- `StreamEncoder.many(encoder: Encoder[A])` — кодирует последовательность значений.
- `StreamEncoder.encodeMany[A](encoder: Encoder[A])` — альтернативный синтаксис.
- `contramap[B](f: B => A)` — преобразует входные значения перед кодированием.
- `andThen` — композиция кодеров (последовательное кодирование).

## Обработка ошибок и неполных данных

Scodec различает два типа ошибок:

1. **Ошибка декодирования** (`Err`) — возникает, когда структура данных не соответствует ожидаемой (например, неверный формат, выход за границы буфера).
2. **Недостаточно данных** — возникает, когда в буфере недостаточно байтов для завершения декодирования.

В `StreamDecoder` обе эти ситуации обрабатываются прозрачно:

- При недостатке данных декодер приостанавливается и ожидает поступления новых байтов.
- При ошибке декодирования декодер завершается с ошибкой (если не использован `handleErrorWith`).
